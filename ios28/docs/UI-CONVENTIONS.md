# UI 规范（2026-11-07 定稿）

> 这份文件是**唯一口径**。新页面、改旧页面都按这里来；与代码冲突时，
> 以这份文件为准并改代码，不要反过来。
>
> 背景：这一版之前，同一件事在不同页面有 3–4 种画法（16 处页内提示行、19 个本地
> message 状态、37 句各自写的空态文案）。下面把每一类收成一个出口。

---

## 1. 反馈分四级，按「用户要不要立刻看到」选

| 级别 | 组件 | 用在哪 | 例子 |
|---|---|---|---|
| 一次性回执 | **AppToast**（底部玻璃胶囊，2 秒，VoiceOver 6 秒） | 动作成功、复制、认领、撤销 | 「已复制 · 90 秒后自动清除」 |
| 页内提示 | **NoticeLine**（`tone: .error/.ok/.info`） | 需要**留在页面上**的一句话结果 | 「校验和不一致」「已生成，去通知里看」 |
| 需要下一步 | **FailureCard**（标题+细节+下一步+重试） | 失败且用户要决定接着做什么 | 开锁失败、读日志失败 |
| 整页无内容 | **EmptyNote**（衬线一句 + 说明 + 一个动作 + 母题） | 列表/页面确实没有数据 | 「还没有记录。」 |

**不许**再出现：裸 `Text(errorLine).foregroundStyle(T.C.danger)`、页内自建 toast、
只画一个 `ProgressView` 当空态。

---

## 2. 按钮只有一个主行动

| 层级 | 组件 | 规则 |
|---|---|---|
| 主行动 | `PrimaryButton` | **每屏最多一个**；黄铜实底；不可用就 `enabled: false`（不要隐藏后换文案） |
| 次行动 | `GhostButton` | 玻璃底、整宽；同一组里可以并排两个 |
| 行内动作 | `TextAction` | 章节头右侧、卡片底部；危险动作用 `destructive: true` |
| 选择 | `ChoiceChip` | 系统玻璃按钮（选中 = prominent） |

系统控件（Toggle / Picker / Stepper）一律 `.tint(T.C.brass)`。

---

## 3. 状态：一屏七态，不许各写各的

`ScreenState`（`App/Core/ScreenState.swift`）：`idle / loading / data / stale / empty / failed / partlyDone`。

- **loading** → 骨架屏（`ScreenSkeleton`），不用居中转圈。
- **stale** → 数据照常显示 + `StaleBadge`（「上次读取 · N 前」+ 刷新）。
- **failed** → `FailureCard`；有旧数据时 `degraded()` 成 stale，**不整页清空**。
- **partlyDone** → `PartialSuccessCard`（「已完成一部分」）。
- **长任务** → `ProgressMeter`（页数/条数/步数），**可取消**，取消要说「已读到的保留」。
- 空壳里：所有状态照常渲染，但**不显示任何「空壳」字样**；写入拒绝统一「当前无法保存，请稍后再试」/「当前无法读取，请稍后再试」。

---

## 4. 文案口径

| 场景 | 统一说法 |
|---|---|
| 重试 | **再试一次** |
| 取消 | **取消** |
| 关闭页面 | **关闭** |
| 完成 | **完成** |
| 从锁读日志 | **读全量日志**（会清空本机副本）；进行中「正在读门锁记录…」 |
| 刷新读数 | **刷新** |
| 确认框标题 | 一句**带问号的短句**：「删除这枚凭证？」 |
| 确认框按钮 | 动词与标题一致（删除/吊销/清空/关闭），危险动作用 `.destructive` |
| 失败一句话 | 「发生了什么」+「下一步」（走 `ErrorCopy`；不露 hex / rc 原文） |
| 空态 | 不写「暂无数据」；写「还没有…」+ 下一步 |

**同一句话只在一个地方定义**：通用短句进 `App/Core/Copy.swift`；带业务语义的留在页面常量。

---

## 5. 章节编号

- 每屏从 `01` **连续**编号，不跳号、不重复。
- 空壳里被隐藏的整段**不占号**（用 `DB.isDecoy ? "0N" : "0M"` 的动态编号）。
- 编号在章节头里是黄铜小方块（`SectionHead`），不是装饰字。

---

## 6. 颜色与状态

- 强调色只有一个（黄铜，品牌色可换但只有一套）。
- 状态色只在真实状态出现：`danger`（异常/失败）、`ok`（可证明/成功）。
- **不靠颜色单独表达状态**：同时给图标或文字（告警行左侧竖条 + 点 + 文案）。
- 文字对比度全部 ≥ 4.5:1（`Gates/contrast.js` 现场算）。

---

## 7. 动效

| 用途 | 曲线 |
|---|---|
| 入场（首屏依次亮起） | `Motion.reveal`（0.55 / 0.86），index × 0.055s |
| 小范围位移 | `Motion.glide`（0.38 / 0.9） |
| 页面级切换 / 玻璃变形 | `T.M.settle`（0.45 / 0.86） |
| 按压回弹 | `T.M.snap`（0.28 / 0.9） |

- 只动 `opacity / offset / scale / blur`，**不动布局**。
- 动效是**状态反馈**：每次出现都对应一件刚发生的事；不做装饰性循环（日光场除外）。
- 「减少动态效果」下全部退化为直接出现；「减少透明度」下玻璃退化为不透明面板。
- 长列表用 `.scrollParallax` 做边缘过渡，不给每行加独立动画。

---

## 8. 空壳（胁迫码）下的统一规则

- 屏幕上**不出现**「空壳」二字；拒绝写入一律用中性话。
- 不显示真实读数、凭证数量、验证模式、最近读取时间、锁清单（只留当前锁）。
- 不产生任何锁端写、不读锁内日志、不参与自动开门、不签发手机钥匙、不算动态密码。
- 剪贴板与导航栈在进入的那一刻清空。

## 9. 检查清单（改完一屏，逐条过）

- [ ] 主行动只有一个？不可用时是置灰而不是换文案？
- [ ] 提示走的是四级出口之一？没有裸红字？
- [ ] 失败给了「下一步」？有旧数据时没有被清空？
- [ ] 长任务有进度、可取消？取消后已读到的还在？
- [ ] 章节编号连续？空壳里隐藏的段落没占号？
- [ ] 空态写了下一步？没有「暂无数据」？
- [ ] 颜色不是唯一的状态载体？
- [ ] 动效只动 opacity/offset/scale/blur？减少动态下退化？
- [ ] 空壳里这条路径不泄露任何真实数据？
