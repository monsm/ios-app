# 后台实际功能点 · Engine 层梳理

> 对象：`App/Engine/`（69 个 Swift 文件，约 1.4 万行）。
> 这一层是从已验证的实现照搬的：它有字节级差分金标（40 条命令帧、NIST AES 向量、状态/日志解析、ZOTP、归属推断）。
> 界面层（`App/Features`、`App/Design`、`App/Core`）是这次新写的。

---

## 0. 一句话

这是一个 **ZK 系离线门锁** 的完整客户端：通过 BLE 用私有 `0x87` 帧 + `0x88` AES 包络直接和锁说话。
配对、开锁、写密码/指纹/临时码、读日志、校时、布防、网关配网、硬件钥匙串、DFU 全部在本地完成；**没有任何服务器**。

```
BLE 帧  ←→  BLEService (CoreBluetooth)
             ↓
        LockService (会话令牌 / 命令串行 / rc 自愈)
             ↓
        DB (kf_* 键；密钥在 Keychain)
             ↓
        AppModel（新写的界面投影层）
             ↓
        页面
```

## 1. 协议事实（照搬的部分，不要改）

| 项 | 值 |
|---|---|
| 锁服务 | NUS `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`（写 `…0002` / 通知 `…0003`） |
| 网关服务 | `FE90`（写 `FE92` / 通知 `FE91`） |
| 请求帧 | `87 00 len:u16LE cmd:u8 00 00 00 KLV*`（8B 头）；另有 10B / 7B 兼容变体 |
| KLV | `key:u8 len:u8 value[len:u8]`，长度只有 1 字节，>255 显式拒绝 |
| 加密包络 | `88 00 MAC[6]反转 trackId:u32LE validFrom:u32LE validTo:u32LE cmd` + 明文命令体 → AES-128-ECB 零填充 |
| 会话令牌 | `0x01` 取 token；`KLV#0xEE` 注入；20 秒内复用 |
| 时间基准 | **本地** 2010-01-01 00:00:00 起的秒；永久有效期 = `3_408_134_400`（本地 2118-01-01） |
| 响应码 | `0x05` 的 rc 在 `KLV#01`，其余在 `KLV#03` |
| 传输 | 20 字节分块写，逐块等 ack；单命令 8 秒超时、默认 3 次重试 |
| 安全模型 | 无 CRC / 无消息认证；`skey` 在 `0x05` 明文下发；ECB 无 IV（相同明文产生相同密文） |

**这些"缺点"是协议的既成事实，不是本仓引入的。** Engine 的注释逐条记录了依据（含真机勘误）。

## 2. 能力清单

### 2.1 发现与链路

1. **扫描**：不过滤 service（要同时看见锁 / 网关 / DFU 三类设备）；解析广播 `98ed` 厂商段的 pid 与 MAC。
2. **连接**：优先 NUS，回退 FE90；**notify 订阅成功才算连接就绪**。
3. **身份校验**：连上后读 `0x03`，把 pid 与钥匙串里的 pid 对比；不一致就断开且不落盘。
4. **帧编解**：三种头变体、KLV 解析、粘包重组（64K hex 上限）。
5. **会话令牌**：`0x01` → `KLV#02` 原样 token + `KLV#03` TTL；20 秒复用窗口，空 token 硬失败。
6. **重试与自愈**：超时 / 写失败 → 断开重连；rc=3/13 → 重取 token 再发一次；rc=12 → 翻转 MAC 字节序再发并持久化。
7. **命令串行**：三层互斥（物理写槽 FIFO、每服务单等待者、帧归属标签），避免两个服务抢同一条链路。
8. **防重复开锁**：`04/05/08/0a/0b/0c/0d/0e/13/14/15/18/19/20/21/22/24/25/31/32/35/41/43/44` 在超时后**不重试**（锁可能已经执行）。
9. **RSSI**：连接后主动 `readRSSI`（锁连上后不再广播，扫不到新样本）。
10. **后台保持**：配对 / 录指纹 / DFU 期间用 `beginBackgroundTask` 防止被挂起。

### 2.2 锁操作

11. **读状态 `0x03`**：20+ 字段 —— rc / 电量 / 锁钟 / 固件 / 安全级别 / 验证模式 / PIN·密码·指纹的容量与存量 / 动态码周期 / pid。
12. **开锁 `0x04`**：凭证优先级 = 用户选定 PIN 现签 ekey → 配对时存的 ekey → PIN 池逐枚现签；凭证类 rc（1/2/6/11）不再重试。
13. **配对**：`23 → 01 → 05 → 08×4 → 21 → 03`；64 枚 PIN、每批 20；断点续配；MAC 字节序靠 `0x08` 的 rc=12/18 现场裁定。
14. **修复 PIN 池**：只发 `08`，不换 `skey` —— 别人的旧钥匙失效，本机无线电密钥仍有效。
15. **密码增删 `0x0A`**：先问锁的最大密码长度；响应必须带 `KLV#04` alias；8 位上限。
16. **密码有效期 `0x0B`**：起止时间；解析失败中止下发，不静默改成"现在"。
17. **指纹录入 `0x13`**：多帧收集，8 次按压，单次 15 秒，首帧 8 秒，硬上限 150 秒。
18. **指纹确认 / 删除 `0x14` / `0x15`**：rc=25/17（忙）时 1.5 秒退避、最多 3 次。
19. **删除 PIN `0x08`**（无 add 列表、无哨兵）：吊销手机钥匙的底层原语。
20. **读日志 `0x16`**：从 `0xFFFFFFFF` 往回翻页，每页 5 条，最多 20 页；解码 19 种事件类型 + 凭证变更差分体。
21. **校时 `0x0E`**：写前读、写后读；偏差 >60 秒报错。
22. **静音 `0x18` / 双验 `0x20` / 自动上锁 `0x24` / 动态码开关 `0x19`**。
23. **布防 `0x25`**：off / once / period；时间字段是**半秒**的日内值；跨午夜合法；下发成功才落本地配置。
24. **进入 DFU `0x22`**：让锁重启进 bootloader（预期断链）。
25. **回声 `0x12`**：未配对设备也能发；用于扫描列表探活，不改锁内状态。
26. **近场自动开锁**：RSSI P95 标定 + 八重门控（前台 / 已解锁 / 非空壳 / 面容档 / 布防 / 距离 / 6 秒冷却 / 锁状态）；rc=3 时自愈校时再试一次。

### 2.3 硬件与网关

27. **硬件钥匙串 `0x41/0x43/0x44`**：写 ekey、删 ekey、读状态、列出已写入的锁 MAC。
28. **网关 `0x30/0x31/0x32/0x35/0x38`**：读状态、WiFi 配网、IoT 凭据、重启。
29. **DFU**：Nordic Secure（FE59 / 8EC90001 / 8EC90002）与 Legacy（1530 / 1531 / 1532）双通道；不校验签名；失败必定断开。

### 2.4 本机数据

30. **锁记录**：`kf_keychains`（非密钥字段）+ Keychain（skey/bkey/ekey/pins）。
31. **凭证台账**：密码 / 临时码（含有效期）、指纹（批次、告警位），每个密码单独存 Keychain。
32. **记录缓存**：每锁最多 300 条，按 idx 去重，最新在前。
33. **成员**：档案 + 扩展（角色 / 分组 / 归档 / 备注 / 紧急联系人）；删除成员有跨表级联。
34. **本机密码**：PBKDF2-HMAC-SHA256 6 万次 + 旧 FNV 兼容；胁迫码独立键；空壳模式下数据层整体返回空、写入拒绝。
35. **备份**：规范 JSON（固定键序）→ FNV-1a32 校验 → PBKDF2(6 万)→AES-128-CBC + HMAC-SHA256；导入有预览、逐锁 skip/merge/keep、校验和不匹配只警告不硬拒。
36. **凭证包**：加密导出 / 导入，冲突跳过。
37. **记录覆盖层**：本机备注（60 字）、旗标、处置结论；键是 `mac#idx`。
38. **检索**：中文自然语言（`+`/`-`、成员名、凭证类型、`昨天/昨天凌晨/最近N天/N月D日`）。
39. **归属推断**：R1 临时码窗口唯一命中；R2 锁内唯一凭证 + 3 天内 + 实时背书。只在可证明时给归属。
40. **提醒**：凭证到期最多 6 档（7d/3d/1d/24h/2h/0）；低电 20%/10% 滞回、30% 才重新武装；夜间 22–08 静音。
41. **统计**：周报 CSV、30 天开锁构成、临时码越窗异常、未定时记录数。
42. **诊断**：锁端 vs 本机双侧快照（不含明文密钥，只给指纹）、帧脱敏（保留 8 字节头 + KLV 骨架）。
43. **剪贴板**：90 秒自动过期；进空壳立即清空（由界面层的 `AppModel.noteGate` 触发 `Clip.clear()`）。
    ⚠️ 上一版（ios27）在进空壳时清过剪贴板，这一版初稿**漏了** —— 已补回：
    进空壳前可能刚复制过一枚动态码，而空壳里没有任何界面会去动剪贴板，
    胁迫者长按粘贴就能拿到。

## 3. 数据存放在哪

| 数据 | 介质 | 保护 |
|---|---|---|
| 锁母钥 / bkey / ekey / PIN 池 | iOS Keychain | `WhenUnlockedThisDeviceOnly` |

| 回滚点 | Application Support | 文件保护；**明文 skey**（已知弱点） |

## 4. 安全边界（事实）

- **没有消息认证**：`rc` 是可伪造的普通 KLV 字段；本仓在注释里明确承认这一点。
- **ECB + 固定密钥**：相同明文 → 相同密文；开锁链**依赖**这一点跳过重复签发。
- **`skey` 明文下发**：只在配对窗口、靠近距离和锁的重置态保护。
- **TOFU**：首次连接信任广播里的 pid/MAC；连上后交叉校验 pid（已有记录时）。
- **固件包无签名**：只有 CRC 与尺寸检查；本仓会拒绝降级，但无法证明包是谁产的。
- **空壳模式**：所有读路径返回空、所有写路径拒绝；门仍可开。
  进空壳时**立刻**清掉界面投影与剪贴板（不等下一次 reload —— 那一拍里胁迫者正盯着屏幕）；
  出空壳时**必须重建**已清的到期提醒，否则提醒永久消失而界面仍显示「已排程」。

## 5. 这次产品用到 / 没用到

**用到**：状态、开锁、配对、密码/临时码/指纹、日志、校时、静音、双验、自动上锁、布防、动态码、手机钥匙、硬件钥匙串、网关、DFU、备份、成员、归属、提醒、诊断、自动开门。

**没用**：`cmd30` / `cmd32`（云端 IoT 档案，厂商侧功能）、WebDAV 上传（本版不提供云）、回滚点的"应用"（本来就只有写、没有读）、只读试验的导入拦截之外的试验能力。

## 6. 已知限制（不在这次修复范围）

- 布防没有回读校验：只知道锁回了 `rc=0`，不知道它真的布防了。
- 指纹录入依赖用户真按 8 次；中断后锁的 15 秒窗口会过期。
- 日志翻页上限 20 页（约 100 条）；更早的记录读不到。
- `Keychain.trackid` 生成后没有参与 ekey 签发（配对 ekey 的 trackId 恒 0）。
- 备份校验和是无密钥 FNV，不是防篡改手段；真正的完整性来自信封 HMAC。
