# AUDIT-ROUND-94 · 第九十四轮：标定失败时，旧门槛还在生效

> CI：`744293b` 已验证；`4178cc8`（搜索历史长按删除）/ `e736bfa`（凭证年龄）刚推送。本轮本地提交。

## 1. 缺陷：界面说「未标定」，行为仍在用旧值

```
if AutoOpen.saveAutocal(mac, samples: samples) != nil {
    store.calibrationAt = ...          // 成功
} else {
    store.calibrationAt = nil          // 失败：只清了**界面状态**
    calibrationError = "这次只采到 N/5 个信号样本…"
}
```

`kf_autocal_<mac>` 里的旧门槛**没有被清**。于是用户看到：

- 「上次标定：未标定」「触发距离：默认（-40 dBm）」；
- 同时「标定失败：样本不足」。

而实际生效的门槛还是**上一次那个值** —— 界面与行为不符。用户会以为"现在用的是默认档"，
所以"门内经过也会触发"这种现象会看起来毫无道理。

## 2. 修法：`clearAutocal` 一直存在，且零调用

`AutoOpen.clearAutocal(_:)` 早就写了（RESERVED 第 16 条，接线点写着"自动开门设置页的重新标定"）。
本轮把它接到两处：

1. **标定失败分支** —— 这是真正的缺陷修复（不只是加按钮）：清掉旧值，并改文案为
   「旧门槛已清除，会回落到默认档」；
2. **新增「清除标定（回到默认门槛）」按钮** —— 用户标定错了（比如在门内标的）时的出口。

两处用**同一个函数**，不存在第二份清理逻辑。

## 3. 接线成本：这次真的是「低」

| 项 | 要动什么 | 成本 |
|---|---|---|
| `pwdAgeDays`（上轮） | 模型加字段 + 构建处 + 视图 | 中 |
| `clearAutocal`（本轮） | 只动一个视图文件（状态已在页面上） | **低** |

和上轮一样，接线成本是**做的时候才知道**的 —— 而这次恰好还发现了一个真缺陷，
不只是"接上一个待接功能"。

## 4. 方法论

**「接线」常常会顺手暴露一个真缺陷 —— 因为待接函数的存在本身常常意味着某条路径没写完。**

本段两例：`removeSearchHistory`（那排标签只能点不能删）+ `clearAutocal`（失败分支漏清旧值）。

所以「把 RESERVED 里的低成本项做掉」不只是"补功能"，也是**一种更高产的找缺陷方式** ——
因为待接函数标记的，正是作者当时"知道该做但没做完"的地方。
