# AUDIT-ROUND-264 · 第 264 轮：固件刷写失败了，界面没说锁现在开不了门

> CI：**`eb47535` build 全绿**（MAC 归一化文档轮）；`9816328` / `bfc8d28` / `d8fc80d` 排队中。

## 1. 上下文

`DFUScreen` 刷写失败的路径只做两件事：`phase = .failed` + `error = 「升级失败：…」`。

而 DFU 的中途是：锁已经进了 bootloader（`cmd22` 之后断开重连 ZkDFU 广播）——
**此时锁不再按平常广播、也开不了门**，直到重新刷完。

| 用户看到 | 实际情况 |
|---|---|
| 「升级失败：连接中断」 | 锁停在升级模式，**门开不了** |

用户很可能以为只是没升级成功，转身离开，直到要用门时才发现。

## 2. 修法

失败态补一条 attention 状态行，写成明确指令：

> 升级没有完成。锁很可能仍停在升级模式 —— 此时无法开门。请保持手机靠近门锁，
> 回到本页再点一次「开始升级」；若反复失败，换一部手机或用厂商工具重刷。

## 3. 本轮另外 3 项核对

| 检查 | 结论 |
|---|---|
| 完成后是否刷新版本 | ✅ `await app.refreshStatus()` 后显示锁内版本 |
| 是否提示「不要切后台」 | ✅ 运行中与说明卡都写了 |
| 失败是否断开连接 | ✅ `defer` 里 cancelConnection + stopScan（D-23） |
| `DFUState.aborted` | ⚠️ **从未被 emit**，`DFUScreen` 里对它的判断是死代码 |

`aborted` 保留（将来加「取消升级」按钮时正是它该被 emit 的地方），但记在这里免得有人以为它已生效。

## 4. 方法论

**危险操作失败后，界面必须回答「现在这台设备处于什么状态」，而不只是「操作失败了」。**

| 失败提示的层次 | 例子 |
|---|---|
| 只报结果 | 「升级失败」 |
| **报结果 + 当前设备状态 + 下一步** | ✅ 本轮 |

判据：**凡是会改变设备状态的操作（刷固件 / 配网 / 换钥 / 清空），失败提示都要包含「设备现在是什么状态、必须做什么」—— 因为失败的中间态往往比失败本身更危险。**
