# AUDIT-ROUND-74 · 第七十四轮：空搜索也会被记进「最近搜索」

> CI：`6801fa3` 已验证；`d36c6e5` / `2dae705` 待回执。本轮本地提交。

## 1. 缺陷

```swift
TextField("搜名称 / 归属 / 类型", text: $search)
    .onSubmit { CredentialOrg.pushSearchHistory(search) }   // ← 空串也会进来
```

`.onSubmit` 在输入框**为空**时同样触发（用户按键盘右下角的"搜索"键）。
于是：

```swift
static func pushSearchHistory(_ q: String) {
    var list = Array(searchHistory().filter { $0 != q }.prefix(4))
    list.insert(q, at: 0)          // 插入 ""
    DB.setCodable(list, "kf_csearch_hist")
}
```

后果（都在界面上可见）：

1. 「最近搜索」下多出一个**标签为空白、几乎看不见的按钮**；
2. 点它等于把搜索框设成空（看起来"点了没反应"）；
3. 空串永久占掉 5 个槽位中的一个 —— 而且因为去重是按相等过滤的，它不会被后来的词挤掉。

## 2. 修法（两处）

- **函数内**：先 `trimmingCharacters(in: .whitespacesAndNewlines)`，空则 `return`；
  存入的也是 trim 后的值（顺手解决"搜索词带首尾空格"）。
- **调用点**：再挡一次（不产生"提交了但什么都没发生"的感觉）。

函数内是**主防线**（任何未来调用点都受保护），调用点只是体验补充。

## 3. 新增测试

`testSearchHistoryRejectsEmptyTerms`：

- `""` / `"   "` / `"\n"` 都不进历史；
- `"  前门  "` 存成 `"前门"`；
- 连推 6 个后只剩 5 条且最新的在最前（锁住上限与顺序语义）。

## 4. 方法论

**"输入合法性"检查放在函数内，而不是调用点。**

本仓有大量 `.onSubmit { f(x) }` 形式的调用点，而 `f` 往往没挡非法输入 ——
因为作者默认"界面会挡"。但界面只挡**它没想到的那些**：

| 界面挡了什么 | 挡不住什么 |
|---|---|
| 空串（这个例子：**没挡**） | 纯空白串 |
| 明显的非法格式 | 首尾空格带来的"看似重复" |

判据：**任何"写入存储"的函数，都应在函数内先做一次规范化与合法性检查**，
不要假设调用方已经做好 —— 这与我前几轮反复得到的"清理要落在能力所在的那一层"是同一条。
