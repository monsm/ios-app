# AUDIT-ROUND-64 · 第六十四轮：同一个动作有三条入口，只有一条补了回执

> CI：`d3217ef` 已验证；`70cf56d` / `b00ad23` 待回执；`2d6a02d` 本地。本轮本地提交。

## 1. 上一轮只补了「成员详情页」那一条

归档/恢复这个动作在本仓有**三条入口**：

| # | 位置 | 上一轮状态 |
|---|---|---|
| 1 | `MemberDetailScreen.toggleArchive` | 上轮已补 toast |
| 2 | `HouseholdScreen.archive`（名单里直接归档） | **静默** |
| 3 | `MemberArchiveScreen.restore`（归档页恢复） | **静默** |

我上一轮改完 #1 就以为"这个动作有回执了" —— 但另外两条路径的用户仍然什么也看不到。

## 2. 修法

三条路径统一文案与 tone：

- 归档：「已归档 · 历史仍在，记录页仍能筛到 TA」
- 恢复：「已恢复为在册成员」

并在两处新加的代码上写明"与另一条入口保持同一口径"，避免下次只改一处。

## 4. 把判据变成动作（第三次强调，这次要具体）

不是"记得检查其他入口"，而是：**改完任何一处，立刻把被改的标识符拿去 grep。**

本轮就是这样发现第 2、3 条的：`grep mirrorArchived` → 三个调用点。
这个动作是可执行的、几乎零成本，而"记得检查"不是。
