# AUDIT-ROUND-84 · 第八十四轮：读不到备份目录 ≠ 没有备份

> CI：`e150d03` 已验证；`816aa3f` / `efc94c8` / `dc7b29c` 待回执。本轮本地提交。

## 1. 缺陷

```swift
let urls = (try? fm.contentsOfDirectory(at: BackupStudio.dir, includingPropertiesForKeys: ...)) ?? []
```

`try?` + `?? []` 把**读取失败**变成**空目录**，而界面随后显示：

> 还没有本机备份文件。点上面「生成一份本机备份」…

也就是说：沙箱权限、目录损坏、文件系统异常时，用户看到的是"**我的备份不见了**"，
而真实原因是"读不出来"。这会导致两个连锁反应：

1. 用户以为备份丢了 → 重新生成 → 挤掉 `keepCount` 配额里的旧备份（**真丢了**）；
2. 支持人员拿到"没有任何备份"这个错误前提，排查方向从一开始就是歪的。

## 2. 修法

- `do/catch` 分开处理：成功走原逻辑，失败记 `filesError`；
- 界面三态：**读取失败**（红字说明原因） / **空目录**（正常的首次提示） / 有文件；
- 保留 `urls = []` 作为失败时的退路（列表区域清空，但错误信息在）。

## 3. 同类核查：不是所有 `?? []` 都要改

扫出 23 处 `?? []`，逐一判性质：

| 形态 | 例子 | 要不要改 |
|---|---|---|
| `DB.store.get(...) ?? []` | `CredBinStore.stored`、`MemberHub` | **不改**：键不存在 = 空，这是**正常语义**，不是失败 |
| `try?` + 目录/文件 I/O + 展示 | 本轮这处 | **改**：失败被伪装成"没有数据" |
| `try?` + 清理/裁剪 | `purgeLocalArtifacts`、`pruneRollback` | **不改**：失败时少删无害，且不在用户可见路径上 |

这条区分很重要 —— 如果无差别地给所有 `?? []` 加错误提示，界面会被"正常空态"塞满警告。

## 4. 方法论

**"空"与"读失败"是两种状态，用同一段 UI 表达就等于丢失信息。**

判据：**凡是"取列表 → 展示"的路径，问一句"取失败时用户会看到什么"**。
如果答案是"和空列表一样"，那就要改 —— 因为这正是用户最需要知道真相的时刻。
