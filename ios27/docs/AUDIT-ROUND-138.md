## 1. 为什么写这份文件

本段 137 轮里，**每次真正抓到缺陷靠的都是同几条判据**，而它们只散落在各轮报告里。
一个新人（或下一个我）要重新发现它们，得读 137 份报告。

所以新建 `docs/AUDIT-METHOD.md`，按"怎么找"组织，不按"找到了什么"。

## 4. 顺带记录：本轮为什么没做闸门

我本想把上轮的「同族缺未来时间戳保护」做成闸门。评估后放弃：

```
grep "timeIntervalSince1970 - |now - "  →  26 处
```

26 处里要区分"从 UserDefaults 读的时间戳"（需要保护）与"进程内时间戳"（不需要），
**静态正则无法区分** ⇒ 假红会很多。

按 §2.2 的判据（假红多的不做），**不做闸门，而是写进方法论**：

> 找到一个"有保护"的实现后，立刻 grep 它的同族，逐个看有没有保护。

## 5. 方法论（元层面）

**审计的产出有两种：修好的代码，与"下次怎么修得更快"的知识。后者更容易丢。**

本段前 137 轮一直在产出前者；这轮补上后者 —— 而它恰好是**唯一能被下一个人直接复用的东西**。
