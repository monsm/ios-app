## 3. 三方对抗对比的结论

| 层 | 结论 |
|---|---|
| 字节层（ekey 信封 / AES-ECB / 成帧 / cmd08 PIN 编码） | **三方逐字一致** |
| 语义层（delAlias / 哨兵 / bkey 调整规则 / cmd21 顺序） | **一致** |
| 控制流层（翻页方向 / 终止条件） | **1 个真 bug（翻页方向）** |

**vendor 的 Cordova App 从不直接发 cmd04** —— 它只生成 ekey 交给服务器分享。
所以「vendor 能开」从未验证过手机直连这条路。

## 6. 方法论（本轮新增 6 条判据）

1. **「解析了但没消费」是死代码里最隐蔽的一种** —— 它假装功能已完整。
2. **「脱敏」要脱得够用，不是脱得干净** —— 保留结构（字段号 + 长度）才可诊断。
3. **「文档说我没做」要像「代码说我做了」一样验证** —— 谦虚的断言没人怀疑。
4. **`try?` 后面跟一句「已…」就是 bug** —— 不关心结果才配用 `try?`。
5. **「自愈只做了一半」比「不自愈」更难查** —— 修好前置条件后，原来那件事要不要再做一次？
6. **共享的可变单槽 + 多个观察者 = 一定有人被抢** —— 按类型认领 / 队列 / 广播，三选一。
