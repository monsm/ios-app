# AUDIT-ROUND-109 · 第一百零九轮：把「告警不被看见」这个流程漏洞补上

> CI：`8822444` 全绿；`86f4617`（两处告警修复）待回执。本轮本地提交。

## 1. 上轮的教训不该只写在报告里

上轮发现 `build.log` 里有 6 条 warning，其中 1 条是真缺陷。根因不是"没能力发现"，
而是**流程只读 `errors=` 与 `build_ok=`，从不读 `: warning:`**。

如果只写一份报告说"下次要看告警"，那下次仍然不会看。所以这轮做三件事：

## 2. 让 CI 自己把告警数记下来

`ci-log:meta.txt` 新增一行：

```yaml
echo "warnings=$(grep -cE "^/Users/runner/work/.../ios27/App/.*: warning:" /tmp/ciout/build.log ...)" >> /tmp/ciout/meta.txt
```

口径说明（写进 yml 注释里）：只数**源码**告警行（路径以 `App/` 开头），排除 Xcode 回显行
（`| ... warning:`）与工具提示。这样每次 `git show origin/ci-log:meta.txt` 就能直接看到数。

## 3. 把「读什么」写进架构文档

`ARCHITECTURE.md` 新增一张表：**核对 CI 必须读四样**

| 字段 | 说明 |
|---|---|
| `errors=` | 只说明"没有 error 行"，**不等于 job 绿** |
| `build_ok=` / `archive_ok=` | 真正的绿/红判据 |
| `warnings=` | **源码告警数**；不是 0 就必须逐条看 |

## 4. 修正 `WARNINGS.md` 里那句过期的话

它写着「当前构建 `: warning:` **0 条**」，引的是 run `41219938500`（`a8416aa`）——
而后续提交又引入了 6 条。已改为：

- 明确标注"上一版这句是错的"；
- 列出那 6 条的位置与性质（1 条真缺陷 + 5 条类型标注）；
- 指出**真正的问题是流程**，并指向新增的 `warnings=` 字段。

## 5. 为什么这次不新增闸门

「告警」这件事闸门管不了 —— 告警是**编译器**的产物，本地没有编译器。
能做的只有两件：**让 CI 把数记下来**（本轮做了）+ **让核对流程读它**（写进文档）。

这也划清了闸门与 CI 的分工：

| 层 | 谁能发现 | 手段 |
|---|---|---|
| 形状 / 命名 / 计数 | 21 道闸门 | 本地、秒级 |
| **类型 / 可达性 / 并发 / 告警** | **编译器** | 只能等 CI |

## 6. 方法论

**"知道该看什么" ≠ "每次都会看"。后者需要把它变成一次具体的动作。**

所以这轮的两处改动都不是"提醒"：

- `warnings=` 是一个**能直接读到的字段**（不需要记得去 grep 日志）；
- ARCHITECTURE 那张表是**核对清单**（照着一行行看，不靠记性）。
