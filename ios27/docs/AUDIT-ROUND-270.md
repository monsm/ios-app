# AUDIT-ROUND-270 · 第 270 轮：只读试验模式说「导入导出全拦」，实际**导入照做**

> CI：**`6c20d1c` build 全绿**（备份卡口径说明编译通过）；`fb152c1` / `1f84bca` 排队中。

## 1. 缺陷

开关文案（`TrialGuard.warning`）：

> 开启后：开锁、写凭证、换钥、配网、网关、固件升级、**导入导出**全部被拦下，只能读状态。

而强制点只有一处：`LockServiceLink:258` 的 `ZKProtocol.assertReadOnly(cmd)` —— **BLE 命令层**。

| 操作 | 走 BLE？ | 实际被拦？ |
|---|---|---|
| 开锁 / 写凭证 / 换钥 / 配网 / 网关 / 固件 | ✅ | ✅ |
| **导入备份**（整表改写台账/成员/凭证） | ❌ 本机写 | ❌ **没拦** |
| 导出备份（只读） | ❌ | ❌ 没拦（**这是对的**） |

于是「只读试验模式」下照样能把一份旧备份导进来，把整库台账换掉 —— 而开关说它拦得住。

## 2. 修法

| 改动 | 说明 |
|---|---|
| `BackupStudioKit.restore` 入口加 `guard !TrialGuard.isOn else { throw … }` | 三条导入路径（旧备份页 / 工作室文本 / 换机迁移）的唯一入口 |
| 签名加 `throws` | 三条调用点本来就在 `do/catch` 里，只需补 `try` |
| 文案改准 | 「…导入**备份**全部被拦下；**导出备份仍可用（只读）**」 |

## 3. 为什么改文案而不改行为

导出是**读**，试验模式的目的是「不改设备、不改本机数据」—— 拦导出没有道理，
而且排障时正需要导出数据。所以：**拦导入、放导出、文案说清**。

## 4. 方法论

**一个「总开关」的文案如果列举了 N 项，就必须逐项验证每一项真的被拦 —— 尤其是**不走主链路**的那些。**

| 拦截点 | 覆盖范围 |
|---|---|
| BLE 命令层 | 只覆盖「要经过蓝牙」的操作 |
| **本机写操作**（导入/恢复/迁移/重置） | **完全在它之外** |

判据：**文案里每列举一项，就问「这一项经过我加的那个拦截点吗」—— 不经过的必须单独加。**
