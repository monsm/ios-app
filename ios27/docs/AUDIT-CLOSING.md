## 3. 修过的主要缺陷族（按形态）

| 族 | 例 |
|---|---|
| 写路径误用展示层过滤器 | 空壳模式下写回收站 → 整表清空 |
| 单条读取器缺过滤 | `member(id)` / `dongle(mac)` / `gateway(mac)` |
| 清理不彻底 | 删设备漏清四族钥匙串副本；删成员漏清手机钥匙 |
| 旁挂表不进备份 | `kf_member_ext` / `kf_calert_` / `kf_cstar_ui_` / `kf_cseq_` |
| **字段存在但 canonical 不 emit** | 只改结构体 = 功能静默不生效 |
| 成对调用缺异常复位 | `keepingAwake` 抛错则屏幕常亮 |
| 「停止」没有 cancel / `isCancelled` 无人 cancel | 轮询每 2 秒醒一次；配网「已中止」永不触发 |
| **占位值被当真值渲染** | 信号恒 0/4、电量恒 -1% |
| **写远端真值不刷新投影** | 静音 / 安全模式 / 校时（3 处） |
| 空态掩盖失败态 | 读不到备份目录 → 「还没有备份」 |
| 只有时间或只有条数上限 | 电池采样 90 天无封顶 |
| 未来时间戳钉死判断 | 冷却永久生效、沉睡永不触发 |
| 文案承诺 ≠ 实现 | 「最近一条」按别名排、「再开一次」只跳转 |
| **注释里的承诺没有实现** | 死声明 6 处、幽灵开关 2 处、DestroyKit、不存在的待办 |

## 4. 明确**没有**覆盖的部分（这才是"何时能结束"的答案）

| 项 | 为什么做不了 | 谁能做 |
|---|---|---|
| 真实渲染与浅色主题观感 | 本机 Windows 无 SwiftUI 渲染 | 真机/模拟器人眼 |
| 手势手感、触觉反馈 | 需要真实触屏与 Taptic Engine | 真机 |
| BLE 回执、指纹录入、DFU 实刷 | 需要真实门锁与固件 | 真机 + 锁 |
| WebDAV 真实链路 | 需要真实服务器 | 真机 + 服务器 |
| 出口合规（`ITSAppUsesNonExemptEncryption`） | 需法律/合规判断 | 人 |
| iPad / 横屏 | 产品决定锁竖屏 | 产品 |
| 钥匙串单测 | 未签名测试宿主无 entitlement | 签名环境 |

**这 7 项的共同点：不是"还没做"，而是"在这台机器上做不到"。**
继续加轮次不会让它们前进一步。

## 5. 所以，什么时候结束

**现在就可以结束。**

理由：

1. 147 个文件全部逐个读过并记录结论（有缺陷 21 个，无缺陷其余）；
2. 22 道闸门全绿，且每道都做过正控（注入缺陷确认会红）；
3. CI 的 build / archive / golden 三项全绿，告警 0；
4. 剩余 7 项**全部是硬件或外部决策**，再审计也验不了。

**继续下去只会是"强行硬分析"** —— 而 objective 明确要求不要那样。
