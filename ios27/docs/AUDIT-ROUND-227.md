# AUDIT-ROUND-227 · 第 227 轮：删凭证时，三样「派生数据」没跟着删

> CI：`8eb3843` 全绿（`project=yes / swift_files=150`）。

## 1. 缺陷

`delPwd` / `delFp` 是全仓**所有删除路径的唯一落点**（停用 / 彻底删除 / 批量 / 换槽 / 恢复都走它），
它清了台账行、钥匙串口令副本、到期提醒 —— 但**漏了三样派生数据**：

| 派生数据 | 键 | 漏删的后果 |
|---|---|---|
| 星标 | `kf_cstar_ui_<mac>` 里的 `"pwd:<别名>"` | 锁端**复用别名**时，新凭证自带旧星标 |
| 拖拽顺序 | `kf_cseq_<mac>` 的 `"p":[别名…]` | 新凭证直接排到**旧位置** |
| 本机停用位 | `kf_v7_disabled_<mac>` 里的 `"pwd:<别名>"` | 新凭证一出现就是**停用**状态 |

**为什么"复用别名"是真会发生的**：密码/指纹的别名/批次号由锁端分配，删掉再新增**常常拿到同一个编号**。
于是用户会遇到「刚加的一条，怎么是灰色的/带星/排在中间」—— 而原因在几个月前删掉的那条。

## 2. 修法

三样全部在 `delPwd` / `delFp` 里清掉：

```swift
var stars = CredStarStore.all(mac)
if stars.remove("pwd:\(alias)") != nil { CredStarStore.set(mac, stars) }
var sq = CredentialOrg.seq(mac)
if var p = sq["p"], let i = p.firstIndex(of: alias) { p.remove(at: i); sq["p"] = p; CredentialOrg.setSeq(mac, sq) }
CredentialLocalState.setDisabled(mac: mac, id: "pwd:\(alias)", false)
```

指纹同理（`"fp:<批次>"` / `sq["f"]`）。

## 3. 为什么只改这一处就够

`delPwd` 的注释（第 94 轮写的）已经确认：

> **这里是全仓所有 `DB.delPwd` 的唯一落点**（停用/彻底删除/批量/换槽/恢复都走它），
> 所以取消放在这一处即可覆盖全部删除路径。

本轮三样同理 —— 正是因为有这个唯一落点，漏掉才显得隐蔽：
**清理看起来"已经收口了"，实际只收口了它列出来的那几样。**

## 4. 方法论

**「唯一落点」是一种承诺，要按"派生数据清单"逐项验收，而不是按"我记得的几样"。**

| 派生数据 | 删除时 |
|---|---|
| 台账行 / 钥匙串副本 / 到期提醒 | ✅ 已有 |
| 星标 / 拖拽顺序 / 本机停用位 | ✅ 本轮补 |

判据：**每次给某个实体新增一种"按 id 挂在外面的状态"（星标、停用位、备注…），
就回头问一句"删除时它会不会跟着走"。** 这类状态天生不属于台账，所以最容易漏。
