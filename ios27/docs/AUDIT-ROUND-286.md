# AUDIT-ROUND-286 · 第 286 轮：最重要的那句警告，用户从来没看到过

> CI：`b320efa` build 全绿。

## 1. 缺陷

`KeyDetailScreen.delete()` 的「只从本机移除」分支：

    app.keys.removeAll { $0.id == key.id }
    actionError = "已从本机列表移除；锁端凭证未变（这条没有可下发的撤销命令）。"
    r = .success(())

两个问题叠在一起：

| 问题 | 后果 |
|---|---|
| 文案写进 `actionError` | 它渲染在 `V.C.critical`（**红色错误**） |
| 成功后立刻 `router.keysPath = []` | **弹回列表，这行字根本没机会被读** |

于是「**锁端凭证未变、仍然有效**」这条最要紧的信息，用户**一次都没看到过** ——
而它正是这条分支存在的理由（这条凭证在锁上还能开门，本机只是不再列它）。

## 2. 修法

改成 toast（在弹回前显示，`tone: .warn`）：

> 已从本机列表移除；锁端凭证未变，仍可开门（这条没有可下发的撤销命令）。

## 3. 方法论

**「写进了某个变量」不等于「用户看得到」—— 还要看它渲染在哪、以及页面会不会立刻消失。**

| 检查层 | 本轮结论 |
|---|---|
| 文案存在吗 | ✅ 存在 |
| 渲染在哪 | ❌ 红色错误槽（语义不对） |
| **页面还在吗** | ❌ **弹回列表，来不及读** |

判据：**给「成功后要告诉用户」的文案选通道时，先确认三件事：它是不是错误、它要停留多久、它出现时页面还在不在。**
本仓的三条通道是 `actionError`（红、常驻）、`AppToast`（短暂浮层）、`SettingsNote`（常驻说明）—— 各有适用面。
