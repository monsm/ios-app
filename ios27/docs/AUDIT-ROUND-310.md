# AUDIT-ROUND-310 · 第 310 轮：全 App 最敏感的一页，没有任何遮挡

> CI：`6efb970` build 全绿（errors=0）。

## 1. 方法：把「会显示机密内容的页面」与「装了遮挡的页面」求差

| 页面 | 显示什么 | `.captureShield` |
|---|---|---|
| `KeyDetailScreen` | 凭证码值 | ✅ |
| `ZotpScreen` | 可开门动态码 | ✅ |
| `ShareToAndroidScreen` | 开锁二维码 | ✅ |
| `BackupScreen` | 可开门备份文本 | ✅ |
| `CredentialStudioScreen` / 回收站 | **不显示码值**（`displayPwd` 只返回备注名） | 不需要 ✅ |
| `RecordsStudioScreen` | 帧**已脱敏** | 不需要 ✅ |
| **`DiagStreamScreen`** | **打开「包含原始载荷」时：完整 TX/RX 帧（含 skey / PIN / ekey 明文 hex）** | **❌ 没有** |

差集只有一处 —— 而这一处恰恰是全 App **最敏感**的一处：
它不是「一枚码值」，是**母钥本身**（`skey`）。

## 2. 为什么特别严重

| 页面 | 泄露后果 |
|---|---|
| 凭证详情（已遮挡） | 一枚密码 |
| **诊断流水（原本没遮挡）** | **`skey` —— 可推所有凭证、可写任意码、可换钥** |

而这一页恰恰是**为用户排查而常年开着**的页面（用户报「开锁失败」时就会打开它）。

## 3. 修法

给 `DiagStreamScreen` 的 `NavigationStack` 挂 `.captureShield(...)`，文案随 `rawOn` 变：

| rawOn | 文案 |
|---|---|
| 开 | 这里含原始交互帧（母钥 / PIN / ekey）… |
| 关 | 这里是与门锁的交互流水… |

（复用 Round 309 刚补的 `scenePhase` 那一路 ⇒ 后台快照也一并覆盖 ✅）

## 4. 方法论

**隐私覆盖要按「内容敏感度排序」查，而不是按「页面重要性」查。**

| 直觉排序 | 实际敏感度 |
|---|---|
| 凭证页最敏感（用户天天用） | 一枚密码 |
| **诊断页是给工程师用的，次要** | **母钥 + 全部帧** ❗ |

判据：**给页面排优先级时，按「它显示的东西能推出什么」排 —— 显示母钥的调试页，比显示单枚密码的业务页敏感一个数量级。**
