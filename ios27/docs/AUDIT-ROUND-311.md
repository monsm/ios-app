# AUDIT-ROUND-311 · 第 311 轮：安全头注写着「不复制」，而代码里能复制母钥

> CI：`a8b24bea` build 全绿（errors=0）。

## 1. 缺陷：头注与实现相反

`DiagStreamScreen.swift` 的头注（安全边界那段）原文：

> 完整帧只留在内存 `recentFrames`（不落盘、**不复制**），与既有纪律一致。

而实际代码（第 79-86 行）在用户勾选「包含原始载荷」后，复制的就是 `LockService.rawTrace` ——
**含 skey / ekey / PIN 明文**的原始帧。

## 2. 这条复制本身是**用户明确要求**的，不是 bug

用户原话：「先不要担心泄露，我们是本机调试」。所以实现没问题，**错的是头注**。

| 检查 | 结论 |
|---|---|
| UI 有没有警告 | ✅ 标题「（含密钥，勿外传）」+ 红字说明 + 按钮文案「复制原始流水（含密钥）」 |
| 剪贴板会不会长期留明文 | ✅ 走 `Clip.set`，**90 秒后自动过期** |
| 会不会落盘/进备份 | ✅ 不进 `DiagLogs`、不进备份、不进导出 |

## 3. 修法：把头注改成两条路径的如实描述

| 路径 | 内容 |
|---|---|
| ① 默认 | 展示与复制都走 `FrameRedact`（只留帧头，载荷 `…(N bytes 已脱敏)`） |
| ② 显式勾选 | 复制 `rawTrace` **原始帧**，90 秒过期，不落盘/不进备份 |

并写明准确表述：**「完整帧不会主动离开本机，但用户可以在知情前提下复制它（限时 90 秒）。」**

## 4. 顺带核实：全仓剪贴板写入都走统一入口

`grep 'UIPasteboard.general.string ='` → **只剩 `Clip.swift:18` 一处**（那是清空路径）。
即当年 17 处直写已全部收口到 `Clip.set`（统设 90 秒过期）✅。

## 5. 方法论

**安全注释比安全代码更容易过期 —— 因为改代码的人会加功能，改注释的人不会。**

| 注释类型 | 过期后的危害 |
|---|---|
| 普通说明 | 读者困惑 |
| **「我们不会做 X」型安全断言** | **审计者据此放行，X 实际发生了** |

判据：**凡是「我们不会…」「只…不…」这类安全断言，都必须与一条可执行的检索对应（本轮：`grep UIPasteboard`、`grep rawTrace`）—— 断言可检索，才可复核。**
