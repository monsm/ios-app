# AUDIT-ROUND-60 · 第六十轮：`skipped` 一直有，但三条恢复路径里有两条没报

> CI：`0d35a93` 已验证（`errors=0`、`build_ok=1`、`archive_ok=1`）。本轮本地提交。

## 1. 按上轮判据「列出所有入口」复查 —— 又抓到两处

`BackupStudio.restore` 的返回类型是 `(imported: Int, overwritten: Int, skipped: Int)`，
**一直都有 `skipped`**。但三个调用点里：

| 入口 | 报了吗 |
|---|---|
| 工作室·换机迁移（`BackupStudioScreen:440`） | ✅ 报了 |
| 工作室·恢复文件（`BackupStudioScreen:336`） | ❌ 只报新增/覆盖 |
| 主备份页·粘贴/文件导入（`BackupScreen`） | ❌ 状态行只存了 `(added, merged)` |

后果：用户恢复一份"含 3 把锁、其中 1 把密钥格式非法"的备份，
看到「已恢复：新增 5 项」，会以为全好了 —— 而少掉的那把锁的凭证**永远不会写进本机**。

## 2. 修法

- `BackupScreen`：`restoreDone` 从二元组扩成三元组，状态行在 `skipped > 0` 时
  追加「跳过 N 把锁（密钥格式非法）」，并把 tone 从 `.ok` 改为 `.attention`（不是错误，但需要注意）；
- `BackupStudioScreen`：恢复文件那一路同样追加该段。

（顺带修正：`Tone` 的枚举是 `ok / attention / critical / neutral / live` —— 我先写成了 `.warn`，
查了定义才改对。**凭印象写枚举 case 是这类改动的常见错误。**）

## 3. 方法论

**"这个数据一直都有"不等于"它被用上了"。**
`skipped` 在返回值里躺了很久，三个调用点只有一个用了它 —— 而返回值类型本身就在提示"这里有三种结果"。

判据：**改一个函数的返回值时，要逐个检查所有调用点有没有把新字段接住**；
反过来，看到一个三元组返回值只被用了两个字段，就该问第三个去哪了。

这已经是连续第三轮同一个模式（ROUND-58 预演、ROUND-59 主路径、本轮另两条路径）。
我把它记成一条固定动作：**新增"给用户看的数字"时，先 grep 出该函数的全部调用点。**
