# AUDIT-ROUND-173 · 第 173 轮：接上官方标签栏的玻璃行为 `tabBarMinimizeBehavior`

> 用户反馈仍然指向同一件事：**该液态玻璃的控件没有用官方控件。**
> ROUND-172 已把标签栏换成官方 `TabView`；本轮补齐它的系统玻璃行为。

## 1. 漏掉的官方行为

`swiftui-expert-skill` 的 `latest-apis.md › Tab Bar`：

> **Use `tabBarMinimizeBehavior(_:)` to control tab bar minimization on scroll.**
> ```swift
> TabView { ... }
> .tabBarMinimizeBehavior(.onScrollDown)
> ```

这是 iOS 26 起系统标签栏的**标准动作**：向下滚动时标签栏最小化、向上滚回来时展开。
**自己画的栏做不出这个** —— 它不是"加一个动画"，而是系统标签栏的内部行为。

这恰好印证了本轮的主线：换官方控件之后，才能拿到官方控件的**整套行为**，
而不是只拿到它的外观。

## 2. 另外两条官方玻璃控件，本仓为何不用

| API | 用途 | 为什么不用 |
|---|---|---|
| `tabViewBottomAccessory` | 标签栏上方的常驻控件（如音乐 MiniPlayer） | 本仓没有"跨页面常驻的播放/进度类控件"；提示条是**瞬时**的，不是常驻配件 |
| `Tab(role: .search)` | 独立搜索标签，选中时**形变为搜索框** | 本仓的搜索是"凭证页内的过滤"（带历史 chips、与类型筛选联动），不是独立搜索入口。做成 search 标签会让凭证同时出现在两个标签里 |

两条都记在这里，避免下一轮重复评估。

## 3. 方法论

**「用官方控件」包含两层：外观，以及行为。**

| 层 | 自己画 | 官方控件 |
|---|---|---|
| 外观（材质、圆角、着色） | 要自己实现，且难对齐 | 系统给 |
| **行为（最小化、形变、侧边位置、朗读语义）** | **基本做不到** | **系统给** |

ROUND-158 我停在第一层（贴了 `.glassEffect`），ROUND-172 换到官方控件拿到两层，
本轮补上其中一条行为。**这条路径本身值得记下来**：

```
先换控件 → 再逐条对照官方 API 清单，看这个控件还有哪些"行为开关"没打开
```

如果不做第二步，很容易停在"看起来像了，但动起来不像"。
