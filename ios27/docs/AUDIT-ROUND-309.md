# AUDIT-ROUND-309 · 第 309 轮：装了截图遮挡，却把明文留在**应用切换器快照**里

> CI：`6efb970` build 全绿（errors=0）。

## 1. 缺陷

`CaptureShield` 用两路信号判断要不要遮挡：

| 信号 | 覆盖的场景 |
|---|---|
| `UIScreen.isCaptured` | 录屏 / 被别的进程捕获 |
| `userDidTakeScreenshotNotification` | 用户手动截图（遮 3 秒） |

**缺了第三路：退到后台时的系统快照。** 按 Home 键不会把 `isCaptured` 置真，
于是 iOS 在应用切换器里留下的那张快照**原样带着明文**：

| 页面 | 快照里能看到 |
|---|---|
| `KeyDetailScreen` | **完整码值** |
| `ZotpScreen` | **可开门的动态码** |
| `ShareToAndroidScreen` | **开锁二维码** |
| `BackupScreen` | 可开门的备份文本 |

装遮挡的初衷是「不让码值出现在别人的屏幕上」，而应用切换器恰好是**别人最容易看到的那块屏幕** —— 逻辑上自相矛盾。

## 2. 修法

给 `CaptureShieldModifier` 补第三路信号：`@Environment(\.scenePhase)`，**非 `.active` 即遮**。

| 细节 | 为什么这么选 |
|---|---|
| 用 `scenePhase` 而不是 `didEnterBackground` 通知 | `scenePhase` 在**失活的第一时间**就变，快照拍的是失活后的画面 ⇒ 能赶在快照之前遮住 |
| 文案分两种 | 只因后台而遮时显示中性的「已隐藏」，不谎称「正在被录制」 |
| 只影响调用过 `.captureShield()` 的 4 个页面 | 其余界面不动 |

## 3. 顺带核实的两个「以为有问题、其实没有」

| 怀疑 | 核实结果 |
| `CaptureShield` 是不是死代码 | ❌ 不是 —— 通过 `.captureShield()` 修饰符用在 4 个敏感页 ✅ |
| 凭证工作室回收站会不会显示明文口令 | ❌ 不会 —— `CredentialOrg.displayPwd` **从不返回码值**，只返回备注名/「某某的密码 #N」✅ |

## 4. 方法论

**「遮挡」类机制要按「谁会看到」枚举，而不是按「技术上怎么检测」枚举。**

| 检测手段 | 它其实只覆盖 |
|---|---|
| `isCaptured` | 正在被录屏 |
| 截图通知 | 用户自己按了快门 |
| **`scenePhase != .active`** | **应用切换器快照 / 被系统挂起**（本轮补的） |

判据：**做隐私遮挡时，先列出「这块内容可能出现在哪些屏幕上」（别人的录屏、自己的截图、系统快照、投屏），再逐条找检测手段 —— 少列一条就漏一条。**
