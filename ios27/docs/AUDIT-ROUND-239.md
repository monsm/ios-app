# AUDIT-ROUND-239 · 第 239 轮：一个**看不见的筛选**把列表卡住了

> CI：`1d40003` build 全绿；`ac0e3ed` / `f19322d` 排队中。

## 1. 缺陷

`KeysScreen` 的芯片行按老人模式过滤：

```swift
ForEach(KeysFilter.allCases.filter { !MemberHub.elderMode || $0 == .all || $0 == .password || $0 == .fingerprint }, …)
```

老人模式下「临时码 / 手机钥匙」两个芯片**被隐藏**，但 `filter` 是 `@State` —— 它仍可能是被隐藏的那个：

| 操作序列 | 结果 |
|---|---|
| 选中「临时码」芯片 | 列表只剩临时码 |
| 去设置打开老人模式 → 回凭证页 | **芯片不见了，筛选还在** |
| 用户看到 | 只有几条凭证，**没有任何芯片高亮**，不知道为什么 |

## 2. 修法

抽出 `visibleFilters` 作为**唯一口径**（芯片行与回落都用它），`onAppear` 里回落：

```swift
if !visibleFilters.contains(filter) { filter = .all }
```

## 3. 为什么抽 `visibleFilters` 而不是就地再写一遍

那个过滤式本来只出现一次；本轮要在**第二个地方**用它（回落判断）。

| 做法 | 后果 |
|---|---|
| 两处各写一遍 | 以后改老人模式规则时只改一处 ⇒ **芯片隐藏了但回落没跟上**（或反之） |
| **抽成一个计算属性** | 规则只有一份 |

## 4. 方法论

**「隐藏了控件，却没隐藏它的状态」是一类安静的 UI bug。**

| 形态 | 表现 |
|---|---|
| 隐藏 tab / chip / 开关 | 对应的 `@State` 仍生效 |
| 用户感受 | 「列表怎么少了东西」而界面上没有任何线索 |

判据：**任何"按条件隐藏某个控件"的地方，都要问一句「它的状态在隐藏期间还有效吗、需要回落吗」。**
