# AUDIT-ROUND-68 · 第六十八轮：修掉闸门自己的脆弱点（固定行数窗口）

## 1. 上一轮被迫"缩短注释"来让闸门变绿

`privacy` 第 8 条（CSV 防公式注入）的实现是：

```js
if (/static func field\(_ value: String\)/.test(line)) {
  const srcWindow = f.lines.slice(i, i + 10).join("\n");   // ← 只看 10 行
  if (!/v = "'" \+ v/.test(srcWindow)) note(...);
}
```

我上一轮把注释写详细了，那行防护代码被推到第 11 行 —— **闸门判红，但代码是对的**。
当时我选择"缩短注释"绕过。但那等于**让注释长度左右安全检查的有效性** —— 这不对。

## 2. 修法：扫到函数体结束

按缩进找到函数体的闭合 `}`，对整个函数体做判定。注释多长都不影响。

## 3. 验证（真的能抓到远处的缺陷）

把防护行替换成 `v = v`（即**去掉防护**），并在它上方插入 20 行注释 ——
即"防护逻辑远在窗口之外"的情形。

- 旧规则：`slice(i, i+10)` 看不到，**漏判**；
- 新规则：扫到函数体结束，**判红** ✅

```
privacy: FAIL — 1 处回归

```

## 4. 方法论

**按"行数窗口"写的检查，都会随着被检查代码的注释增删而失效。**
这类闸门的失效是**静默的**：它不会报错，只会变得越来越宽（漏判越来越多）。

判据：**任何 `slice(i, i + N)` 形式的判据都要改成"按结构划界"**（函数体/块/文件），
N 是脆弱的、结构是稳定的。这可能是本仓其它闸门的共性问题 —— 下一轮逐个查。
