# AUDIT-ROUND-301 · 第 301 轮：把「索引不会漂」变成第 23 道闸门

> CI：`c009788` build 全绿。

## 1. 上一轮的声明有个洞

上一轮我写「索引是脚本生成的，所以不会漂」，并把它当作优点。
但**只生成一次、靠人记得重跑**，和手写目录的漂移风险一模一样 —— 只是把「忘记改」换成了「忘记重跑」。

## 2. 修法：第 23 道闸门 `auditindex`

| 动作 | 行为 |
|---|---|
| `node Gates/auditindex.js` | 重新生成 → 与 `docs/AUDIT-INDEX.md` **逐字节比对**，不等则判红并提示 `--write` |
| `node Gates/auditindex.js --write` | 就地重生成 |

生成器成为唯一真源；索引文件只是它的产物。

## 3. 加闸门当场触发了另一道闸门（很好的连锁）

闸门数从 22 变 23 ⇒ **`workflow` 闸门立刻报红 7 处**：README / COMPLETION / ARCHITECTURE / AUDIT-COVERAGE / ios27.yml
里所有「22 道」的声称都过期了。共改了 **11 处**（含「二十二道」中文数字与两处示例输出块）。

这正好证明了 `workflow` 那条「声称的闸门数必须等于 allgates 真实数量」是有效的 —— 它不靠人记。

## 4. 双向验证

| 方向 | 结果 |
|---|---|
| 干净状态 | ✅ `auditindex: OK — 索引与 300 份审计文档一致` |
| **塞一份假文档 `AUDIT-ROUND-998.md`** | ✅ 报「与重新生成的结果不一致」，`allgates: 1/23 失败` |
| 删掉假文档 | ✅ `allgates: 全部 23 道闸门通过` |

## 5. 方法论

**「生成式产物」不自动等于「不会漂」—— 漂移风险只是从「忘记改内容」转移成「忘记重跑生成器」。**

| 做法 | 真实漂移风险 |
|---|---|
| 手写文档 | 忘记改 |
| 生成但无校验 | **忘记重跑**（与手写同级） |
| **生成 + 逐字节校验闸门** | 无（不一致就红） ✅ |

判据：**凡是「由脚本生成并提交进仓库」的文件，都必须配一道「重生成后是否一致」的闸门；否则它只是换了种方式手写。**
