# AUDIT-ROUND-104 · 第一百零四轮：给新闸门做跨平台验证（而不是硬找缺陷）

> CI：`539d4f7` 已验证（build + golden）；`cceceb7` / `4ea2c9f` / `a25ec99` 待回执。

## 1. 唯一真实的待验证项：`reserved.js` 还没在 CI 上跑过

第 21 道闸门是我在本机（Windows / CRLF）写的，而 CI 的 `gates` job 跑在 **ubuntu（LF）**。
闸门读 `.md` 与 `.swift` 时如果对行尾有假设，本机绿、CI 红是完全可能的。

## 2. 做了什么验证

**（a）静态检查跨平台风险**

```
grep -E "path.sep|\\\\|\\r" Gates/reserved.js
```

结果：只有 `split(/\r?\n/)` 这一种行尾处理（已兼容 CRLF/LF），**没有路径分隔符假设**。

**（b）端到端模拟**：把整个 `ios27/` 复制到临时目录、**把所有 CRLF 转成 LF**，再跑闸门：

```
exit: 0
```

也就是说在 Linux 的行尾环境下同样通过。

## 3. 顺带核对了一个我担心的正则

① 的判据是 `\bfunc <name>|\benum <name>` —— 交替符优先级容易出错。
在真实源码上逐个测了 8 个符号：

| 符号 | 交替版 | 只 `\bfunc` |
|---|---|---|
| `TimeWord`（是 enum 不是 func） | ✅ 命中 | ❌ 不命中 |
| 其余 6 个（都是 func） | ✅ | ✅ |
| `NopeXyz`（不存在） | ❌ 正确不命中 | ❌ |

交替是**必要的**（`TimeWord` 是 `enum`），且不会误判。

## 4. 方法论

**"本机绿" 与 "CI 绿" 之间隔着"运行环境差异"，而这类差异只能靠"模拟对方环境"来验。**

本段已经因此吃过一次亏（`fd07a75` 的 actor 隔离，本机 20 道闸门全绿、CI 红）。
这次不是靠"等 CI"，而是主动构造了一个 LF 环境 —— 在拿到回执之前就把不确定性降到最低。

判据：**任何新增的闸门/脚本，都要问"它假设了什么环境"**（行尾、路径分隔符、shell、编码）；
能在本机模拟的，就别等 CI 告诉你。
