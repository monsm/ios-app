# AUDIT-ROUND-51 · 第五十一轮：诊断页的「原始帧」面板永远是空的

> CI：`7f87aef` 已验证；`2971b60` 待回执。本轮本地提交，不推送。

## 1. 缺陷：一个只在那盏灯亮时才记录的缓冲

`RecordsStudioScreen` 的诊断区读 `LockService.shared.recentFrames`，展示 `FrameRedact.apply(...)`。
而 `recentFrames` 只在 `log()` 里、且 `msg` 含 `"hex="` 时才 append；
产生这种日志的调用点全部包在 `if debugRaw { ... }` 里。

`debugRaw` 读 `kf_debug_raw`，而**全仓没有任何 UI 写这个键** ——
于是：**原始帧环形缓冲在正常使用中恒为空，诊断面板永远是空的。**

更要紧的是这会误导：用户/支持人员看到空的原始帧列表，会以为"链路没数据"，
而事实是"根本没记录"。

## 2. 修法：把「记录帧」与「打印日志」拆开

- 新增 `LockService.recordFrame(_:)`：只把原始帧放进内存环形缓冲（60 条，不落盘、不可复制）；
- `LockServiceLink` 的 TX/RX 两处：`debugRaw` 开时仍打日志，关时改调 `recordFrame`；
- 同步更正 `debugRaw` 上方的注释（原文写"恒为空"，已不再成立）。

为什么可以无条件记录：这段设计本来就说"完整帧只留在内存 recentFrames（不落盘、不可复制）"，
展示侧还要过一遍 `FrameRedact.apply`。所以"记录"与"是否打日志"本来就该分开 ——
旧实现把两者耦合在一起，才有了这个空面板。

## 3. 方法论

**"诊断能力"必须有一个不依赖开关的采集路径。**
如果采集本身受一个无法打开的开关控制，那么整套诊断就是装饰。

判据：**任何"仅当 X 开启才采集"的开关，都要检查 X 是否可达**；
不可达就等于"永远采不到"，而界面仍会显示一个空面板 —— 比不显示更容易误导。
