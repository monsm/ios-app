# AUDIT-ROUND-185 · 第 185 轮：**交互流水排障页**（用户要求：可复制给你排查开锁问题）

## 1. 原本缺的是什么

仓库里其实有三块底座，**但用户一个都用不上**：

| 底座 | 状态 |
|---|---|
| `LockService.log()` → `DiagLogs`（持久、按天保留、已脱敏） | **每行都在写，但全仓没有任何界面读** —— `DiagLogs.entries/all()/today()` 零消费者 |
| TX/RX 的 `hex=` 日志 | 被 `debugRaw` 挡着，而**那个开关没有 UI**（只能外部改 defaults） |
| `LockService.recentFrames`（内存 60 条） | 记录工作室有「复制」，但**只在内存、重启即失** |

所以用户遇到"开锁失败"时，**无法把现场交互复制出来**。

## 2. 做了什么

**（a）新页 `DiagStreamScreen`（设置 → 帮助 → 交互流水）**

| 元素 | 作用 |
|---|---|
| 开关「记录每条命令的 TX / RX 帧头」 | 写 `kf_debug_raw` —— 补上那个一直缺 UI 的开关 |
| 「复制全部流水」 | `Clip.set(...)`，一行一条：`日期 时间 [级别] 内容` |
| 流水列表 | `DiagLogs.all()` 倒序，等宽字体，可长按选中 |

**（b）`unlock` 补 rc 明文日志**

这是关键一步：TX/RX 帧里的**载荷**会被 `FrameRedact` 脱敏，而 **rc 就在载荷里** ——
若不加这条，用户复制出来的流水只有帧头，**看不出"锁到底为什么拒绝"**。

```swift
log(r.rc == 0 || r.rc == 22 ? "info" : "warn",
    "开锁回执 rc=\(r.rc) · \(StatusParser.rcMessage(r.rc))")
```

自愈重试那条路径也补了一条（`开锁回执(重试后) rc=…`），这样能看出"是不是换了凭证才成功的"。

**（c）设置页入口**

`帮助` 组新增一行「交互流水（排障）」，右侧显示当前行数，点开即弹 sheet。

## 3. 安全边界（**没有妥协**）

帧里携带 skey（cmd05 换钥）/ 密码（cmd0A）/ PIN / ekey —— 都是开锁凭据。所以：

| 出口 | 内容 |
|---|---|
| 交互流水页 / 复制 | **只经 `FrameRedact` 脱敏的文本**：8 字节帧头（命令号 + 长度）+ `…(N bytes 已脱敏)` |
| 完整帧 | **只留内存** `recentFrames`（不落盘、不复制），与既有纪律一致 |
| rc | 明文（协议码，不是凭据） |

新页的注释里也把这条边界写明了 —— 避免以后有人"为了方便"把完整帧接到复制按钮上。

## 4. 怎么用它排查开锁

1. 设置 → 帮助 → **交互流水（排障）** → 打开「记录每条命令的 TX / RX 帧头」
2. 回「门」页，复现一次开锁
3. 回交互流水页 → **复制全部流水** → 发给我

你会看到类似：

```
20:26:01 [info] TX hex=87001004 000000…(12 bytes 已脱敏)
20:26:01 [info] RX cmd=04 hex=87001004 000000…(18 bytes 已脱敏)
20:26:01 [warn] 开锁回执 rc=2 · 无效的PIN码
```

**「cmd 号 + rc + 时间」这三样就足以定位绝大多数开锁失败**：
是没发出去（缺 TX）、没回包（缺 RX）、还是锁明确拒绝（有 rc）。

## 5. 方法论

**"有日志"和"能把日志拿出来"是两件事。**

| 层 | 缺一不可 |
|---|---|
| 采集 | 事件被记录下来（本仓早就做了，还很讲究脱敏） |
| **出口** | **用户能把记录取走**（本轮补的） |

本仓在"采集"上做得非常细（防抖落盘、按天保留、逐段脱敏），
却在"出口"上留了一个洞 —— 三个底座都齐了，就是没有一扇门。

判据：**做可观测性时，从"用户要把它发给谁"倒推** —— 不能复制的日志，等于没有。
