# AUDIT-ROUND-79 · 第七十九轮：消掉「再开一次」的重复日志扫描

> CI：`d252700` 已验证；`1ca498e` / `4ed8c5b` 刚推送。本轮本地提交。

## 1. 上一轮引入的重复计算

上一轮给「再开一次」加了带编号的无障碍标签，用了 `@State` 缓存 `name`。
但复查调用点发现：

| 位置 | 做了什么 | 问题 |
|---|---|---|
| `.task` | `QuickPool.repeatTarget(...)?.name` | 扫一遍日志 |
| `.onChange(lock)` | 同上 | 换锁再扫 |
| `quickLabel`（逐磁贴） | `repeatTargetName ?? repeatTarget(...)?.name` | **兜底分支会再扫一遍** |
| `runQuick` | `QuickPool.repeatTarget(...)` | **第三次扫** |

也就是说我"加了缓存"，但真正频繁触发的 `runQuick` 仍然自己算一次。

## 2. 修法：缓存 `keyID`，一处算好、两处共用

`repeatTarget` 的两个成员都是**同一份确定性输入**算出来的：

- `keyID` 是"去哪"（跳转用）—— `"pwd:3"`；
- `name` 是它的显示形式 —— `"#3"`。

所以只存 `keyID` 即可，`quickLabel` 从它派生显示文本（`split(":").last`）。
这样：**算一次、两处用、零重复扫描**。

（顺带核对了 `Router.request(.key(id:))` 期望的格式：`AppModel:653` 也是构造 `"pwd:\(alias)"`，
格式一致，派生显示不会引入不一致。）

## 3. 顺带记录一次失败的尝试

我想把"元组成员有没有被使用"做成扫描器，结果 13 个候选里**几乎全是误报** ——
因为多行解构 `let (a, b) = f(...)` 和 `.0 / .1` 访问识别不了。
按前几轮定下的原则（误报多的工具比没有更糟）**放弃**，改为手工核对调用点。

手工这一步确实抓到了真问题（`runQuick` 的第三次扫描），说明"工具做不了就手工列调用点"
在这类检查上仍然有效。

## 4. 方法论

**"我加了缓存"需要按调用点逐个验证，而不是按"我写了一个缓存变量"来判断。**

上一轮我写了 `@State` 并改了两处（`task`/`onChange`），就以为"缓存好了"；
实际最热的那条路径（`runQuick`）压根没走缓存。

判据：**加缓存时，先列出该函数的所有调用点，逐个确认它走的是缓存而不是原始计算。**
——与本仓反复出现的"先列调用点"是同一个动作（`grep 函数名`）。
