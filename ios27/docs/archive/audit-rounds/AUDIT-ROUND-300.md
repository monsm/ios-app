# AUDIT-ROUND-300 · 第 300 轮：把 299 份审计文档收成一份可检索索引

> CI：`c009788` build 全绿（errors=0）。

## 1. 为什么做这件事

`docs/` 下已有 **299 份** `AUDIT-ROUND-*.md`。它们各自写得清楚，但**没有入口** ——
想回答「备份这块查过没有」「通知这块查过没有」，只能一个个打开。
这轮把它做成一份**脚本生成的索引**。

## 2. 内容

| 段 | 说明 |
|---|---|
| 怎么用 | 三种典型问题各指向哪一段 |
| **方法论入口** | 10 条跨轮沉淀的判据，每条标注出处轮次 |
| 全部轮次 | 299 条标题，按 50 轮分段 |
| **真机专属** | 7 项静态验证不了的，写明为什么 |

## 3. 关键点：索引是**生成**的，不是手写的

| 做法 | 漂移风险 |
|---|---|
| 手写目录 | 每加一轮就要记得改，迟早漏 |
| **脚本读 `docs/AUDIT-ROUND-*.md` 的 `# ` 行生成** | **不可能漂** ✅ |

生成时踩了一个小坑：文档标题里含反引号（如「手写 `CodingKeys` …」），
而我用模板字符串拼行 ⇒ 反引号把模板截断。改成字符串拼接即可。

## 4. 方法论

**「写了很多文档」不等于「知识可用」—— 缺索引时，299 份文档的实际检索成本高于重做一遍。**

| 资产 | 什么时候变得没用 |
|---|---|
| 无索引的文档集 | 数量超过「能记住在哪一份」的阈值之后 |
| **有生成式索引的文档集** | 只有当文档本身丢失时 |

判据：**凡是「按编号/日期成批产出」的文档，第一天就该配一个生成式索引 —— 手写目录一定会漂。**
