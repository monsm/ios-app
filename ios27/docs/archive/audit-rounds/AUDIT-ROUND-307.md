# AUDIT-ROUND-307 · 第 307 轮：行号引用全扫 —— 0 处真实失效

> CI：`344acda` build 全绿（errors=0）。

## 1. 方法

扫全部注释里的 `X.swift:NNN` 形式，检查两件事：

| 检查 | 含义 |
|---|---|
| 被引用文件是否存在 | 不存在 = 读者找不到 |
| 行号是否 ≤ 该文件行数 | 超出 = 行号一定失效 |

## 2. 结果

| 类别 | 数量 | 判定 |
|---|---|---|
| **行号超出文件长度** | **0** | ✅ 所有「活引用」都落在文件内 |
| 引用文件不存在 | 17 | 逐条核实后**全部合理**（见下） |

## 3. 那 17 条为什么合理

| 类别 | 例子 | 说明 |
|---|---|---|
| **溯源注释**（「来源：原 X.swift:NNN」） | `UnlockDial.swift:311`、`DeviceHomeView.swift:77`… | 指向**旧版 App 目录**（`D:\aapk\ios-app\App`），那边文件都在 ✅ 逐条核对 9 个文件名全部命中 |
| **已自我标注失效** | `DiagKit.swift:61` 的 `CredentialStudio.swift:1113-1115` | 注释本身写着「该文件已于 2026-10-29 拆成 8 个文件，**行号失效**；行为本身仍在」 ✅ |

所以没有一条需要改。

## 4. 方法论

**行号引用一定会过期 —— 能做的不是「永不过期」，而是「过期时可被识别」。**

| 做法 | 过期后读者体验 |
|---|---|
| 只写 `X.swift:123` | 找不到就当自己看错了 |
| **写「来源：原 X.swift:123」**（标明是历史文件） | 知道该去旧树找 ✅ |
| **就地注明「行号失效，行为仍在」** | 知道这是历史注记，不会白找 ✅ |

判据：**无法避免过期的引用，就要在写下的那一刻标明它的「时效属性」（历史 / 当前 / 已失效）—— 这比精确行号本身更有价值。**
