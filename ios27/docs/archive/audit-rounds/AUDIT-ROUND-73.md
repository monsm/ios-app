# AUDIT-ROUND-73 · 第七十三轮：用「可达性」扫描又分出两种东西

> CI：`6801fa3` 已验证；`d36c6e5` / `2dae705` 刚推送。本轮本地提交。

## 1. 先确认这一类已经清干净

两个更硬的判据（比上一轮的"引用数"更可靠）：

```
private static func 同文件零引用  -> 0 处
private func（含实例方法）同文件零引用 -> 0 处
```

`private` 在 Swift 里只可能被同文件调用，所以"零同文件引用"= **必然不可达**。两者都为 0，
说明前几轮的清理是彻底的。

## 2. 跨文件扫描：132 个候选，其中 5 个 `same-refs: 0`

"对外零引用"对 `internal` 函数来说**不能直接判死**（可能是给未来用的保留），
所以改看"定义文件内也零引用"——那是**必然死的**（连它自己文件里都没人调）。筛出 5 个：

| 函数 | 判定 | 处置 |
|---|---|---|
| `BatteryCare.facePct` | **真死**：三个界面都直接用 `displayPct`，它只是多包一层 | 删除 |
| `CredentialOrg.removeSearchHistory` | 保留未接（531 配套，缺 UI 入口） | 加标记 + 入清单 |
| `CredentialOrg.recentUseCount` | 保留未接（529 组尾统计，实现完整含性能优化） | 加标记 + 入清单 |
| `CredentialOrg.pwdAgeDays` | 保留未接（包5 凭证工坊辅助） | 加标记 + 入清单 |
| `AutoOpenKit.clearAutocal` | 保留未接（缺「重新校准」入口） | 加标记 + 入清单 |

## 3. 判定依据（沿用 RESERVED 的三特征）

- `facePct`：**没有**接线点、**没有**需求编号、实现只是转发 —— 三特征全不满足 ⇒ 死；
- 其余四个：都有需求编号（531 / 529 / 包5 / 自动校准）、实现完整（`recentUseCount` 甚至有
  "把解析提到循环外"的性能优化注释）⇒ 保留未接。

## 4. 方法论

**"可达性"与"引用数"是两件事，而"对外零引用"还有第三种解释。**

| 形态 | 判据 | 处置 |
|---|---|---|
| 引用数 = 0 | 单符号引用计数 | 死（除非 private 且被反射，本仓无）|
| 引用数 > 0 但成闭环 | 追引用点的可达性 | 死簇（ROUND-72） |
| **对外 0、对内也 0** | 定义文件内也无人调 | **必然死** |
| 对外 0、对内 > 0 | 同文件内自洽 | **可能保留未接**，看三特征 |

第四行才是需要人工判断的那类 —— 而它恰好是**最容易被误删的**（"看起来有人用"）。
所以本轮只对第四行加标记、不改行为，只对第三行动手。
