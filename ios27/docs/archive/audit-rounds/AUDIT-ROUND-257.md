# AUDIT-ROUND-257 · 第 257 轮：钥匙串没写进去，界面却说「配置已保存」

> CI：**`f03e367` build 全绿**（可观察手势设置编译通过）。

## 1. 缺陷

    private func saveDav() {
        DB.store.set("kf_bk_dav_url", …)
        DB.store.set("kf_bk_dav_user", davUser)
        DB.store.set("kf_bk_dav_path", …)
        _ = SecretStore.set(davPassword, for: "backup.webdav.password")   // ← 返回值被丢掉
        davState = "成功：WebDAV 配置已保存"
    }

`SecretStore.set` 的签名是 `-> Bool`（钥匙串写入成功与否）。用 `_ =` 丢掉之后**无条件报成功**。

| 情况 | 界面 | 实际 |
|---|---|---|
| 钥匙串写失败（受限/被锁/配额） | 「配置已保存」 | **密码没存下来** |
| 用户之后点上传 | 以"没有密码"的形态失败 | 与界面的"已保存"矛盾 |

## 2. 修法

接住返回值，失败时如实说明「配置已保存，但应用密码没能写进钥匙串」。
（地址/账号确实写进去了，所以不能说"全都没保存"—— 要精确到**哪一项**没成。）

## 3. 顺带

grep 全仓 `_ = SecretStore.set` / `_ = SecretStore.remove` —— **无其他丢弃点** ✅。

## 4. 方法论

**`_ =` 是 Swift 里最容易被忽略的"断言真空"：它让一个返回 Bool 的调用看起来像无返回。**

| 写法 | 编译器 | 后果 |
|---|---|---|
| `try? f()` | 有 `try?` 提示 | 已被 Round 223 的闸门覆盖 |
| **`_ = f()`** | **完全静默** | **只能靠人看** |
| `f()`（`@discardableResult`） | 静默 | 同上 |

判据：**凡是返回 `Bool` 的"写"函数，调用处必须接住并处理；`_ =` 只允许用在确实无副作用的场景。**
本轮这处若不接住，用户会在"上传失败"和"明明显示已保存"之间反复怀疑自己。
