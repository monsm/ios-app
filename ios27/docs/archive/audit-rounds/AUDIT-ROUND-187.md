# AUDIT-ROUND-187 · 第 187 轮：时间戳格式器在同一行里多次取「现在」

> CI：**`f08d7db`（交互流水页）已验证绿**；`c0b755a` 待回执。

## 1. 缺陷

`DiagTime` 的四个格式器都是这个形状：

```swift
return String(format: "%02d:%02d:%02d",
              c.component(.hour,   from: Date()),   // ← 取一次
              c.component(.minute, from: Date()),   // ← 又取一次
              c.component(.second, from: Date()))   // ← 再取一次
```

三个 `Date()` 是**三个不同的瞬间**。绝大多数时候差几微秒、看不出来；
但跨秒/跨天那一瞬，拼出来的时间戳会是**两个瞬间的拼接** ——
例如 `23:59:59` 里最后一次取已经到 `00:00:00`，得到 `23:59:00`（或更糟的组合）。

危害不大但性质差：**时间戳本身是用来对齐证据的**。
排查时"这条日志到底是 23:59 还是 00:00"若不可信，对齐就失去意义。

## 2. 修法

**一次取，多处用**：

```swift
let now = Date()
return String(format: "%02d:%02d:%02d",
              c.component(.hour, from: now), c.component(.minute, from: now), c.component(.second, from: now))
```

四个函数（`hhmmss` / `mmddHHmm` / `mmddHHmmss` / `full`）都改。

## 3. 本轮另外 2 项「审过、判定合理」

| 疑点 | 结论 |
|---|---|
| 遍历时改数组（Swift 会崩或跳元素） | **0 处** ✅ |
| 其余「一行里多次 `Date()`」 | 2 处，都是 `calendar.date(...) ?? Date()` 的兜底，取到哪个都不影响语义 ✅ |
| 同页同时用 `.onAppear` 与 `.task` 加载 | 7 个文件，但两者职责互补（`.onAppear` 读本机缓存 / `.task` 刷新 Engine 投影），不是重复 ✅ |

## 4. 方法论

**"时间戳"这种东西，只要写了两次「现在」，它就已经不精确了 —— 哪怕平时看不出来。**

| 写法 | 出问题的概率 | 出问题时的后果 |
|---|---|---|
| `Date()` 取一次 | 0 | — |
| `Date()` 取多次 | 极低 | **时间戳不可信**，而它的唯一用途就是可信 |

这类缺陷的判据不是"会不会发生"，而是**"它坏掉的那一刻，还有没有别的东西能兜底"**。
时间戳没有兜底 —— 它坏了就是坏了，而且看不出来。
