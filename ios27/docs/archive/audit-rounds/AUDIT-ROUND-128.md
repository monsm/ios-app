## 1. 缺陷：`createdAt` 在"逐字段重建"处被清零

ROUND-93 我给 `KeyItem` 加了 `createdAt`（带默认值 0），用来显示「已使用 N 天」。
而本仓有三处**逐字段重建 `KeyItem`** 的地方，都没跟着加：

| 位置 | 场景 | 后果 |
|---|---|---|
| `KeysParts.withDisabled` | 停用 / 恢复凭证 | 详情页「已使用 N 天」消失 |
| `KeysParts.withExpiry` | 改到期日 | 同上 |
| `MemberDetailScreen:409` | 解除成员归属 | **所有**相关凭证的年龄清零 |

**为什么编译不报错**：`createdAt` 有默认值 `= 0`。逐字段重建时漏传一个带默认值的字段，
Swift 完全不提示 —— 这正是"默认值掩盖漏传"这类缺陷。

## 2. 修法

三处都补 `createdAt: key.createdAt`（或 `k.createdAt`）。

## 3. 顺带：指纹那条也该填

`AppModel.reloadKeys` 里指纹那条原本没填 `createdAt`，理由是"指纹台账没有到期字段"。
但 `LedgerFp` **有 `at`**（录入时刻，注释写明"epoch **毫秒**，与 `LedgerPwd.at` 同约定"）——
所以指纹同样能显示「已使用 N 天」。已填 `createdAt: f.at`。

手机钥匙（`MobileKey`）确实没有创建时刻概念，保持默认 0 是对的。

## 4. 方法论

**"给结构体加带默认值的字段"是一种高危改动** —— 它不会报错，但所有"逐字段重建"处都会静默丢值。

正确做法（本轮才做到）：

1. 加字段时**立刻** grep 该类型的**所有构造点**（`grep "KeyItem("`）；
2. 逐个看是"新建"还是"重建"；重建的必须带上新字段；
3. 若新建的确实没有该值，写明为什么（如手机钥匙）。

我在 ROUND-93 只改了 `AppModel` 里**密码**那一条（因为我当时想的正是"密码要显示年龄"），
完全没想到另外三处重建点。**"改一处就以为改完了"** 是本段反复出现的同一个错误形态。
