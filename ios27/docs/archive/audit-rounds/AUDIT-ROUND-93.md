## 1. 按「接线成本」评估 RESERVED 剩余项

上一轮定了新判据：登记时要写清接线成本，**低成本的要直接做掉**。
这一轮挑了 `pwdAgeDays`（凭证年龄）——接线点是"凭证详情页加一行"，成本低。

实际做下来发现是**中**：`KeyItem`（界面投影）没有创建时刻字段，要先给模型加 `createdAt`、
在 `AppModel.reloadKeys` 里从 `LedgerPwd.at` 填进去。

## 2. 修法

1. `KeyItem` 加 `var createdAt: Double = 0`（**带默认值** —— 三处构造点只有密码那条需要填，
   指纹/手机钥匙没有这个概念；有默认值就不必改动另外两处，也不会触发"实参顺序"那类编译错）；
2. `reloadKeys` 里密码那条填 `p.at`；
3. 详情页在"已使用"一行展示（`createdAt == 0` 时不显示）。

## 3. 我当场改掉了自己造的重复实现

第一版我在详情页写了个 `private static func ageInDays(since:)`，理由是"`pwdAgeDays` 收 `LedgerPwd`，
而本页只有 `KeyItem`"。写完立刻意识到：**这正是我这几轮一直在修的"同一规则两份实现"**。

正确处置是**改前者的签名**：

```swift
// 前：pwdAgeDays(_ p: LedgerPwd)
// 后：pwdAgeDays(_ millis: Double)   —— 收毫秒 epoch，两边都能用
```

然后删掉我自己那个 `ageInDays`。

> 值得记的是：**"为了复用一个函数而先造一个假对象"** 与 **"另写一份实现"** 都是错的；
> 第三条路（把签名改成两边都适用的形状）才是对的，而它需要改动一个"已经有调用点"的函数 ——
> 所以更容易被下意识避开。
