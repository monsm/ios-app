# AUDIT-ROUND-97 · 第九十七轮：我的 RESERVED 清单有 4 条是错的

> CI：`bac6cbb` 已验证；`f90fac9` / `e5c4c04` 刚推送。本轮本地提交。

## 1. 发生了什么

我按新判据去接「低成本项」`weakReason`（弱口令提示）—— 打开 `KeyCreateParts.swift` 一看，
**它已经在用了**：

```swift
if let weak = CredentialOrg.weakReason(code), codeValid {
    KeysInlineNote(tone: .attention, text: "弱口令：\(weak) —— 建议换一串更难猜的数字。")
}
```

于是把整份 RESERVED 清单逐条 grep 验证，又发现**三条同类误判**：

| 符号 | 实际调用点 |
|---|---|
| `weakReason(_:)` | `KeyCreateParts.swift:192` |
| `strictBytes(_:)` | `ZKProtocol.swift` **7 处** + 5 条测试 |
| `batchPrefixNote(...)` | `CredentialStudioScreen.swift:491` |
| `recentExcerpts(_:_:)` | `MemberOpsScreen.swift:282` |

清单从 12 条缩到 **9 条**。

## 2. 根因：我把"标记"当成了"证据"

这 4 个函数的注释里都写着 `【保留未接 2026-10-29】`。我当时就是**按标记采信的**，
没有验证调用点。

而**标记会过期** —— 接线的人忘了去掉标记，标记就从"事实"变成了"假信息"。
更麻烦的是：我上一轮还给这份清单加了一列「接线成本」，那等于给假信息加了权威性。

## 3. 判据修正（已写进 RESERVED.md 顶部）

> **`【保留未接】` 标记只是"线索"，不是证据。**
> 判定零调用必须 **grep 名字并逐个看命中处是定义、注释还是真调用**。

这条其实正是本段前几十轮一直在用的方法（"注释里的承诺要去找实现"），
**只是这次我自己在文档里犯了同一个错**。

## 4. 顺带确认真正剩下的 9 条

逐个 grep 后，剩余 9 条的命中全部是「定义 + 注释」，无真调用 —— 这一轮之后清单是干净的。

## 5. 方法论

**给一份清单加"权威字段"（如成本列）之前，必须先验证清单本身的正确性。**

我上一轮加成本列时很认真地在评估每条的成本，却没先验证"这条到底该不该在清单里" ——
顺序反了。**先验证事实，再给事实加注解。**
