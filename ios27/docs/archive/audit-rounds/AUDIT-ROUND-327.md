# AUDIT-ROUND-327 · 第 327 轮：把剩下两个根页也交给系统标题，并修正阅读顺序

> 接 326 轮。那轮把门页与设置页的标题交给系统导航栏；本轮补齐 Keys / Records，
> 并修掉一处**阅读顺序**问题。

## 1. 四个根页的标题归属（本轮收口）

| 页 | 改前 | 改后 |
|---|---|---|
| 门 | 导航栏隐藏 + **页内没有任何标题** | 系统大标题 = 锁名 |
| 钥匙 | 导航栏隐藏 + 页内 34pt「凭证」 | 系统大标题「凭证」 |
| 台账 | 导航栏隐藏 + 页内 22pt「记录」 | 系统大标题「记录」 |
| 设置 | 导航栏隐藏 + 页内 34pt「设置」 | 系统大标题「设置」+ 系统搜索 |

**为什么非要系统大标题**：它随滚动收成 inline，导航栏这时才浮现液态玻璃；
自绘标题永远是静止的一块字，拿不到这层材质，也拿不到「点状态栏回到顶部」和标题语义。

## 2. 两个页面**保留自绘搜索框**，这是有意的

| 页 | 自绘搜索框承载的功能 | 若换 `.searchable` 会丢什么 |
|---|---|---|
| 钥匙 | **搜索历史芯片**（轻点执行 / 长按删除） | 历史芯片没有落点 |
| 台账 | 搜索 + 告警类型筛选 + 工作室 / 导出 / 读取 四个动作 | 那张卡不只是搜索框 |

判据：**「换原生」只在原生能等价覆盖现有功能时做。** 覆盖不了就保留自绘 ——
自绘控件在内容层并不违反 HIG（HIG 禁的是内容层刷玻璃，不是内容层有控件）。

## 3. 阅读顺序：一句解释被夹在两排芯片中间

Keys 与 Settings 原来的顺序是：

```
芯片行（状态/快捷） → 导语（一句解释） → 分组芯片行（筛选） → 内容
```

读起来是「控件 → 解释 → 控件」。既然标题已经在导航栏，正确顺序是
**标题 → 解释 → 控件**。两页都改成：

```
导语 → 芯片行 → 分组芯片行 → 内容
```

## 4. 顺带清掉一个因改动而失去消费者的令牌

`V.F.titleC`（22pt/600）只被台账页的页内标题用过。标题搬进导航栏后它零消费，
按 `tokens.js` 的规矩删掉 —— 它在第 325 轮回退时被恢复过，正是因为它当时还有消费者。
**同一个令牌删了又恢复、恢复了又删，不是反复无常：判据始终是"有没有人读它"。**

## 5. 方法论

| 判据 | 出处 |
|---|---|
| **标题属于功能层**；自绘标题拿不到折叠、玻璃、无障碍语义 | 本轮 §1 |
| **「换原生」的前提是原生能等价覆盖现有功能** —— 覆盖不了就别换，别为了统一而丢功能 | 本轮 §2 |
| **控件与解释的先后顺序决定可读性** —— 解释应该紧接标题，而不是夹在两排控件之间 | 本轮 §3 |
| **令牌的存废只看消费者**，不看它"看起来是否合理" | 本轮 §4 |
