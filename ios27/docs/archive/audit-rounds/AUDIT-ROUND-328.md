# AUDIT-ROUND-328 · 第 328 轮：把重复标题扫干净，并收窄文本色阶

## 1. 上一轮的扫描有盲区：只认「字面量形式的标题」

第 325 轮用 `Text("X").font(V.F.display*)` 匹配重复标题，于是漏掉了**标题由共享组件绘制**的那一类：

| 组件 | 用的页面 |
|---|---|
| `SettingsHeader(title:)` | About / Appearance / AutoOpen / Backup / Security |
| `HHPageHeader(title:)` | Household / MemberArchive / MemberCreate |

这 8 个页面同样是「导航栏一个标题 + 页内一个同名大标题」。

## 2. 本轮处置

| 页 | 处理 |
|---|---|
| About / Appearance / AutoOpen / Backup / Security | 清空导航栏标题（`SettingsHeader` 的 34pt 大字保留） |
| MemberArchive / MemberCreate | 同上（`HHPageHeader` 保留） |
| **Household** | 反过来：标题交给系统大标题「家」，`HHPageHeader` 新增 `showsTitle: false`，只留 overline 与状态行 |

为什么 Household 与另外两个 HH 页相反：它是 **Tab 根页**，与其余四个根页保持同一种外壳（系统大标题）；
另外两个是子页，用页内标题 + 空导航栏（与全仓子页一致）。

## 3. 顺带收窄文本色阶：10 → 7

审计发现 `V.C` 的文本色是**九个编号档 + axisLabel**，其中：

| 令牌 | 实际情况 |
|---|---|
| `text9` | **与 `text2` 数值完全相同**（两种外观都相同）—— 5 处读取其实是同一个颜色 |
| `text5` | 仅 1 处读取；与 `text4` 只在深色值差一点 |
| `text8` | 仅 1 处读取；与 `text2` 只在深色值差一点 |

处置：`text9 → text2`（**零视觉变化**，纯改名）、`text5 → text4`、`text8 → text2`（各一处深色微调），
删掉三个声明。色阶从 10 个名字降到 7 个。

**顺带抓到一个真实的不一致**：同一段「页导语」在钥匙页是 `text9`、在设置页是 `text3` ——
浅色下是两个明显不同的灰。统一为 `text3`。

对比度闸门里有三对把被删令牌写死在参数里，已改为承接它们的令牌，30 对仍全部达标。

## 4. 方法论

| 判据 | 出处 |
|---|---|
| **扫「重复标题」不能只认字面量** —— 标题常常是作为参数传给共享组件的，字符串还在，形态变了 | 本轮 §1 |
| **同名令牌必须同值** —— `text9` 与 `text2` 完全相同这件事，说明色阶是"加名字"而不是"加层次"长出来的 | 本轮 §3 |
| **只有 1 处读取的令牌不是层次，是残留** —— 要么合并进邻居，要么删 | 本轮 §3 |
| **删除令牌会连带打断把它写死在断言里的闸门** —— 闸门要跟着改，不能因为闸门红就把令牌加回来 | 本轮 §3 |
