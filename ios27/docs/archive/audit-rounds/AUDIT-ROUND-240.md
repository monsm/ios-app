# AUDIT-ROUND-240 · 第 240 轮：门页说「5 枚凭证」，点进去列表有 7 条

> CI：**`f19322d` build 全绿**（投影侧 owner 归一化编译通过）。

## 1. 缺陷

两个「凭证数」口径不同：

| 位置 | 算法 | 含手机钥匙？ |
|---|---|---|
| `LockSummary.keyCount`（门页 / 锁状态页） | `ledger.pwds.count + ledger.fps.count` | ❌ |
| 凭证页「全部 N」芯片 | `app.keys.filter { … }.count`（`keys` 含手机钥匙） | ✅ |
| 成员行「名下 N 枚」 | 同上 | ✅ |

于是：**门页说「5 枚凭证在册」，点进凭证页列表却有 7 条**（5 + 2 把手机钥匙）。

## 2. 修法

`keyCount` 加上 `MobileKeyService.list(mac).count`，与 `keys` 对齐。

（`MobileKeyService.list` 在空壳模式返回 `[]`，与 `reloadKeys` 用的同一个函数 ⇒ 两条路径在空壳下也一致。）

## 4. 方法论

**「同一个概念有两个数字」是最容易被用户发现、也最容易被开发忽略的一类。**

| 谁会发现 | 为什么 |
|---|---|
| 用户 | 一眼就能对比两个屏幕 |
| 开发 | 两处各自都"算对了"，只是算的东西不同 |

判据：**给任何"计数"命名时，先写清它的定义（含什么、不含什么），再让所有显示点用同一个来源。**
本仓这类问题已经出现三次（`entries.count` 当本次读数、选中数当成功数、本条），都是"名字一样、算法不同"。
