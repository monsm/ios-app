# AUDIT-ROUND-305 · 第 305 轮：安全域文件头声称了两个**不存在的模块**

> CI：`1897666` build 全绿（errors=0）。

## 1. 缺陷

`App/Engine/AuditChain.swift` 的文件头写着「三个子模块」，并说「实际只有上面两项（AuditLog / AuditChain）」。

实际核实：

| 声称 | 全仓事实 |
|---|---|
| `AuditLog` 审计留痕 | **零类型声明、零调用点** ❌ |
| `AuditChain` 防篡改哈希链 | **零类型声明**；也没有任何「哈希覆盖前序哈希」的链式实现 ❌ |
| `DestroyKit` | 第 99 轮已核实不存在 ✅（这条是对的） |
| 文件真实内容 | **只有 `HashKit`（3 个哈希基元）** |

## 2. 这条假声明是怎么来的

第 99 轮修 `DestroyKit` 那句时，写下了「实际只有上面两项（AuditLog / AuditChain）」——
**修掉一条假声明的同时，把另外两条没核实的当成了真的。**

这是「修正」这个动作本身的风险：修正者会默认「我这次没提到的部分应该是对的」。

## 3. 真实存在的留痕（写清，免得下一个人再去找 AuditLog）

| 机制 | 在哪 | 边界 |
|---|---|---|
| 台账变更留痕 | `StoreLedger.ledgerDiff` → `BleTelemetry.recordEvent` | **200 条上限、落 Caches、不进备份** |
| 口令脱敏 | `HashKit.fingerprint`（sha256 前 4 位） | 明文不落任何留痕（SEC-13） |
| 哈希基元 | `HashKit.sha256Hex` / `fnv1a32` | **无状态，不构成链** |

`HashKit` 本身**不是死代码**：`StoreLedger:150` 用 `HashKit.fingerprint` 做字段 diff 的脱敏 ✅。错的是头注，不是实现。

## 4. 修法

把头注改成**逐条核实过的事实**：三个模块都不存在；真实留痕是哪条链路；`HashKit` 被谁用；
并明确写「在任何防篡改链落地之前，『本 App 有防篡改审计链』的说法不成立」。

## 5. 方法论

**「修正一条假声明」最容易顺手造出另一条 —— 因为修正者会假设「其余部分是对的」。**

| 做法 | 结果 |
|---|---|
| 只删掉被质疑的那一句 | 剩下的未核实陈述变成新的假声明（本轮） |
| **删掉后逐条核实剩下的每一条** | 头注与代码一致 ✅ |

判据：**改一段「说明性文字」时，凡是你没有亲自核实过的断言，要么核实，要么删掉 —— 不要因为它「看起来没被质疑过」就留着。**
