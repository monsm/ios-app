## 1. 盲区：`V7Tokens.swift` 被整体豁免，于是没人检查令牌是否被用

`Gates/tokens.js` 的第一条规则是"页面里不许出现样式字面量"，
而 `V7Tokens.swift` 是**字面量的家**，所以它被整体排除在扫描之外 ——
这是对的（否则每条令牌定义都会红）。

但它带来一个没人注意的副作用：**没有任何闸门检查"令牌是否被使用"**。
本轮按上一轮抓密度 bug 的"表格法"把 `V.C` 的 59 个颜色令牌逐个查消费点，发现：

### `C.blueCursor` —— 全仓零消费点

```swift
static let blueCursor = dual(0x1F6FEB, 0x3F8EF3) // 游标
```

- 没有任何文件引用它；
- 它和 `C.blue`（`dual(0x1F6FEB, 0x3F8EF4)`）**只差最后一个半字节**（F3 vs F4）。

那种"几乎一样却没人用"的令牌是设计系统里最坏的一类残留：
后来的人看到它会以为它有含义、不敢删、甚至照着它做新东西。

**处置：删除，并在原处留一行说明为什么删。**（留着空位比悄悄消失好 ——
下一个人 git blame 到这里能读到理由。）

## 2. tokens 闸门补判据：颜色令牌必须有消费点

新增规则：`V.C` 里每个颜色令牌必须在本文件**之外**至少被引用一次；
若只在文件内被引用，则要求引用它的那个函数**本身**在文件外被调用。

这条"经已用函数间接消费"的必要性是被真实代码逼出来的 ——
我前两版都写错了：

| 版本 | 错在哪 | 后果 |
|---|---|---|
| v1 只看"名字出现在 C 枚举块里" | `C.dimmed` 在外部被用，于是**任何**新令牌只要名字出现在块里就被豁免 | 假通过（我加了个 `zzDeadToken` 测，闸门竟然绿） |
| v2 只扫 `C` 枚举内的函数体 | `ringTrackRed` 的消费方 `V.Ring.track(for:)` 在**兄弟枚举**里，不在 `C` 内 | 误报 3 个（ringTrackRed/Green/Cyan） |

v3 扫**整个令牌文件**的所有 `static func` 函数体，要求"令牌出现在某函数体内，
且该函数在文件外被调用"。结果：

- `ringTrack*` 通过（`V.Ring.track(for:)` 被 `V7Components.swift:404` 调用）✅
- 人工塞进去的 `zzDeadToken` **当场判红** ✅
- 真实代码库全绿 ✅

> 这三次迭代又一次说明：**"证明闸门抓得住"必须真的塞一个死令牌进去测**，
> 只读代码判断"应该能抓到"是不够的 —— v1 就是读起来很对、实际假通过。
