# AUDIT-ROUND-331 · 第 331 轮：自愈在真机上转起来了，但选枚逻辑要改

> 05:35:49 与 05:36:30 的两段真机日志证实：**自愈机制已在跑**（"存储的开锁凭证已失效 —
> 已自动重签"两次出现），但**第二次自愈重复选了第一次已失败的同一枚 PIN** —— 空转。

## 1. 日志说明什么

| 时刻 | 事件 |
|---|---|
| 05:35:49 | ekey(8ad5556d) rc=2 → 现签 pool[1] rc=2 → pool[2] rc=2 → **自愈触发** |
| 05:35:50 | "已自动重签，请再按一次" |
| 05:36:30 | 再按：**又是 8ad5556d** rc=2（自愈上次重签的就是它！）→ pool[0] → pool[2] → 又自愈 |

**因果链**：第一版自愈盲选 `pins[1]` = 8ad5556d。但 8ad5556d **在第一次现签重试时已经失败过**
（"开锁回执(PIN #2) rc=2"）——重签它等于把同一张废票再递一次。

**好消息**：机制本身在转（每次失败都触发、都落盘、都有日志）；
坏消息：**选枚没有记忆**。

## 2. 修法：自愈带记忆，逐枚轮转

`repairPairingEkey` 现在会在 `kf_repair_pin_<mac>` 里**记住上次自愈用的那枚**，
下次自愈时：

1. 排除上次自愈已失败的枚；
2. 排除本次会话刚失败的枚（当前 ekey 嵌的那枚）;
3. 在剩余候选里选第一枚 ≠ 当前 ekey 的；
4. 选中后写回钥匙串 + 记录 `kf_repair_pin_<mac>`。

64 枚池最多 64 次自愈就能穷尽 —— 每次都推进一格，且每一步都有日志。

用 05:35/05:36 的真实数据模拟：

| 轮 | 排除 | 选中 |
|---|---|---|
| 1 | {d2e26f70（当前 ekey）} | 8ad5556d |
| 2 | {8ad5556d（上次失败）+ 8ad5556d（当前 ekey）} | **df8c714c**（不再空转 ✓） |

## 3. 快照交叉验证了修复方向

你贴的快照里"存的那枚 ekey 里嵌的 PIN = **8ad5556d（本机池第 2 枚）**"——
说明在 05:35 自愈后 ekey 已经从 d2e26f70 换成了 8ad5556d。
但 05:36:30 用它开锁**仍 rc=2** ⇒ **8ad5556d 也不在锁端表里**。

结合"锁端已用 PIN 64/64"：锁端的 64 枚与本机 64 枚**完全是两批**。
本机这 64 枚里可能**没有一枚**在锁端 —— 这正是"另一台 App 重新同步过"的特征。
自愈逐枚轮转**有机会碰上**（如果锁端 64 枚与本机池有交集），
但真正的解法是**修池**（第 331 轮的 `repairPool`，保 skey 重写整表）——那个入口还没接到设置页。

## 4. 方法论

| 判据 | 出处 |
|---|---|
| **自愈必须带记忆** —— 无记忆的重试就是"把同一张废票再递一次" | 本轮 §1 |
| **快照是自愈的"对账单"** —— 它告诉你 ekey 现在嵌的是哪枚，对照日志立刻能看出"重签到了已失败的枚" | 本轮 §3 |
