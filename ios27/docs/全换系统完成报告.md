## 七、明确「不做」的清单（附理由）

| 项 | 为什么不做 |
|---|---|
| **13 个纯 `ScrollView` 页面** | 全是「sheet 内套 List 会抢 sheet 滚动」或「内容 ≤ 21 行」，换是负收益 |
| **`KeyCreateParts` 四步表单 Section 化** | ① 四步表单不是「列表」，摊成 Section 行等于把「一次操作」拆成「一堆字段」；② `Group{}.plainRow()` 本身就是「一步 = 一整块」的表达，架构在抵抗；③ `ui-glass.md` §4 把四层校验提示列为必须保留的自造交互。队友实测会把 Section 每行的内边距/分隔线全抹掉（比现状更糟），已完整回退 |
| **内容层刷 `.glassEffect()`** | HIG *Don't use Liquid Glass in the content layer* + `Gates/glass.js` 明令禁止 |

## 八、唯一遗留：需要在 Xcode 编译一次

**我一行都没编译过** —— 这台 Windows 机器没有 Xcode / iOS SDK，无法验证 Swift 编译。

请在 Xcode 里 `xcodebuild` 一次，重点看这三处 API：

| API | 风险 | 若报错的最小回滚 |
|---|---|---|
| `.buttonStyle(.glassProminent)` | 文档确认为 `PrimitiveButtonStyle` 静态成员（iOS 26+），本地无法编译验证 | 改 `.buttonStyle(.borderedProminent)` |
| `GlassButtonStyle()` | 文档确认存在（iOS 26+） | 改 `.buttonStyle(.bordered)` |
| `GroupBox` | 经典 API，低风险；但圆角从 27 变系统值，**视觉会变** | 回滚 `VCard` 一个 struct |

其余改动都是 SwiftUI 标准 API（`List` / `Section` / `.searchable` / `.presentationDetents` / `.swipeActions` / `LabeledContent` / `Divider` / `Picker`），风险低。
