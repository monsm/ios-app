# 审计方法论（AUDIT-METHOD）

> 这份文件记录**怎么找缺陷**，而不是"找到了什么"。
> 每条判据都来自本段（`AUDIT-ROUND-1..137`）里**实际抓到缺陷**或**实际产生假阳性**的经验。
> 没有实战验证过的方法不写进来。

## 0. 第一原则

> **注释、标记、脚本输出、CI 计数 —— 全都是线索，不是证据。**

本段因违反这条而误判过 6 次：

| 轮次 | 我采信了什么 | 真相 |
|---|---|---|
| 97 | `【保留未接】` 标记 | 4 条其实早就接线了 |
| 99/100 | "有需求编号 + 实现完整" | 2 条是重复实现，功能已由界面自己实现 |

| 133 | 以为 `VStateDot + Text` 是重复显示 | `VStateDot` 只画形状，`word` 仅用于 a11y |

**证据 = 打开文件读那几行 + 实跑一次 + 看双向。**

## 1. 找缺陷的七条高价值判据

### 1.1 同族里只有一处漏了

**本段最高产的一条。** 找到一个"做对了"的实现后，立刻 grep 它的同族，逐个看有没有同样处理。

| 轮次 | 同族 | 漏的那一处 |
|---|---|---|
| 30 | 三个单条读取器 | `member(id)` 缺空壳过滤 |
| 47 | 三族钥匙串副本 | 删设备漏清（后续又发现第四族） |
| 76/77 | 两处 `now - t` | `coolReady` / `touchConnection` |
| 81 | 三处 `keepingAwake` | `KeyDetailScreen` |
| 118 | 四种动效写法 | `.transition(` / `.contentTransition(` |
| 126 | 四个 `DateFormatter()` 创建点 | 3 处未钉公历 |
| 137 | 两处 30 天窗口 | `isSleeping` / `reached30d` |

**怎么做**：`grep` 同一个常量、同一种比较、同一个修饰符，而不是只搜函数名。

### 1.2 同一语义的多种写法（闸门的盲区）

闸门"看不见"往往不是漏了文件，而是漏了写法。

| 语义 | SwiftUI 里的写法 |
|---|---|
| 动效 | `.animation(` / `withAnimation(` / `.transition(` / `.contentTransition(` |
| 尺寸 | `.frame(width: N, height: N)` / `.frame(height: N)` / `.frame(height: V.Hit.min - V.S.gapX)` |
| 日期格式化 | `DateFormatter()` / `ISO8601DateFormatter()` / `dateStyle` 版 |

**扩判据前先问**："这件事在这门语言里有几种写法"，再逐个纳入。

### 1.3 读侧合理 + 写侧合理 ≠ 往返正确

| 轮次 | 缺陷 |
|---|---|
| 52 | 字段加了但 `BackupCanonical` 不 emit（导出后读不回来） |
| 119 | `setOrder` 丢顺序（存进去再读出来不是同一个） |

**怎么做**：凡有 get/set 一对，写一个"set 进去再 get 出来"的测试。

### 1.4 带默认值的字段会静默丢

ROUND-93 给 `KeyItem` 加 `createdAt: Double = 0`，三处"逐字段重建"没跟着加 —— **编译不报错**。

**怎么做**：加字段时立刻 grep 该类型的**所有构造点**（`grep "TypeName("`）。
闸门 22 `memberfill` 把这条机械化了。

### 1.5 缓存了派生值，却没写"何时作废"

ROUND-136：`appLowBattery` 缓存按 mac，`sample()` 更新电量后不作废 ⇒ 充上电后动效仍被压。

**判据**：看到 `if cached.x == x { return cached.y }`，就问"x 不变时 y 会变吗"。会变就必须有作废点。

### 1.6 差一 / 边界值不存在

| 轮次 | 缺陷 | 边界 |
|---|---|---|
| 40 | 回收站上限丢错端 | `suffix(from: n)` 越界即崩 |
| 117 | 跨年组头只显示月日 | 年份 |
| 135 | 「23–24 点」 | 小时上界 |

**判据**：凡是「X 到 X+1」的显示，问一句"X 取最大值时 X+1 还合法吗"。

### 1.7 枚举分支用 `switch` 而不是三元

`switch` 有**穷尽检查**，枚举新增一值会编译报错；三元会**静默走 else**。

ROUND-133：`HHMemberStatus` 四态，`HHMemberRow` 只判两种 ⇒「还没用过」和「已归档」都显示成「活跃」。

## 2. 关于闸门（做与不做）

### 2.1 值得做闸门的

| 条件 | 例 |
|---|---|
| 判据清晰、假红少 | `frame` 尺寸、`DateFormatter` 未钉公历、带默认值字段漏传 |
| 缺陷会重复发生 | 同族漏一处、新增字段忘记传播 |

### 2.2 不该做闸门的（本段已放弃 4 个）

| 想法 | 放弃原因 |
|---|---|
| 死类型扫描 | 66 个候选，绝大多数是合法的 |
| 只读 `kf_` 键扫描 | 55 个，绝大多数是"有意只读" |
| 逐字段重建漏传（未登记版） | 839/915 假红 |
| `return` 之后不可达代码 | 130 处假红（多行 `return [` 字面量） |
| 重复修饰符 | 3/4 假红（相邻两个 Button） |

**判据**：**假红多的判据不做**。半成品闸门比没有更糟（会让人开始忽略闸门输出）。

### 2.3 新闸门必须双向验证

1. 现状 → 绿；
2. **故意注入缺陷 → 红**；
3. 修好 → 再绿。

只测"能判红"不够 —— 还要确认"修好后会转绿"（否则可能是一个永远红的闸门）。

## 3. 关于 CI

### 3.1 核对 CI 必须读四样

| `ci-log:meta.txt` 字段 | 说明 |
|---|---|
| `errors=` | 只说明"没有 error 行"，**不等于 job 绿** |
| `build_ok=` / `archive_ok=` | 真正的绿/红判据 |
| `warnings=` | 源码告警数；不是 0 就逐条看 |

### 3.2 本地全绿 ≠ 能编译

本段 6 次"21 道闸门全绿但 CI 红"：

| 轮次 | 错误 | 性质 |
|---|---|---|
| 54 | 实参顺序 | 语法 |
| 89 | actor 隔离 | 并发类型 |
| 108 | 死代码（`return` 后 4 行） | 可达性 |
| 108/110 | Sendable 捕获 | 并发类型 |
| 111 | `@escaping` 位置 | 语法 |
| 119→126 | `@escaping` 删错（3 轮才修对） | 语法 |

**闸门判形状，编译器判类型与语义。**

### 3.3 改类型标注前，先看"它现在能编译吗"

`git show <已知绿的提交>:<文件>` 做基准对比 —— 我两次"纠正" `@escaping` 都是把**正确的写法改错**。

**做法**：不理解的类型标注，只做**最小增量**，不做"纠正"。

## 4. 关于测试

### 4.1 「写了测试」≠「测试在跑」

要看到 CI `test.log` 里的 `passed` 行 + `Executed N tests`。

### 4.2 比对测试的结构性盲区

```swift
XCTAssertEqual(A 的输出, B 的输出)   // 两边都错得一样时，永远通过
```

**两个都要**：

| 写法 | 能发现 |
|---|---|
| `assertEqual(A 的输出, B 的输出)` | A 与 B **不一致**（漂移） |
| `assertEqual(A 的属性, 期望值)` | A **本身错了**（无论 B 如何） |

ROUND-125 补的正是后者，立刻抓到「两个 formatter 都没钉公历」这个从 ROUND-1 起就存在的缺陷。

### 4.3 反向对照断言

```swift
// 旧实现确实会重排 —— 把"被修的缺陷"本身钉成测试
let old = DevSlot.allCases.filter { given.contains($0) }
XCTAssertNotEqual(old, given, "旧实现必然丢掉用户顺序")
```

以后谁改回旧写法，这条会红。

## 5. 关于文档与数字

### 5.1 数字要么机器对账，要么不写

| 方案 | 前提 | 结论 |
|---|---|---|
| 写死数字 | 每次改动都记得同步 | ❌ 本段忘记 6 次 |
| 从源码数出来 | 所有同类都有统一格式 | ❌ `privacy` 的 1–10 条没有编号 |
| **不写数字** | — | ✅ 承认"这个事实不值得维护" |

闸门数由 `Gates/workflow.js` 对账 6 个文件；其它数字（判据条数、断言数）不写死。

### 5.2 历史快照不改

`AUDIT-ROUND-*.md` 里的数字是**当时的真实快照**，改掉等于篡改记录。
对账只覆盖"当前状态类"文档（README / COMPLETION / ARCHITECTURE / AUDIT-COVERAGE / CI 工作流）。

### 5.3 指标与台账是两件事

| | 差集指标 | 逐文件台账 |
|---|---|---|
| 用途 | 找"还没看的" | 回答"哪些看过了" |
| 精度 | 宁可多列 | **必须准确** |

不要用前者替代后者。

## 6. 关于"没有发现"

**「审过但没发现问题」是一种结果，应该如实记录。**

否则两种坏结局：为了"有产出"硬改一处 → 引入回归（本段发生过多次）；不记录"审过" → 下一个人重读一遍。

所以 `AUDIT-COVERAGE.md §2.5` 有一张「已审且无缺陷」表 —— 那是**结果**，不是"没做事"。
