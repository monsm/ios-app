# AUDIT-ROUND-80 · 第八十轮：安全风险披露文案从未显示给用户

> CI：`d252700` 金标全绿；`1ca498e` / `4ed8c5b` / `3479121` 已推送。本轮本地提交。

## 1. 这是本段审核里最重的一处

```swift
/// §3.4 风险披露（**强制展示，不弱化**）
static let riskDisclosure = "默认档只认「手机已解锁 + App 在前台」：别人拿你已解锁的手机走近门锁，
                            6 秒后仍可能自动开门。介意请切严格档（每次进前台刷一次脸）。"
```

注释写着"强制展示，不弱化"，而它**全仓零引用** —— 也就是说这段风险说明，
从未出现在任何界面上。

自动开门是本 App 唯一一个**不需要用户动手就会开门**的功能。用户打开它时，
界面上当时只有"门控边界"（什么时候会被拒）与"标定说明"（怎么调灵敏度），
**没有一句提到"别人拿着你已解锁的手机走近也可能开门"**。

## 2. 为什么这是"承诺级"而不是"文案漏了"

| 层 | 内容 |
|---|---|
| 代码注释 | 强制展示，不弱化 |
| 实际界面 | 从不显示 |

一个功能的风险说明书写了却不显示，用户承担的是**他不知道的风险**。
这与前面几轮修的"假开关""幽灵警告"同族，但后果更重：前几轮是"功能没生效"，
这轮是"用户不知道自己在承担什么"。

## 3. 修法

在自动开门设置页的主开关卡片里，用 `VStatusLine(tone: .attention)` 展示它
（紧跟主开关与状态行之后、门控边界之前）—— 位置刻意靠前，因为它讲的是"这个功能的代价"，
而不是"边界条件"。

（顺带：`callsig2` 又一次抓到我的真错 —— 我先写成 `AutoOpenKit.riskDisclosure`，
而它定义在 `AutoOpen` enum 里。**这是本段审核第二次被自己的工具拦住**，见 ROUND-65。）

## 4. 防复发：`privacy` 第 20 条

判据：`AutoOpenKit.swift` 里定义了 `riskDisclosure`，则 `AutoOpenScreen.swift` 里必须出现它。

**第一版写成 `u.raw.indexOf(...)`，验证时发现漏判** —— 因为我的规则注释里也写了这个词，
`indexOf` 命中了注释。改成逐行检查且排除 `//` 开头才真正生效：

```
移除展示后 → privacy: FAIL — 1 处回归
  AutoOpenScreen.swift:1 — 风险披露文案定义了却没有任何界面显示
```

> 这也是本仓闸门的一条常见坑：**判据里出现的标识符，会污染对同一标识符的检测。**
> 第 8 条（CSV）当初也有类似隐患（它检测 `v = "'" + v`，而注释里写了 `' =x`）。

## 5. 方法论

**"注释里的承诺"要找对应的实现，找不到就是事故。**

这条判据我已经用了十几轮（前 6 处死声明、2 处幽灵开关、1 处幽灵警告），
但之前找的都是"功能/数据结构"。这轮第一次用在**安全披露**上 —— 后果的量级完全不同。

所以补一条固定动作：**专门扫一遍注释里带「强制」「必须」「不得」「承诺」字样的声明，
逐个确认它在代码里真的有对应实现。**
