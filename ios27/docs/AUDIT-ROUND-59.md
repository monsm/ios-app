# AUDIT-ROUND-59 · 第五十九轮：把"会被跳过多少"放到**确认之前**

> CI：`3864e54` 已验证（`errors=0`、`build_ok=1`、`archive_ok=1`）；
> 金标 **72 tests / 0 失败 / 1 skipped**（从 63 增到 72，说明前几轮加的用例确实在 CI 真跑）。

## 1. 上一轮只修了"工作室"那一路

上一轮给 `BackupStudioScreen` 的预演页加了「将被跳过 N 把」。
但**主备份页**（`BackupScreen`，从"文件"App 导入）走的是另一条路：
选完文件 → 直接弹确认对话框 → 点确认才 `runImport()` 解析。

也就是说：**用户在确认的那一刻，还不知道这次会写进多少。**

## 2. 修法

- 选文件并读入文本后，**先解析一次**（只解析、不恢复），得到
  「N 条密码 / M 枚指纹」以及「会被整把跳过的锁数」；
- 把这些写进 `importPreviewNote`；
- 确认对话框的 `message` 用这段摘要**开头**，后面接原有的合并语义与校验和风险；
- 恢复完成后清空（一次性，避免残留旧摘要）。

解析失败不阻断流程：真正的错误仍由 `runImport` 报出来 —— 预演只是"提前告知"，不是新增一道门。

## 3. 方法论

**"告知"的位置比"告知的内容"更容易出错。**
上一轮我把数字做出来了，却只在工作室那一路显示；主路径的用户仍然看不到。

判据：**新增一个提示/数字时，先列出"用户会经过的所有入口"，逐个确认它出现的位置**
（不是"我改的那个页面有没有"，而是"所有入口有没有"）。
这与 ROUND-30 那条（"同一份数据的多个入口"）是同一类错误 —— 我又犯了一次。
