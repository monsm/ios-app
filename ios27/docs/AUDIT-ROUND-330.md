# AUDIT-ROUND-330 · 第 330 轮：把「为什么玻璃这么少」查清楚

用户原话里有半句一直没被正面回答：**「没改几个液态玻璃效果」**。
本轮把它查成了可核对的事实。

## 1. 全 App 的自定义玻璃面：**1 处**

`git grep VGlassSurface\|glassEffect` 的全部命中：

| 位置 | 是什么 |
|---|---|
| `Design/Components/GlassSurface.swift` | 玻璃的**唯一实现**（不是使用点） |
| `Features/Settings/ToastCenter.swift:79` | **唯一的使用点** —— 顶部 Toast |

也就是说：**这个 App 从头到尾只有一块自定义玻璃（Toast）。**

## 2. 这不是缺陷，是设计契约规定的

`docs/DESIGN-CONTRACT.md` §6「材质（Liquid Glass 的纪律）」：

| 层 | 材质 | 出现处 |
|---|---|---|
| 功能层（浮动控件） | 系统原生玻璃 | Tab bar、导航栏按钮、浮动操作条、sheet 顶栏 |
| 内容层 | **不透明** `plate` / `plateAlt` | 卡片、列表、读数块、刻度盘底 |

硬规则第 1 条：**「内容层永不用 `glassEffect`。玻璃出现在卡片上 = 缺陷。」**

⇒ 所以"没改几个玻璃效果"的正确解释是：**这个设计本来就不允许内容层有玻璃。**
真正能加玻璃的地方只有系统功能层，而功能层的玻璃由**系统控件**提供 ——
你得用 `TabView` / 导航栏 / `.searchable` / sheet，玻璃才会出现；

**自己画一个控件再给它刷 `.glassEffect` 不叫"用原生玻璃"，那叫"给自绘控件贴了一层膜"。**

## 3. 本轮据此核对：系统功能层的玻璃现在齐了吗

| 功能层位置 | 之前 | 现在 |
|---|---|---|
| Tab bar | ✅ 系统 `TabView`（含 `.tabBarMinimizeBehavior`） | 不变 |
| 门页导航栏 | ❌ 整个隐藏 | ✅ 系统大标题 |
| 钥匙页导航栏 | ❌ 整个隐藏 | ✅ 系统大标题 |
| 台账页导航栏 | ❌ 整个隐藏 | ✅ 系统大标题 |
| 设置页导航栏 | ❌ 整个隐藏 | ✅ 系统大标题 + `.searchable` |
| 家页导航栏 | ⚠️ 空标题 | ✅ 系统大标题 |
| 滚动边缘 | 17 页有 / 18 页无 | ✅ 全部 `.soft`（契约 §6 硬规则 5 明文要求） |
| Toast | ✅ 唯一自定义玻璃面 | 不变 |

⇒ **五个 Tab 根页的系统功能层玻璃，现在已经全部到位。**

## 4. 顺带核对的契约条款

| 契约条款 | 实现 |
|---|---|
| §6 硬规则 5：滚动边缘用 `.scrollEdgeEffectStyle(.soft, for: .top)` | ✅ 全部滚动页 |
| §6 硬规则 4：减少透明度 / 增强对比度 → 玻璃退化为不透明 | ✅ `VGlassSurface` 两个都处理了，描边加粗一倍 |
| §6 硬规则 1：内容层不用玻璃 | ✅ 内容层零 `glassEffect` |
| §6 硬规则 2：同屏自定义玻璃 ≤2 | ✅ 最多 1（Toast） |

## 5. 方法论

| 判据 | 出处 |
|---|---|
| **「玻璃少」不一定是没做，可能是设计不允许** —— 先查契约，再查实现 | 本轮 §2 |
| **原生玻璃是系统控件的副产品** —— 想得到它只能改用系统控件，不能给自绘控件刷材质 | 本轮 §2 |
| **给自绘控件刷 `.glassEffect` 是"仿玻璃"，不是"原生玻璃"** | 本轮 §2 |
