# AUDIT-ROUND-268 · 第 268 轮：周起始日偏好一旦接上，周报会和其它「本周」错开一周

> CI：**`2d02f3c` build 全绿**（钥匙串写入反馈编译通过）；`345756d` / `6c20d1c` 排队中。

## 1. 现状

`kf_week_start`（周起始日：跟随系统 / 周一 / 周日 / 周六）目前是【保留未接】—— 无 UI 写入点，
所以 `WeekCal.calendar` 恒等于 `WeekCal.gregorian`。**今天没有缺陷。**

但全仓的周计算分成了两拨：

| 调用点 | 用哪个 | 会应用偏好？ |
|---|---|---|
| `MemberHub.weekKey`（本周轮值） | `WeekCal.calendar` | ✅ |
| `HouseholdRoster`（轮值/值班） | `WeekCal.calendar` | ✅ |
| `RecordSearchParse`（本周/上周） | `WeekCal.calendar` | ✅ |
| **`StatsKit.lastWeekDigest`（周报周界）** | **`WeekCal.gregorian`** | ❌ |

## 2. 一旦接线的后果

用户在设置里把周起始日改成「周日」后：

| 页面 | 周界 |
|---|---|
| 本周轮值 / 本周记录 | 周日起 |
| **周报** | **仍按系统首日（周一）** |

同一周的记录会被劈成两半，而两处都写着「本周」。

## 3. 处置

**不改代码**（改了今天就等于提前接线，而接线还要处理 duty 表迁移，是独立动作）。
在 `WeekCal` 的【保留未接】注释里补一份**调用点清单 + 必须同步改的那一行**：

> 接线动作里必须包含：把 `StatsKit.lastWeekDigest` 的 `WeekCal.gregorian` 改成 `WeekCal.calendar`。

## 4. 方法论

**「两个 accessor 今天等价」是最容易埋雷的状态 —— 因为它们的分歧只在某个开关打开后才显形。**

| 状态 | 该做什么 |
|---|---|
| 已经分叉（行为不同） | 修代码 |
| **今天等价、未来会分叉** | **在开关的接线点写清「还有谁要一起改」** |

判据：**给一个「保留未接」的开关写接线说明时，必须列出所有**绕过**它的同义调用点 ——
因为那些点今天看不出问题，正是接线时最容易漏的。**
