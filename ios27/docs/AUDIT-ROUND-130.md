## 1. 三个数字，三个地方

| 位置 | 写的 |
|---|---|
| `privacy.js` 的输出 | 「**10 类**回归判据」 |
| `ARCHITECTURE.md` 闸门表 | 「判红，**14 条**判据」 |
| `ARCHITECTURE.md` 边界表 | 「第 **13–18** 条…」 |
| `AUDIT-COVERAGE.md` | 「已扩到 **21** 条判据（第 13–21 条）」 |

实际：`privacy.js` 里有 **21 条**编号规则（`// 1)` … `// 21)`，其中 11–21 是新加的）。

## 2. 修法：把两个明确过期的改对

- `ARCHITECTURE` 闸门表：`14 条` → **21 条**；
- `ARCHITECTURE` 边界表：`第 13–18 条` → **第 13–21 条**（因为 19/20/21 同样是"同文件内形状检查"）。

## 3. 试过让闸门自己数 —— 失败，已回退

想法：输出里不写死条数，改成从 `privacy.js` 自己的注释里数 `// N)` 的行。

```js
const ruleCount = (fs.readFileSync(__filename, 'utf8').match(new RegExp('^// [0-9]+\\)', 'gm')) || []).length;
```

跑出来 **11** —— 因为**规则 1–10 是早期写的，没有 `// N)` 编号**，只有 11–21 才有。

按本段原则（**不可靠的判据不做**），**回退**：改成只列覆盖面、不报条数。

```js
console.log('privacy: OK — 剪贴板/备份加密/空壳隔离(读+写)/… —— 全部通过');
```

## 4. 方法论

**"让程序自己数"听起来比"写死一个数字"可靠，但前提是"被数的东西格式统一"。**

| 方案 | 前提 | 本仓满足？ |
|---|---|---|
| 写死数字 | 每次改动都记得同步 | ❌ 已三次忘记 |
| **从注释数** | **所有规则都有统一编号格式** | ❌ 1–10 没有 |
| **不写数字** | — | ✅ 这次选了它 |

第三条不是"逃避"，而是**承认"条数"这个事实不值得维护** ——
它不像闸门数那样由 `workflow.js` 对账，写错也没人发现，不如不写。

判据：**一个"只出现在文档里、没有机器对账"的数字，要么补上对账，要么删掉。**
夹在中间只会不断过期。
