# AUDIT-ROUND-332 · 第 332 轮：god 模式第一步 —— 解码锁端凭证变更日志的权威明细

> 用户原话：「密码和指纹等数据也对不上吧，加入更全面的最深层次 god 模式管理锁一切可以管理的数据」
>
> 本轮先落**地基**：把锁端日志（cmd16）里 type 14/15/20/21 的 diffBody 从"一串没人解的 hex"
> 解成人话，并把它们贯通到缓存 → 模型 → 记录详情。

## 1. 为什么这是 god 模式的第一步

之前"密码和指纹对不上"只能靠**两个间接证据**推断：

| 证据 | 局限 |
|---|---|
| 本机台账 diff（`StoreLedger.ledgerDiff`） | 只记 **App 自己发起**的变更；锁端被别人改的本机看不到 |
| cmd03 的容量/存量计数 | 只有总数（64/64），不知道**哪一条**变了 |

而锁端日志 type 14/15/20/21 是**锁自己记录的凭证变更流水**：

| type | 含义 | diffBody 解码（vendor parseDiffBody 逐字对齐） |
|---|---|---|
| 14 | 同步 PIN | track(4B) + opType(1B) + pin 值(4B) |
| 15 | 同步密码 | track(4B) + 删除别名(2B) + 新增别名(2B) |
| 20 | 添加指纹 | track(4B) + 批次号(4B) + 特征点数(1B) |
| 21 | 删除指纹 | track(4B) + 批次号(4B) + 特征点数(1B) |

**它们是"锁端到底改了什么、被谁改的（track）"的第一手证据** —— 别的 App 删了密码、
别的手机录了指纹，这里都有记录。这正是"对不上"时的裁判。

## 2. 实现（一条贯通链）

```
锁端 cmd16 → StatusParser.parseLogEntry   ← 新增 diffBody 解码（长度严格匹配才解，半条不解）
           → DB.saveLogs → CachedLog.diff ← 新增字段（Codable 缺省 nil，旧缓存免迁移）
           → buildRecs → Rec.diff        ← 新增字段
           → 单锁路径 detail 后缀        ← 记录详情直接可见
```

解码口径逐字对齐 vendor `main.js`：`En.toNormalByteOrder` = 字节反转为 LE→主机序。
长度不匹配（翻页截断的半条）**宁可不解也不给错数**。

## 3. 你贴的日志里就有一条活样本

05:31:47 的 cmd16 回包里有一行以 `05161314e6…` 开头 —— **type=05 是 KLV 键，正文首字节
`16`=0x16=22？不对：body 首字节 `16` = 0x16 = 22 十进制 = "设置安全级别"。**
而 `05131315…` 那行首字节 `13` = 19 = 指纹开门。
**05161314e6** 那行 body = `161314e6640000f096ab1f1100010003000000ffffffff` ——
首字节 0x16=22（设置安全级别）。
**05161314e5** 行 body = `161314e5640000df95ab1f1300010004000000ffffffff` —— 同样 22。
**等等：body 的第二段 `1300010004` 里 13=19？** 这两行实际是**复合条目**，
说明这把锁的固件对 22 号事件带了 track(11000100) 与一段参数 —— 本轮解码器对未识别的
body **原样保留**（`body` 字段不丢），后续对拍 vendor 逐类型再补。

（这段是【推断】，需要真机对拍验证 —— 正好 `ci-shots`/日志可以复核。）

## 4. 明确没做的（god 模式的剩余清单）

| 项 | 为什么没做 |
|---|---|
| 修池入口（`repairPool` 接设置页） | 等 CI 截图确认设置页现状后再动 UI |
| cmd05 换钥历史 / DFU 记录解码 | 日志里出现频率低，价值待证 |
| 锁端 PIN 表**逐枚枚举**（cmd43/44） | vendor 只有容量/存量，无逐枚读协议 —— 解码日志是唯一路径 |
| 日志 body 全类型结构化 | 22 号等复合条目需要真机对拍 |

## 5. 方法论

| 判据 | 出处 |
|---|---|
| **"对不上"要找锁端的原始记录，而不是本机台账** —— 台账只记自己做的，锁端日志记所有人做的 | 本轮 §1 |
| **长度不匹配宁可不解** —— 半条解码出的错数比空白危害大 | 本轮 §2 |
| **god 模式的第一步是"读"，不是"写"** —— 先把锁端能告诉我们的全部解出来，写操作（修池/重签）才有依据 | 本轮 §4 |
