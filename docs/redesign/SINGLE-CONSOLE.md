# 门厅控制台 —— 设计契约

> 单一主界面 `App/UI/HomeConsole.swift`。取代原 B/D/F 三域与三棱柱。
> 本文是后续所有改动的判据：改这里之前先看它是否还成立。

## 一、为什么合并

原设计是"三棱柱 + 三个面"的导航。问题出在**产品与形式不匹配**：

| 原设计 | 现实 |
|---|---|
| 三个面各承载一个域 | 用户只有两个意图：**开门**、**看一眼今天** |
| 三棱柱是导航核心 | 竖屏手机上棱柱占满全宽，看不出是物体（只有 HTML 原型正方形舞台的一半宽度才有物体感）|
| 面切换 = 换域 | 换域不是高频动作，做成主交互成本过高 |

结论：**导航结构要跟着任务频率走**。开门最高频 → 主视觉；数据次之 → 第二层；管理最低 → sheet。

## 二、构图（一屏，纵向节奏 28pt）

```
① 页眉        时间（TimelineView 驱动）+ 连接态胶囊
② 空状态      仅未配对时出现：「还没有门锁」+ 去配对
③ 门的身份    锁名 22pt bold + 一句摘要
③.5 关键状态  低电量 / 未处理告警（有问题才出现，否则整条不占位）
④ 开锁环      220pt，视觉中心，落在拇指舒适区
⑤ 三指标      今日开门 / 常用成员 / 最早开门
⑥ 今天        24 根分时柱 + 时刻刻度
⑦ 成员        横向胶囊（近 30 天口径）
⑧ 管理        5 个瓦片 → ManagerFace sheet
```

## 三、排版（全部语义字号，随 Dynamic Type 缩放）

| 角色 | 字号 | 用途 |
|---|---|---|
| 锁名 | `.title` bold | 页面唯一大标题 |
| 指标数字 | `.title` rounded semibold | 弱视距下先被读到 |
| 正文 | `.subheadline` / `.footnote` | |
| 区块标签 | `.caption2` semibold 大写 + 0.8 字距 | 只做结构 |

**禁用**：固定 `.system(size:)`（不缩放）、10pt 及以下（低于 HIG 11pt 下限）、
`minimumScaleFactor` 缩字（等于拒绝放大）。
图标尺寸是唯一允许写死的地方（设计系统明示）。

## 四、色彩（一色一义）

| 令牌 | 含义 | 用在哪 |
|---|---|---|
| `accent` 铜 | 可操作 / 此刻 | 开锁弧、当前小时、今日高亮 |
| `ok` 绿 | 已连接 / 已开锁 | 状态胶囊、成功弧 |
| `warn` 黄 | 可恢复异常 | 低电量行 |
| `danger` 红 | 失败 / 告警 | 失败弧、告警行 |
| 灰阶 | 一切结构与说明 | 不做彩色装饰 |

## 五、开锁环（按物理对象设计）

| 状态 | 表现 |
|---|---|
| 静息 | 7pt 中性轨道（凹槽内阴影）+ 锁图标 + 「按住开锁」 |
| 按下 | 缩放 0.97、图标 lock→lock.open、140ms 纯缓出、一次触觉 |
| 蓄力 | 铜色角度渐变弧从 12 点顺时针 + 柔光；**1.05s** 充满 |
| 成功 | 弧转绿 + 勾号 + 成功触觉，0.9s 后回静息 |
| 失败 | 弧转红 + 一行人话原因 + 警告触觉，2s 后回静息 |
| 中途松手 | `XMotion.chargeReset` 回零 |
| reduceMotion | 不缩放、不柔光，进度仍可见（功能不降级）|

### 安全约束（最重要）

用 `onLongPressGesture(minimumDuration:)` 而不是 `DragGesture` + 自搓 sleep。
**原因**：手势被系统取消（来电/弹窗/视图移除）时 `onEnded` 不一定触发，
`pressing` 会停在 true，定时器睡完就真的发出一次开锁 —— 用户没按完，门开了。
`onLongPressGesture` 的完成回调由 SwiftUI 保证「按住满时长且未取消」。

另外：切后台 / 视图消失一律 `abortCharge()`。不允许在后台完成开锁。

## 六、数据口径（不许编）

协议日志**没有凭证身份字段**（CAPABILITY §3），所以：

- 「今日开门 N 次」= 真数据 ✅
- 「今天 N 人开过」= **算不出来** ❌ → 改成「今天开过 N 次 · 近 30 天 M 人用过」
- 指标二标签是「常用成员」不是「在家成员」

## 七、刷新分寸

`refreshStatusQuietly()` 会**真的建立 BLE 连接**，不是免费的。

| 场景 | 动作 |
|---|---|
| 开门成功后 | 连门锁拉状态（连接是热的）|
| 下拉刷新 | 连门锁拉状态（用户显式要求）|
| 回前台 | **只重算本地**（不能因切 App 就唤醒硬件）|

## 八、性能

- 当日统计**一次扫描**写进缓存（原来 `hourCounts` 被 4 处调用 = 一次渲染扫 4 遍日志）
- 蓄力动画交给 Core Animation 线性插值（原来 16ms 循环 = 62 次/秒重建视图）

## 九、无障碍

- 开锁环：`.isButton` + label/hint + `.accessibilityAction`（视障用户不必长按）
- 装饰性图标一律 `.accessibilityHidden(true)`
- 自定义 tap 行必须给 traits + value + action（`PrivacyDashboard` 的 5 个安全开关
  原来对 VoiceOver **完全不可操作**）
- 显式 `accessibilityLabel` 会**覆盖** `children: .combine` 的内容，要写全
  （`LocksPage` 因此丢过电量与锁态）
