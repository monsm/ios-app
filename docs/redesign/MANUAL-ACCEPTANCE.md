# 人工验收表 —— 代码验不了的那些

> 这个会话说得最重的一句是：**「闸门全绿」和「能编译」是两个不同的东西。**
> 那「能编译」和「好用」之间还差什么？这份表就是答案。

> 下面每一条，**代码层面都已经自洽**，但都没有任何机器能替你确认。
> 每项都写了「怎么验」和「什么算过」——照着做，别凭感觉。

**读法**：验完一项就把方框改成勾，并在末尾写一句实机观察。
**任何一项不通过，都不要当作「小问题」记事** —— 它意味着我这一路的推断有一处错了，值得回头查。

---

## 一、交互手感（最优先，影响每天）

### A1 · 长按开锁的触发时机

- [ ] **怎么验**：站在门边连续开锁 10 次。3 次故意按得快（0.5 秒松手），3 次按满 1.05 秒，2 次按住后移开手指，2 次正常。
- [ ] **什么算过**：
  - 快按 3 次 **都不开锁**，且界面明确显示「还要按住」（不是静默无反应）
  - 按满 3 次 **都开锁**
  - 移开 2 次 **进度归零**，没有半截卡住
  - 正常 2 次不误触

### A2 · 长按与系统手势冲突

- [ ] **怎么验**：在门厅页面，从屏幕左边缘右滑（返回手势）、从底部上滑（主屏手势），各试 3 次。
- [ ] **什么算过**：系统手势正常，**不会同时触发开锁**。
- **风险**：如果 1.05 秒的长按被系统「轻点唤醒」抢先，会表现为「按住时屏幕亮一下但不开锁」。

### A3 · 分时图点选的小时对不对

- [ ] **怎么验**：先在「事件记录」同步一次日志，确认某小时有记录（比如 14 点 3 次）。回门厅，点分时图**第 14 根柱子**附近。
- [ ] **什么算过**：跳转后顶部显示「只看今天 14:00 – 14:59」，且列表条数与柱高对应。
- **风险**：如果坐标换算偏了（点第 14 根落到 13 或 15），是取整边界问题。

### A4 · 成员卡直达

- [ ] **怎么验**：点门厅「成员」区任意一张卡。
- [ ] **什么算过**：直接打开该成员详情，且**是这个人**（不是列表第一个）。

## 二、协议与设备（只有真机知道）

### B1 · 日志同步到底能不能拉到

- [ ] **怎么验**：「事件记录」→ 菜单 →「从门锁同步日志」。连上锁后等结果。
- [ ] **什么算过**：toast 显示「已同步 N 条（新增 M 条）」，且 **M > 0**。
- **如果不通过**：会弹出「同步详情」，里面有逐页的 start / 返回条数 / surplus。**把那段截图** —— 它能直接指出是分页约定不对、还是协议没对上。
- **未验证的推断**：`start += page.logs.count` 这个分页约定是**我推出来的**，没有协议文档佐证。

### B2 · 队列下发（最长的一条链）

- [ ] **怎么验**：断开蓝牙 → 删除一个凭证 → 走近门锁连上 → 等几秒。
- [ ] **什么算过**：
  1. 连上后 **toast 主动播报**「已向门锁发出 N 项变更」
  2. 回收站页的「等待门锁确认」里那条**消失**
  3. **回锁上用那个凭证试一次 —— 应该已经失效**

### B3 · 明文密钥迁移

- [ ] **怎么验**：如果你有旧版本备份能恢复到本机，恢复一次，然后冷启动 App。
- [ ] **什么算过**：门锁仍能正常开锁（密钥没丢）。
- **风险**：迁移逻辑是「Keychain 里确实有值才抹掉明文」。若首次启动在解锁前，Keychain 写入可能失败 —— 此时**不会抹明文**（这是对的），但也就**没迁移成功**。冷启动两次后再查一次。

### B4 · 配对中下滑关闭

- [ ] **怎么验**：进入配对流程，在「配对中」阶段**从屏幕顶部下拉**（试图关掉弹层）。
- [ ] **什么算过**：**拉不动**（弹层拒绝下滑关闭）。
- **风险**：`interactiveDismissDisabled` 在少数情况下会被父级手势抢先，这个没验过。

## 三、视觉（我看不到渲染结果，全部未验）

### C1 · 门厅的间距层级

- [ ] **怎么验**：打开门厅，从上往下看一遍。**别分析，就感觉**。
- [ ] **什么算过**：
  - 能一眼看出「身份 + 开锁环」是一组、「三指标 + 分时 + 成员」是另一组
  - 两组之间的空隙明显大于组内
- **改了什么**：原来 8 个区块一律 32pt 等距，改成簇内 16 / 簇间 24。

### C2 · 设置列表的行

- [ ] **怎么验**：进「管理」面板，逐组看。
- [ ] **什么算过**：每行副标题**完整显示，没有被切掉**（我把 7 处过长的副标题收短到 16 字内）。

### C3 · 浅色模式

- [ ] **怎么验**：外观工作室切到浅色，看三级文字（时间戳、单位、说明）。
- [ ] **什么算过**：小字**看得清**，不用凑近。
- **改了什么**：浅色 textTertiary 从 0x72727C 调到 0x666670（对比度 3.97 → 4.73）。

### C4 · 大字号（动态字体）

- [ ] **怎么验**：系统设置 → 显示与亮度 → 文字大小 → 调到最大。回 App 看门厅。
- [ ] **什么算过**：不截断、不重叠、开锁环仍可点。

### C5 · 管理面板的 5 个瓦片

- [ ] **怎么验**：看门厅底部那排「钥匙 / 设备 / 成员 / 安全 / 数据与外观」。
- [ ] **什么算过**：「数据与外观」这 5 个字**没有被压成两行或缩得看不见**（缩放下限已提到 0.9）。

## 四、安全流程

### D1 · 二次开锁闸（30 秒内连开两次）

- [ ] **怎么验**：设好应用锁 → 开锁成功 → **30 秒内再按一次**开锁环。
- [ ] **什么算过**：弹出「再次开锁需要验证」的密码输入框。输对放行；输错 toast「口令不对，这次开锁已取消」。
- **这条修之前的行为是**：什么都不发生（showGate 只写不读，静默堵死开锁）。

### D2 · 删除凭证的三件事

- [ ] **怎么验**：删除一个凭证，看确认框文字。
- [ ] **什么算过**：同时说清 **① 本机会删 ② 锁端会撤销（断网不丢）③ 本机留在回收站 30 天可恢复**。

### D3 · 回收站恢复

- [ ] **怎么验**：安全 → 回收站 → 对一条点「恢复」。
- [ ] **什么算过**：条目回到钥匙列表原位，且 toast 如实说明结果（包括「锁端已删、指纹无法远程补录」这类话）。

---

## 五、如果你只有 10 分钟

按这个顺序，能覆盖风险最高的部分：

1. **A1 长按开锁**（每天用，错了最难受）
2. **B2 队列下发**（最长的一条链，之前最后一环是静默的）
3. **D1 二次开锁闸**（修之前是静默堵死）
4. **C1 门厅间距**（最常看的界面）

---

## 六、验完之后

- **全部通过** → 这个 App 在「能用」这个层面是成立的；「好看」仍需你自己判断
- **有不通过** → 把那一项的条件和实机现象记下来。那意味着我在那一处的**推断错了** —— 这比多接一个功能重要得多。

> 这份表的价值不在于它列了多少项，而在于它**承认了哪些事我没做到**。
