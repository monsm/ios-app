## 有意偏离（已论证）

| 项 | HTML | App | 理由 |
|---|---|---|---|
| 扫码界面 | 自绘取景框 + 权限引导 | 系统扫码器 | 系统控件优先；不需要相机权限页面 |
| 换绑确认 | 自定义全屏危险卡（三按钮）| 系统 AlertDialog（两按钮）| 系统对话框更符合平台规范；「只解绑不换」是新业务逻辑，不应由我臆造 |
| 成功态 | 全屏点任意处关闭 | 主屏内联回执卡 | 成功是主屏的一个状态，不是独立屏 |

## 附：iOS ↔ Android 主屏功能级对照（第 69 轮）

| 功能 | iOS | Android | 判定 |
|---|---|---|---|
| 开锁交互 | 按住 1.05s 蓄力环 | 点击 UnlockDial | ✓ **各自忠实于各自原型**（iOS 原型=按住环，Android 原型=轻点胶囊）|
| 信号语言 | 胶囊 dBm + RingInfo | KfChip dBm + SignalMetric 状态词 | ✓ 同构 |
| 自动开锁规则 | AutoOpenKit 阈值 | AutoOpenKit 阈值 | ✓ 逐值相同 |
| 成功态 | 环转绿 + status | 环转绿 + 开锁回执卡 | ✓ Android 更丰富 |
| 设置入口 | 齿轮 → sheet | 齿轮 → 二级菜单 | ✓ 同构 |
| 后台防窥 | scenePhase 糊屏 | foreground 停扫 | ✓ 各自平台惯用 |

**结论：双端"同一功能、不同表达"的差异全部源自原型层的有意设计，实现零偏差。**
