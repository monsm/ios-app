# 媒体资源盘点与裁定（2026-10-23）

> 用户要求：「App 需要的一切媒体资源都用 3js 做精美再放到 app」。
> 先按规范 §6.4 盘了一遍**这个 App 到底需要什么图**，再决定做什么。

## 一、规范 §6.4 的铁律（这一节的验收高于任何几何条款）

| # | 铁律 |
|---|---|
| **I1** | **禁止用 CSS 渐变 / 纯色块冒充图像素材** |
| **I2** | 设备样机必须是**真实设备渲染图**（PNG 带 alpha，@3x）|
| **I3** | **没有素材时用单色占位，不用假渐变** —— 单色显得「未完成」，假渐变显得「廉价」，前者诚实 |

§6.4.5 自检第一条：**页面上不得有任何用渐变冒充的照片/渲染图**。

## 二、本 App 现有的媒体

| 类型 | 现状 | 结论 |
|---|---|---|
| App 图标 | **12 套真实 PNG**（1024×1024，Bell/Guard/Heart/Home/…）| 已有，且是生成的真图 ✓ |
| 界面内图片 | `Image("…")` 引用 **0 处** —— 全部走 SF Symbols | 这是 §6.4.4 的**首选**做法 ✓ |
| 图表 | 代码绘制 | §6.4.2 明确「唯一允许用代码画的图像」✓ |
| 空态插图 | SF Symbols 单色 + 无底 | §6.4.4 首选 ✓ |

## 三、这个 App **不需要**什么图（有规范依据，不是我偷懒）

| 参考图里的东西 | 为什么本 App 不适用 |
|---|---|
| 设备样机（iPhone 渲染图）| 图 1/2/6 是**展示壳**（Face Gallery / Activity Details）—— 用样机展示「App 长什么样」。`DEVIATIONS.md §5` 早已裁定本 App 不是展示壳，`shellCard` 已删。硬塞一个 iPhone 样机进来，是用别人的骨架撑自己的内容。|
| 双列图文卡（Watch 表盘缩略图）| 图 6 的 `Health and Fitness` / `Photos` 卡里是**产品实拍渲染**。本 App 没有任何「可浏览的产品图库」——它管的是真实门锁，不是卖表盘。|
| 主视觉 3D 渲染 | 图 5 那种渐变大环是**代码画的**（规范 §7.8 给了完整参数），不是 3D 素材。|

## 四、真正值得做、且我能做的

**「这台锁」页的锁具形象**（截图 14 的靛蓝圆盘 + 锁图标）。

当前是 `Circle().fill(LinearGradient(...))` + SF Symbol —— 这正是 §6.4.4 允许的
「单色占位」，但一个管真实硬件的 App，锁具形象是它唯一够得上「主视觉媒体」的槽位。

按 §6.4.3 的规格做一张：

| 项 | 要求 |
|---|---|
| 格式 | PNG 带 alpha，高 ≥330px @3x |
| 背景 | **透明**，不得白底 |
| 光源 | 单一主光源，左上方 |
| 对比 | 主体亮度高于 `#1C1C1E` ≥3 档 |
| 阴影 | 自带柔和落地影 `rgba(0,0,0,0.45)`，模糊 ≥12px |
| 文字 | **不得含文字** |
| 色相 | 服从 §3.4 语义色 |

**做法**：three.js 在无头 Edge 里渲染 → 导出透明底 PNG。
本机有 Edge 157 + Node 25，`tools/prism-render.js` 已有 PNG 编码器可复用。

## 五、我不会做的

**不会**为了「看起来有图」而做一批假渐变块塞进页面。
规范 §6.4 那一整节存在的理由就是防这个 —— 而它写明「素材假了只能重做」。
