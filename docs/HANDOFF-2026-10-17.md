## 3. FaceID 那个 bug（已修，但还没出包）

- 根因：`AutoOpen.SystemFaceService.silentRefresh()` 调 `LAContext.evaluatePolicy`。**iOS 没有静默生物识别**，调了就弹系统模态窗；而 `onForeground` 每次进前台都调它（标准档）。
- 后果：切回 App / BLE 重连 / 点通知都弹一次；系统窗模态期间吃掉开锁圆盘的按压 → "按了没反应"。
- 修法：`silentRefresh()` 改空实现。标准档不再主动验证，只沿用 `lastFace ≤60s` 窗口。
- 代价：标准档下「靠近自动开锁」在无近期面容记录时不触发；要自动开门请选**严格档**（明确弹一次）。

## 5. Swift 6 迁移：已完成（2026-10-17）

### 5.0 结果

| 指标 | 迁移前 | 迁移后 |
|---|---|---|
| `SWIFT_VERSION` | 5.0 + strict complete | **6.0** |
| 编译错误 | 1（`BatteryCare` 的 `if let` 解非可选元组） | 0 |
| 并发红线告警 | 120 条 | **0** |
| 脏修复残留 | 0（上一轮已回退） | **0**（本轮一处没加） |

修法分布（全部是"让编译器认可"，没有一处是"让编译器闭嘴"）：

| 类别 | 做法 | 落点 |
|---|---|---|
| UIKit 读点 | 整族下沉 `@MainActor`（`AXFlags` / `AXTools` / `DS.Haptics` / `SeasonIcon` / `QuickActions` / `quickDestination` / `VK.card`） | 视图与设计令牌本来就在主 actor，代价为零 |
| 渲染期回调 | `ShapeStyle.resolve` 的判据全部改走 `EnvironmentValues`（降透明 / 增强对比 / 反转） | 不再读全局旗标，同帧所有令牌看到同一份环境 |
| 跨线程共享状态 | `Locked<Value>` 持有（`Speech.synth`、`SpotlightKit.pending`） | 取旧值 + 写新值在**同一个临界区**，顺带修掉并发改名的漏刷 |
| 系统回调边界 | 回调参数标 `@MainActor`（本身即 Sendable）+ `Task { @MainActor in }` 真跳；`@preconcurrency import` 只用在 CoreSpotlight / UserNotifications 两个事实上线程安全的框架 | 零 `assumeIsolated` |
| 界面状态类 | `ExportProgress` / `SecTickCenter` 整类 `@MainActor`；三处 `MainActor.run` 删除（Task 已继承隔离） | 生成体仍 `Task.detached` |

顺带修掉的一个**真 bug**：`UNDelegate` 的 `didReceive` 写成了 `completionHandler:`，协议要求是 `withCompletionHandler:` ——
编译器只给 "nearly matches" 告警，运行时这一支**永远不被调用**（通知点按等于没接）。本轮改成正确标签。

### 5.1 原始迁移路径（留档：这是 Apple 官方路径，不要再绕）

1. `project.yml` 已经是 `SWIFT_VERSION: "5.0"` + `SWIFT_STRICT_CONCURRENCY: complete`
   → 每处跨隔离访问是**告警**，工程照常绿。
2. 每次推完，把告警清单抓下来：
   ```bash
   xcodebuild -project OfflineLock.xcodeproj -scheme OfflineLock \
     -destination 'generic/platform=iOS Simulator' build 2>&1 \
     | grep -E "warning: .*(actor|Sendable|isolation|concurren)" | sort -u > conc.txt
   ```
   （CI 里对应 `build/test.log`，可直接从 Actions 日志捞。）
3. 按告警逐条修，**四类修法，优先级从高到低**：
   | 告警类型 | 原生修法 | 备注 |
   |---|---|---|
   | `call to main actor-isolated X from nonisolated context` | 调用方标 `@MainActor`（async 调用点自动跳主），或把 X 下沉成真纯函数后标 `nonisolated` | **优先改调用方**，别动被调方 |
   | `non-Sendable type X crossing isolation boundary` | 让 X 变成 `Sendable`（值类型/不可变/ final class + 不可变状态） | 别用 `@unchecked Sendable` 糊 |
   | `static property is not concurrency-safe` | 共享可变状态上 **`OSAllocatedLock`**（iOS 16+）或 `NSLock`；只读缓存改 `let` | **绝对不要** `nonisolated(unsafe)` |
   | `data race / mutable global` | 收进某个 actor，或改成实例状态 | |
4. 告警归零、CI 连续两轮干净之后，**最后一步**才把 `SWIFT_VERSION` 改成 `"6.0"`，并把 `SWIFT_STRICT_CONCURRENCY` 那一行删掉（Swift 6 下它恒为 complete，留着是噪音）。

### 5.2 红线（今天已经踩过，写在这里防止再犯）

- ❌ 不要批量加 `nonisolated(unsafe)` 压错误——那是把检查关掉，不是修好。
- ❌ 不要用 `MainActor.assumeIsolated` 赌"渲染时一定在主线程"——赌错就是 trap，而且它是**运行时断言**，有成本。
- ❌ 不要 `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` 一刀切——它会把每一层非 UI 类型都拉上主线程，然后你就要给几十个类型逐个标 `nonisolated`，一层层暴露，永远修不完（今天实测 204 → 321 → …）。
- ✅ 纯函数 `nonisolated` 是零成本的，可以放心标。
- ✅ 共享状态上锁是正路；`OSAllocatedLock` 比 `NSLock` 更 Swift-native，且自带 `withLock` 不会忘了 unlock。

### 5.3 已知的硬骨头（提前有个预期）

- `AppIntents.swift`：6 个 `AppIntent.perform()` 是非隔离协议要求，方法体要拆成"在主 actor 上取数" + 回值。
- `LiveUnlockActivity.swift`：`ActivityAttributes` 一致性要求 Sendable。
- `ExportCenter.swift` / `BackupStudioKit.swift`：后台导出链路，本来就该在后台 actor 上跑，别硬拉回主线程（那是真的会卡 UI）。
- `BLEService.swift`：CoreBluetooth 回调在 `.main` 队列，已是事实主线程；把类本身的主隔离写明即可，不要 unsafe。

## 7. CI / 工程的坑（都踩过了）

- **GitHub Actions 镜像**：稳定通道 `macos-latest` 最高只到 **iOS 26.5**；要 27.x 必须用预览镜像 `xcode-27`（无 SLA，3C/7G，跑得慢）。回退就改回 `macos-latest`。
- **预览镜像要显式选 Xcode**：镜像里 27.0/27.1/27.2 并存，默认未必是新的。工作流里有一步 `ls /Applications/Xcode*.app | sort | tail -1` + `xcode-select`。注意 **BSD `sort` 没有 `-V`**，字典序对 27.0/27.1/27.2 恰好正确。
- **每次改构建配置类的东西，CI 会先在编译前红**：`destmap`（目的地台账，改了视图要 `node tools/destmap.js --emit`）、`uicoverage`（自绘容器预算，只能下调，改 `fixtures/uicoverage/budget.json`）、`changelogcheck`、`sheetcover`。本地先跑：`for f in tools/golden.js tools/logicparity.js tools/cmdsshadow.js tools/parseshadow.js tools/destmap.js tools/uicoverage.js; do node $f >/dev/null 2>&1 || echo "RED $f"; done`
- **多个提交连着推会排队**：Preview 镜像并发低，每次约 6–9 分钟。要快就先合再推，别一个 commit 一推。

## 8. 三条设计口径（别改错）

1. **协议时间基准 = 本地 2010-01-01**（APK `An.getDate` 两侧同时区相减）。东八区同一时刻的协议秒 = UTC 基准 + 28800。写死的永久窗口：vf = 0，vt = **3_408_134_400**。
2. **13 录指纹**：Java `post()` 只有一个 8s 接收计时器，收到任一帧即 cancel 且**不重启**。所以 App 侧只有首帧 8s 窗口 + 150s 整体兜底，**没有按压间隔计时器**（今天删掉了自创的 16s，它是"按 3 下就不动"的根因）。
3. **写类命令超时/写失败不重发**（指令可能已生效，避免双开门）。这是与 APK 的有意分歧。
