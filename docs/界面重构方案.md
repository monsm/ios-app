## 三、重构目标 IA（方案 B：以「锁」为对象）

### 核心原则

1. **一个对象的所有能力，在它自己的详情页里** —— 锁的能力不散在 App 设置里
2. **设置页只放全局** —— 不属于任何一把锁的东西
3. **任何功能 ≤ 2 层可达** —— Tab → 页面 → （可选）sheet
4. **文件按域拆，单文件 ≤ 600 行**

### 新结构

```
Tab 1「设备」
├─ Hero 卡（锁名/状态/电量/固件/锁钟/钥匙/信号）
│     └─ 点卡片 → 【锁详情】★新建
├─ 开锁圆盘（176pt）
├─ 快捷操作格（用户可配：添加密码 / 临时码 / 校时 / 添加指纹 / 工坊 / 备份 …）
```

## 九、补充问题：网关入口不在「添加设备」里

### 事实

- `AddDeviceView`（`Sheets.swift:13`）的 `scanView` 只扫**门锁**：文案是「正在搜索门锁…」（`:101`），扫描参数走门锁 pid 白名单。
- 网关配网 `GatewayView`（`Sheets.swift:1037`）的唯一可见入口是 **设置 → 工具 → 智能网关**（`SettingsView.swift:639`，`showGateway = true`）。
- 而 APK 的入口是 **添加设备 → 设备类型列表（`page-devicetypelist`）→ 选「网关」**。

### 判断

「加一台新设备」这个任务下，用户会去「+」；但那里只能加锁。网关被放进了「工具」，语义错位。

### 方案补充

把设备页右上角「+」改成 `Menu`：

```
+ ─┬─ 添加门锁   → AddDeviceView
   └─ 添加网关   → GatewayView
```

同时 `SettingsView` 的工具段删掉「智能网关」一行（避免双入口）。

### 这一条与主方案的耦合

它不属于「锁详情」重构，是**独立的小修**。可以单独做，不必等主方案。

## 十、合并冲突：三块内容不是简单相加

「锁详情」要合并 `DeviceInfoView` + `LockProfileView` + 设置页 `lockSection`。以下是实测到的**重叠与冲突**，实施时必须先定口径。

### 10.1 电池档案：两处都能编辑，交互方式不同

| 位置 | 实现 | 交互 |
|---|---|---|
| `DeviceInfoView.swift`（在本文件 600-625） | `batterySection` | 两行 `Button` → `UIAlertController` 弹窗编辑（`editBatteryModel` / `editBatteryDate`） |
| `LockProfileView`（964-970） | `Section("电池档案")` | 内联 `TextField` + `VariantToggle` + `DatePicker` |

**冲突**：同一份数据（`LockArchive.meta().batteryModel` / `batteryDate`）两套编辑器。
**建议**：合并后**只保留内联版**（Form 里的内联编辑更符合 iOS 习惯，也少两次弹窗），删掉 `DeviceInfoView` 的两个弹窗方法（合并后会变成死代码）。

### 10.2 安全模式：一处显示、一处切换

| 位置 | 内容 |
|---|---|
| `DeviceInfoView` 583 行 | `LabeledRow("安全模式", modeText)` —— **只读显示** |
| 设置页 `lockSection:313` | `NavigationLink("安全模式 (A/B 双验)") { SafemodeIntroView() }` —— **可切换** |

**合并后**：状态区显示当前模式 + 同一行给「切换」按钮（进 `SafemodeIntroView`）。不要分成两个 Section。

### 10.3 锁钟：一处显示、一处校准

| 位置 | 内容 |
|---|---|
| `DeviceInfoView` 541 行 | `LabeledRow("锁钟偏差", driftText)` |
| 设置页 `lockSection:335` | `NavigationLink("校准门锁时间") { SyncTimeView() }` |

**合并后**：状态区显示偏差 + 同一行「校准」按钮。

### 10.4 型号显示口径不一致

| 位置 | 取哪个字段 |
|---|---|
| `DeviceInfoView:529` | `PidMap.productName(kc.pid)` → 「智能门锁 V1 Pro」 |
| `LockProfileView` 无型号显示 | — |
| 设备页 Hero 卡 | `LockArchive.subtitle(kc)` → 场所副标题或型号 |

**合并后**：统一用 `PidMap.productName`（带完整产品名），不要用 `modelName`（短代号）。

### 10.5 合并后估算体量

| 来源 | 行数 | 合并后保留 |
|---|---|---|
| `DeviceInfoView` | 300 | ~200（去掉弹窗电池编辑、去掉重复 footer） |
| `LockProfileView` | 232 | ~180（保留身份/符号/色标/电池/PIN/默认锁/保存） |
| 设置页 `lockSection` | 95 | ~60（只保留能力入口） |
| **合计** | **627** | **~440 行 + 新导航壳** |

**结论**：`LockDetailView` 约 **450-500 行**，仍在「单文件 ≤600」目标内。但它是**最长的一页**，实施时要按区块拆成 `@ViewBuilder` 私有属性。
