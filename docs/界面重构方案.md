## 三、重构目标 IA（方案 B：以「锁」为对象）

### 核心原则

1. **一个对象的所有能力，在它自己的详情页里** —— 锁的能力不散在 App 设置里
2. **设置页只放全局** —— 不属于任何一把锁的东西
3. **任何功能 ≤ 2 层可达** —— Tab → 页面 → （可选）sheet
4. **文件按域拆，单文件 ≤ 600 行**

### 新结构

```
Tab 1「设备」
├─ Hero 卡（锁名/状态/电量/固件/锁钟/钥匙/信号）
│     └─ 点卡片 → 【锁详情】★新建
├─ 开锁圆盘（176pt）
├─ 快捷操作格（用户可配：添加密码 / 临时码 / 校时 / 添加指纹 / 工坊 / 备份 …）
├─ 最近开门（可点成员 → 记录页按 TA 过滤）
└─ 底部：模块顺序编辑

【锁详情】★新建（= 现 DeviceInfoView + LockProfileView + 设置页锁段 三者合并）
├─ 身份（可编辑）：昵称 / 场所 / 符号 / 色标 / 分组 / 备注

├─ 锁能力（按 pid 裁剪）：
│     ├─ 布防        ← canDefend

```

## 八、修正：设置页的真实结构与完整落点（审核前自查发现的方案错误）

**上面第二节写的「17 个 Section」是错的。** 那个数字来自 `SettingsGroups.swift:3` 的注释「设置页把 17 个 Section、约 37 个一级入口平铺在一屏」—— 但它描述的是**加分组之前**的历史状态。实测现在是 **10 个 Section 变量**（每个变量内部可能再套 `Section {}`）。
下面是逐变量清单与完整落点 —— 这份表才是实施依据。

|---|---|---|---|---|

| 2 | `unlockSection` | 56 | 按住确认开锁 / 误触围栏 / 双击直开 / 失败自动重试 | **设置 → 开锁**（全局交互，保留） |

### 因此「设置 5 组」实际是 6 组

```
设置
├─ 安全：应用锁 / 通知权限 / 只读试验
├─ 开锁：按住确认 / 误触围栏 / 双击直开 / 失败重试 / 走近自动开门
├─ 数据：备份与恢复
├─ 外观：主题 / 字号 / 动效 / 长辈模式 / 大格模式 / 快捷格 / 时间显示 / 主控卡显示项
├─ 家人与钥匙：成员中心 / 手机钥匙 / 蓝牙钥匙串 / 成员别名
└─ 关于：版本 / 构建 / 遥测 / 协议测试
```

**智能网关**单独说明：它是「与这把锁配对的网关」，语义上属于锁的邻居设备。
但它也可能有多个网关（`PidMap.gws` 三个型号），所以更准确的做法是放在**锁详情 → 关联设备**区，

## 十一、搜索索引：迁移会让 5 条搜不到（方案必须解决）

### 事实

设置页的 `SearchHit` 一共 **14 条**（`SettingsView.swift:232-258`）。按 `anchor` 分：

| anchor | 条数 | 具体条目 |
|---|---|---|
| `.lock` | **5** | 锁档案 / 静音模式 / 校准门锁时间 / 布防 / 固件升级 |
| `.family` | 1 | 手机钥匙 |
| `.tools` | 1 | 只读试验模式 |
| `.unlock` | 1 | 开锁偏好 |
| `.autoOpen` | 1 | 靠近自动开锁 |
| `.applock` | 1 | 本机数据保护 |
| `.appearance` | 1 | 外观 |
| 无 anchor（直接开 sheet） | 3 | 成员管理 / 智能网关 / 备份与恢复 |

### 问题

方案要把 `anchor: .lock` 那 5 条对应的 Section 全部迁到「锁详情」（设备 Tab）。
但设置页的搜索框是**唯一的全局搜索入口**。迁走后：

> 用户在设置页搜「布防」→ **搜不到**。
> 而设置页现在没有任何提示「布防在设备页」。

### 三个解法

| # | 解法 | 改动 | 风险 |
|---|---|---|---|
| A | `SearchHit` 增加「跨 Tab 目标」：这 5 条保留，点中后 `requestRoute(.device)` + 打开锁详情并滚到对应行 | 中 | 需要 `pendingLockDetailAnchor` 这类字段；要处理"设备页还没选锁" |
| B | 把设置页搜索升级为**全局搜索**：搜到任何页面（含锁详情、凭证工坊、记录） | 大 | 等于重做搜索，超出本方案范围 |
| C | 这 5 条从设置搜索删掉，接受"搜不到" | 小 | **用户会认为功能丢了** —— 不可接受 |

### 推荐：A（最小可行）

```swift
// SearchHit 增加一个可选的目标路由
struct SearchHit {
    let id: String
    let title: String
    let icon: String
    var anchor: SettingsAnchor? = nil
    var targetRoute: Route? = nil        // 新增：跨 Tab
    var targetSection: String? = nil     // 新增：锁详情里滚到哪一行
    var action: (() -> Void)? = nil
}
```

这 5 条改成 `targetRoute: .device, targetSection: "defend" | "mute" | ...`。
`selectSearchHit` 里：有 `targetRoute` 就 `requestRoute(targetRoute)` + 写 `app.pendingLockSection = targetSection`；
`DeviceHomeView.onAppear` 消费 `pendingLockSection` 并打开锁详情 + `ScrollViewReader.scrollTo`。

**这条不做，方案不能实施** —— 会直接制造"搜索能搜到但点不进去"或"搜不到"两类问题之一。

`FpStudio` 的归属预选机制是 `app.pendingFpOwner`：

**建议 A**：既然 `FpStudio(prefillOwner:)` 已经支持，建档完成后直接传进去就行，用户少一次往返。
