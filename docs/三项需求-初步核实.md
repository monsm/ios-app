## 一、协议命令 —— 零缺口（用对的源证明）

### APK 两张命令表

| 表 | 位置 | 命令数 |
|---|---|---|
| `0x87` 明文帧 | `main.js` @356976 | **32 条** |
| `0x88` 包络帧 | `main.js` @368416 | **20 条**（32 条的真子集） |

13 条只能走明文：`01` `02` `05` `12` `23` + 网关 `30/31/32/35/38` + ekey `41/43/44`

### iOS 30 条，帧类型零不符

逐条核对「命令字节 + 帧构造器」→ **不符 0**。

`buildFrame(header: 8)` = 0x87 明文；`wrapFrame(...)` = 0x88 包络。

### 载荷逐字段对齐

| 命令 | APK | iOS | 一致 |
|---|---|---|---|
| `0x02` | 换钥回包 KLV#02 回显比对 | `LockService.swift:930` | ✓ |
| `0x03` 回包 KLV#31 | `parseKlv` → `verFirmwarePri = p2.p1.p0` | `StatusParser.swift:92-98` | ✓ |
| `0x41` | `Eu`：01=MAC反序6B / 02=type / 03=pid / 04=ekey | `cmd41WriteEkey` 同样 4 KLV | ✓ |
| `0x44` | `Ru(mac)`，空=查全部 | `cmd44GetEkeyInfo(String?)` | ✓ |
| 帧头 | `getBytes()` = dt + verReserve + len反序 + cmd + ssToken + "000000" + KLV | `buildFrame` 相同 | ✓ |

`0x0C` / `0x0D` 是**死命令**（APK 里 `.SYNCPWDFREEZEPOLICY` / `.SETZOTPPERIOD` 引用数 0，Java 层也没有）。
iOS 把它们列进 `writeCmdsBlocked` 是正确处理。

## 四、架构取舍（不是缺口，但要让用户知道）

**原版 APK 是云端 App，iOS 是纯离线 App。**

APK 有 12 个云端接口：
```
getDeviceMsg / SEARCH_ZK_ACCOUNT / getDeviceFirmwareProfile / getDeviceSetting
setDeviceSetting / removeDevice / UPDATE_DEVICE_MEMBER_LOCK_KEY
RETRIEVE_DEVICE_MEMBER_INFO / GET_DEVICE_SETTING / SET_DEVICE_SETTING
retrieveDeviceInfo / getDeviceState
```

依赖云端而 iOS 天然做不到的：手机号登录、短信验证码、消息推送、按手机号搜用户加成员、
服务端固件版本检查、清空密码后同步服务端、头像上传。
