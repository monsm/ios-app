## 二、最终结论

**「界面重构」这件事，基于现有证据，不成立。**

三条硬事实：

1. **单锁是基线**（`Store.swift:120-122`「vendor 单锁，用不上」）—— 设备页本身就是锁详情，不存在「第二个对象页」的需求。
2. **唯一有用户证据的问题（布防找不到）已被 M2 解决** —— 设备页圆盘下方一行、1 次点击、带状态摘要。
3. **其余 6 项锁能力（防尾随/安全模式/静音/固件/清空密码）+ 校准，没有任何用户证据** —— 包括搜索失败记录、使用数据、用户反馈。

**在没有证据的情况下，任何「重构」都是把开发者审美包装成用户价值。**

## 三、最终方案（可执行部分）

### 3.1 已交付：M2（22 行，commit `630e4de` + `9ca3462`）

设备页开锁圆盘下方「布防」行：

- 只在 `PidMap.canDefend(pid)` 时出现（KX / V1_Pro / 未知 pid）
- 行内 `DefendKit.summary(DB.defend(kc.mac))` 显示当前状态（撤防 / 布防中 / 时段）
- 1 次点击进 `DefendView`
- 与设置页那条**并存**（不删，老用户路径不打断）

**V1 Pro（pid 7858）会看到。**

### 3.2 本次新增：`QuickPool` 加 3 条页面型快捷格（**6 行**）

```swift
// App/Core/QuickPool.swift

// ① all 数组（第 37 行 backup 之后）加 3 条
QuickAction(id: "tailgate", icon: "figure.walk.arrival",        label: "防尾随"),
QuickAction(id: "safemode", icon: "lock.rotation",              label: "安全模式"),
QuickAction(id: "dfu",      icon: "arrow.up.circle",            label: "固件升级"),

// ② quickDestination（第 142 行 backup 之后）加 3 个 case
case "tailgate": TailgateView()
case "safemode": SafemodeIntroView()
case "dfu":      DFUView()
```

**关键约束**：

- **`defaultIds` 不改**（`["addPwd","otp","syncTime","addFp","studio"]`）—— 默认界面零变化
- 用户要自己到「设置 → 外观 → 快捷格」勾选
- `TailgateView` / `SafemodeIntroView` / `DFUView` 都是**既有页面、既有 `Destination`**，不新增任何东西
- 能力门禁：`QuickPool` 不判 `canDefend/canTailgate/canDeviceUpgrade` —— 用户勾了但型号不支持时，走各自页面里的门禁（`DefendService.allowed` / `canDeviceUpgrade` 已在各页内判）

**这 6 行给的是「可选能力」，不是「默认界面变化」。**

### 3.3 为什么是 6 行，不是 35-75 行

| v2 想做的 | 最终方案怎么做 |
|---|---|
| `DeviceInfoView` 加 7 项能力 | ❌ 不做（语义混乱 + 要滚 16 行 + 自动写锁钟） |
| Hero 卡齿轮 | ❌ 不做（`.combine` 会吞 + 挤压锁名） |
| 设置页 7 项 → 1 行 | ❌ 不做（设置页 2 屏 → 3 屏，是倒退） |
| `SearchHit` 4 条改 `go` | ❌ 不做（打开页面顶部比滚到锁段更远） |
| **快捷格加 3 条** | ✅ **做**（6 行，零默认变化，复用既有页面） |

## 四、明确不做的事（附理由）

| 不做 | 理由（审核证据） |
|---|---|
| 新建 `LockDetailView` | 单锁基线（`Store.swift:120-122`）；设备页就是锁详情 |
| 改 `DeviceInfoView` | 它是「只读信息名片」；混入设置撞 `modality.md`；`reload()` 进页会自动写锁钟（`Sheets.swift:725-736`） |
| Hero 卡加任何按钮 | `.accessibilityElement(children: .combine)`（`DeviceHomeView:449`）会吞掉；右侧 `LinkPill` 会挤锁名（`:342-345` 历史 bug） |
| 改 `SettingsGroup` | 现有 5 个 case + 「全部」= 6 chip 已上线（2026-10-14）；`SettingsGroups.swift:18-23` |
| 改 `Route` | 只有 4 个 Tab 级成员；加非 Tab case 会让 `tabIndex=-1` → `tabSelection=-1` |
| 拆 6 个巨型文件 | 10,573 行；`private` 边界（`ProximityRemask` / `private extension Double` / `BattSpark`）；无 UI 测试兜底；**应作为独立技术债，与本需求解耦** |
| 删设置页 7 项 | 会让设置页用户从 2 屏变 3 屏 |
| 协议测试提到关于页可见 | HIG 无开发者工具页先例；仍是彩蛋是正确的 |
| 网关塞进锁详情 | `Gateway` 无宿主锁 MAC（`Store.swift:293-306`），`kf_gateways` 全局；`Sheets.swift:1067` 明写「无需和门锁配对」 |

## 五、如果将来要再做（需先有证据）

### 证据门槛

连续 2 周记录以下之一：

- 用户在设置页搜索「静音 / 防尾随 / 安全模式 / 固件 / 清空密码」的**失败次数**（现在 `SearchHit` 里「安全模式」「防尾随」「清空密码」根本没有索引，搜不到）
- 至少 3 条用户反馈明确说「找不到 XX」

### 有证据后的正确做法（不是 v2）

**独立 `LockSettingsView`**（约 80-120 行）：

- `Form`/`List`，**只放 7 行能力**，不承载型号/固件/电量/身份
- 不调用 `DeviceInfoView.reload()` —— 打开页面不自动连接、不写锁钟
- 入口：设置页 `lockSection` 一行 + 设备页工具栏齿轮（**不是 Hero 卡内**）
- 静音/清空的业务逻辑抽成共享方法，不复制三套状态

**当前不做。**
