# iOS 界面重构方案 v2（锁设置 sheet）

生成：2026-10-29
定位：**替代 v1（10,573 行大重构，已被三份子代理审核打回）**

---

## 一、为什么有 v2

v1 的教训（三份子代理审核的共同结论）：

| 问题 | 事实 |
|---|---|
| 单锁基线 | `Store.swift:120-122`「vendor 单锁，用不上」→ 设备页本身就是锁详情，再建 `LockDetailView` 是重复 |
| 导航层数 | v1 说「3 层→2 层」，实际是 **2 屏 → 3 屏**（Section 折叠 ≠ 导航层） |
| 投入产出 | 10,573 行 / 6 文件 / 16 新文件 vs 1 条用户抱怨 |
| P2 假完成 | 协议测试仍在 `if eggShown`（连点 10 次） |

**v2 的核心不同：不新建任何页面。**

---

## 二、目标

**唯一目标**：让「锁的能力」（布防 / 防尾随 / 安全模式 / 静音 / 校准 / 固件升级 / 清空密码）**在设备页就能到达**，不用切到设置 Tab。

**不做的**：不改信息架构、不新建页面、不动 `Route`、不拆文件、不改 `SettingsGroup`。

---

## 三、方案：把 `DeviceInfoView` 升级为「锁设置」

### 3.1 复用现有载体

`DeviceInfoView`（`Sheets.swift:467-766`，300 行）已经是一个完整页面：

- 有 `NavigationStack` + `List`（`:476-477`）
- 有 `Destination.deviceInfo`（`:474` `.destined(.deviceInfo)`）
- 已有 `NavigationLink { LockProfileView() }`（`:482`）→ 锁档案编辑
- 已有三个 Section：`infoCardSection`（:503）/ `statusSection`（:550，含连接环境 + 运行状态）/ `batterySection`（:601）

**它现在叫「锁信息名片」，只读。把它扩成「锁设置」是自然延伸，不是新页面。**

### 3.2 新增：`Section("锁能力")`

在 `batterySection` 之后加一段（约 70 行）：

```swift
// 2026-10-29：锁能力区 —— 从「设置 → 锁段」迁来。
// 理由：这些是这把锁的策略，用户在看锁的时候最可能想调；不用切 Tab 去设置页找。
@ViewBuilder
private var capabilitySection: some View {
    let kc = app.current
    Section {
        if let kc, PidMap.canDefend(kc.pid) {
            NavigationLink { DefendView() } label: {
                capabilityRow("布防", icon: "shield.lefthalf.filled",
                              detail: DefendKit.summary(DB.defend(kc.mac)),
                              active: DefendKit.isActive(DB.defend(kc.mac)))
            }
        }
        if let kc, PidMap.canTailgate(kc.pid, fw: kc.fw) {
            NavigationLink { TailgateView() } label: {
                capabilityRow("防尾随入室", icon: "figure.walk.arrival", detail: "", active: false)
            }
        }
        NavigationLink { SafemodeIntroView() } label: {
            capabilityRow("安全模式 A/B", icon: "lock.rotation", detail: modeText, active: false)
        }
        muteToggle                       // 静音（即点即下发，保留现有逻辑）
        NavigationLink { SyncTimeView() } label: {
            capabilityRow("校准门锁时间", icon: "clock.arrow.circlepath", detail: driftText, active: false)
        }
        if let kc, PidMap.canDeviceUpgrade(kc.pid) {
            NavigationLink { DFUView() } label: {
                capabilityRow("固件升级", icon: "arrow.up.circle", detail: "", active: false)
            }
        }
        if let kc, PidMap.canClearPwd(kc.pid) {
            Button(role: .destructive) { confirmClearPwd() } label: {
                capabilityRow("清空密码", icon: "delete.left", detail: "指纹保留", active: false)
            }
        }
    } header: {
        Text("锁能力")
    } footer: {
        Text("这些是这把锁本身的策略，只影响这一把锁；App 级设置仍在「设置」Tab。")
    }
}

private func capabilityRow(_ title: String, icon: String, detail: String, active: Bool) -> some View {
    HStack(spacing: DS.Space.s) {
        Label(title, systemImage: icon)
        Spacer(minLength: 0)
        if !detail.isEmpty {
            Text(detail).vkFont(.caption)
                .foregroundStyle(active ? DS.Palette.ok : DS.Palette.textSub)
        }
    }
    .frame(minHeight: DS.Hit.min)
}
```

## 五、用户价值（诚实标注）

| 场景 | 现在 | 方案 |
|---|---|---|
| 在设备页想调布防 | 切设置 Tab → 找「锁」段 → 点布防（**2 次操作 + 1 次 Tab 切换**） | 点 Hero 卡齿轮 → 点布防（**2 次操作，不切 Tab**） |
| 在设备页想改静音 | 同上 | 同上 |
| 在设置页想调布防 | 设置 → 锁段 → 布防（**不变** —— 设置页那行保留？不，3.4 删了） | 设置 → 锁段 → 锁信息名片 → 布防（**多一层**） |

⚠️ **诚实标注**：3.4 删掉了设置页的 7 项能力，所以**从设置页进的人会多一层**（要先进「锁信息名片」）。这是本方案唯一的倒退。

**两个选项**：

| 选项 | 设置页行为 | 评价 |
|---|---|---|
| **A（推荐）** | 设置页 `lockSection` **保留一行**「锁设置（布防/防尾随/固件…）→ 锁信息名片」 | 设置页仍有直接入口，不倒退 |
| B | 删掉 7 项，只留锁档案/名片 | 设置页变薄，但从设置页进的人多一层 |

**选 A**：`lockSection` 里把 7 项换成 **1 行** `Button("锁设置（布防 / 防尾随 / 固件…）") { showDeviceInfo = true }`。设置页反而更清楚。

### 真实收益

| 收益 | 评价 |
|---|---|
| 设备页直达锁能力 | ✅ 真收益（少一次 Tab 切换） |
| 锁能力集中一处 | ✅ 真收益（现在散在 7 行） |
| 设置页更清楚 | ✅ 真收益（7 行 → 1 行） |
| **导航层数减少** | ❌ **不成立** —— 屏幕数不变（都是主屏 → 目标页 / sheet） |
| **文件数减少** | ❌ 不涉及 |

## 六、不做的事

- ❌ 不新建 `LockDetailView`（复用 `DeviceInfoView`）
- ❌ 不改 `Route`（`Route.byHost` 只有 4 个 Tab 级成员，加非 Tab case 会让 `tabIndex=-1`）
- ❌ 不改 `SettingsGroup`（保持 5 个 case + 「全部」= 6 chip）
- ❌ 不拆 6 个巨型文件（作为独立技术债，与本次需求解耦）
- ❌ 不动 `Destination`（`DeviceInfoView` 已是 `Destination.deviceInfo`）
- ❌ 不改功能语义（静音仍读锁端、清空密码仍保留指纹、删除设备仍键入锁名）

## 七、风险

| 风险 | 缓解 |
|---|---|
| `DeviceInfoView` 从 300 行涨到约 400 行 | 仍在可维护范围；按 Section 拆 `@ViewBuilder` 私有属性 |
| `muteToggle` / `clearPwd` 从 `SettingsView` 复制会重复逻辑 | **不复制**：把 `doClearPwd` 的「保留指纹」判据抽成 `CredentialOrg.clearPwdsKeepFps(mac)`（已有 `batchDisable` 同族），两处调用 |
| `DeviceInfoView` 从设置页和设备页两处打开，`dismiss` 行为不同 | `@Environment(\.dismiss)` 在 sheet 里自动正确；`LockProfileView` 的 `save()` `dismiss()` 只关它自己那层 |
| 齿轮按钮与 Hero 卡现有内容挤 | 放在标题行 `LinkPill` 右侧；44pt 触达；窄屏时 `layoutPriority` 保证锁名优先 |
| `SearchHit` 4 条改 `go` 后无法「滚到」 | 改为直接打开 `DeviceInfoView`，比滚动更直接 |
