## 一、「同一个界面被很多次入口」

### 根因

`destmap` 台账显示 5 个目的地有多重入口，最多的一处 4 个：

| 目的地 | 修前入口数 | 都在哪 |
|---|---:|---|
| `AddDeviceView` | **4** | 凭证页空态 / 设备页「+」/ 记录页空态 / 设置页「添加另一把锁」 |
| `LockSettingsView` | **3** | 设备页工具栏齿轮 / 设备页「管理这把锁」/ 设置页「锁设置」 |
| `LockProfileView` | **2** | 锁信息名片 / 设置页门锁段 |
| `DeviceInfoView` | **2** | 设置页「锁信息名片」/（原 `LockSettingsView` 无） |
| `DefendView` | **2** | 设备页圆盘下方 / 锁设置页能力段 |

### 修法：每个目的地收敛到**唯一入口**

| 目的地 | 唯一入口 | 删掉的重复 |
|---|---|---|
| `AddDeviceView` | 设备页右上角「+」 | 凭证页 / 记录页的空态按钮改成 `goAddDevice()`（跳到设备页 + 提示）；设置页「添加另一把锁」删除 |
| `LockSettingsView` | 设备页「管理这把锁」行 | 设备页工具栏齿轮（`@State showLockSettings` + sheet 一起删）；设置页「锁设置」按钮 + sheet 删 |
| `LockProfileView` | 设置页门锁段 | 锁信息名片里的「编辑锁档案」NavigationLink 删 |
| `DeviceInfoView` | 锁设置 → 概览底部一行 | 设置页「锁信息名片」按钮 + sheet 删 |
| `DefendView` | 设备页圆盘下方（带实时状态） | 锁设置页能力段的布防 NavigationLink 删 |

设置页搜索命中这四项时，改成 `goAddDevice()` / `openLockSettings()` —— 把用户送到唯一入口，而不是在本页再开一个重复的 sheet。

**结果**：28 个目的地全部单一入口（`destmap` 无 `2 处` 及以上）。

## 二、「A/B 切换的只看到说明，没有实际切换」

### 根因

`SafemodeIntroView` 的切换按钮被 `if app.status == nil` 挡住：

```swift
if app.status == nil {
    Text("还没读到锁状态 —— 先在设备页读一次锁信息，这里才会出现切换按钮。")
} else if app.status?.verifyMode == 1 {  // ← 切换按钮在这里
```

而这一页**自己不读状态**，`app.status` 只在设备页 `reload()` 后才有值。用户从锁设置页直接进来时 `app.status == nil`，就只看到两段说明 + 一句「还没读到锁状态」。

### 修法

1. 进页自读一次：`.task { if app.status == nil { await app.refreshStatusQuietly(manual: true) } }`
   （`manual: true` 让静默排查档不吞掉这次回读）
2. 「还没读到锁状态」那句改成**可就地重试的按钮**，不再让用户自己跑去设备页
3. `unlockSection` 的 footer 文案过期（原写「要放宽请到门锁键盘操作」），改成指向真实入口

## 三、「生成临时码后被挡住了，看不见」

### 根因：`otpPeek` 语义反了

```swift
@State var otpPeek = false        // 默认 false
...
.overlay(alignment: .leading) {
    if !otpPeek {                 // ← false 取反为 true ⇒ 挡片**常驻**
        RoundedRectangle(...).fill(.ultraThinMaterial)
```

原注释写「挡片默认值原为 true，改成默认关」，但改成 `otpPeek = false` 之后 `if !otpPeek` 反而**恒为真** —— 挡片从「默认盖住」变成「永远盖住」。生成完也不揭开。

### 修法

拆成两个状态，语义直白：

```swift
@State var otpShieldOn = false   // 防窥挡片开关：默认关
@State var otpReveal = false     // 长按揭开中：松手复位
...
if otpShieldOn && !otpReveal { ...挡片... }
```

- 挡片开关放长按菜单（`VariantToggle("防窥挡片（盖住临时码）", isOn: $otpShieldOn)`），不占版面
- `genOtp()` 成功后强制 `otpReveal = true` —— 刚生成的码必须立刻可见

## 六、教训

1. **`if !flag` + `flag = false` 是双重否定**。改一个开关的默认值时，要连带检查所有 `if !flag` 的读点 —— 这里正是「把默认值从 true 改成 false」却没有同步改判断，导致挡片从「默认盖」变成「永远盖」。
2. **`@State` 在 `extension` 里非法**，但方法可以。把 `goAddDevice` 插到文件末尾的 `}` 之前时，落到的是 `extension UIApplication` 而不是 `struct CredentialsView` —— 必须按「宿主类型的闭合位置」定位，不能按「文件最后一个 `}`」。
3. **删一段 UI 时要连它的 helper 一起查**。`deviceRow` 删掉后 `PidMap.isLock` 变成零引用，再恢复 `deviceRow` 时它已经不存在了。
4. **GitHub API 限流 ≠ CI 失败**。这次连续两次因为 403 读不到结果而误判，实际 CI 是 success。
