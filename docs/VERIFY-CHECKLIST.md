## 2. 销毁流程（磁盘侧是本审计最重的一条）
1. 先做一次导出备份（让 `Documents/lockkeeper-backups/` 与 `Application Support/lockkeeper-rollback/` 有文件）。
2. 安全中心 → 核弹销毁，读完新告警文案（应包含"会一并覆写删除本机备份件与回滚快照"）。
3. 执行后看结果文案：应有"覆写删除本地备份与回滚快照 N 个文件"，且"残留复核: 零残留（已检索 X 项…）"。
4. **交叉验证**：连真机后用 文件 App / `ios-deploy --list_documents` 或 Xcode Devices 下载容器，确认 `lockkeeper-backups/`、`lockkeeper-rollback/`、`Caches/exports` 已空；若还有，`residueSelfCheck()` 必须报命中而不是"零残留"。

## 3. 备份与 OTP（改的是包体结构，必须测恢复）
- 勾选 181 + 设口令导出 → 用该文件恢复：TOTP 种子/静态码应回来（这是"只写不读"修成"可恢复"的验收点）。
- 同一文件用文本编辑器打开：应看不到 `//OTPK` 尾段，且**明文 2FA 种子不可见**。
- 篡改包体内 `otpKeys` 任一值（无口令场景）→ 恢复时校验和应失败并拒绝，而不是照写。
- 不勾 181 导出 → 恢复后 TOTP 密钥不应存在（默认排除口径保持）。

## 4. 协议与数据口径
- 密码含 emoji：新增一条含 astral 字符的密码 → 与小程序/JS 侧同一口令应得到**同样**的锁内行为（`asciiHex` 已改为 UTF-16 码元；旧 iOS 会写错字节）。
- 台账导入 ISO 形态有效期（`2026-01-05T08:00:00Z`）→ 下发的有效期应等于该时刻，不再是"当前时刻"；无法解析的字符串应**报错并中止**，不是静默改期。
- 深链：`kf://credentials`、`kf://records`、`kf://settings`；未知 host（`kf://whatever`）应什么都不做；**锁屏状态下**用深链进 App 应先看到锁屏，解锁后才落到目标 Tab。
