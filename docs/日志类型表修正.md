fix(协议): 日志类型表改用 APK 的 `We` 表 —— 原来抄的是消息中心枚举 `Rn`

## 用户的问题

「App 真的能从锁读到日志吗？看看 `jzzns22561_out` 里实现了没。」

## 答案：能，APK 实现了，iOS 也实现了 —— 但 iOS 的类型表抄错了

### APK 证据（`resources/assets/www/build/main.js`）

1. **命令号**：`l.ZKCCOMM_GETLOG="16"`（0x16）
2. **帧构造**：`new Re(index)` → `ZKCCOMM_GETLOG, true(needToken), "0000"`，KLV `01` = 起始 index
3. **回调解析**：`parseKLV()` 里 `03`=resultCode / `04`=surplusLogs / `05`=每条日志
4. **分页**：`e.getSurplusLogs() > 0 && t.logCount < 100 && (t.logIdxNow = i - 1, t.getLog(0, t.logIdxNow))`
   —— 剩余 >0 且不足 100 条就继续读。iOS 的 `fetch()`（`RecordsRows.swift:230-253`）与这套逻辑同构。

### APK 里有**两套**枚举，iOS 抄错了

| 枚举 | 内容 | 实际用途 |
|---|---|---|
| `Rn` | `DigitalKeyOpen=1 / PasswordOpen=2 / FPOpen=3 / TempPwdOpen=4 / NFCOpen=5 / PowerLower=6 / Lockpicking=7 / WarningFP=13 / Thekeyboardislocked=224` | **消息中心 mType**（全仓只有 `Rn.WarningFP` 一处被消息列表用） |
| `We` | `4 静态电量 / 8 重新上电 / 9 DFU成功后版本号 / 10 多次密码开门失败锁定 / 11 数字钥匙开门 / 12 授时 / 13 交换秘钥 / 14 同步PIN / 15 同步密码 / 16 一次性密码开门 / 17 密码开门 / 19 指纹开门 / 20 添加指纹 / 21 删除指纹 / 22 设置安全级别 / 23 开关事件、状态广播 / 24 设置单、双验 / 25 开通临时密码 / 26 设置音量 / 27 设置zkBeacom密钥` | **日志条目解析**（`this.name = We[this.key]`） |

iOS 的 `StatusParser.logTypes` 抄的是 `Rn`，所以：

| 锁端实际报 | 旧 iOS 显示 | 影响 |
|---:|---|---|
| `17` 密码开门 | 「未知(17)」 | **最常见的开锁方式显示成未知** |
| `19` 指纹开门 | 「未知(19)」 | 同上 |
| `11` 数字钥匙开门 | 「未知(11)」 | 同上 |
| `13` 交换秘钥 | 「指纹告警」 | **每次配网换钥都误报成告警** |
| `4` 静态电量 | 「临时密码开门」 | **低电量被算成一次开门** |

### 修正内容

- `StatusParser.logTypes` → `We` 全表（20 项）
- `StatsKit.openTypes` `[1,2,3,4,5]` → `[11,16,17,19]`
- `StatsKit.alarmTypes` `[6,7,10,13,224]` → `[4,10]`
- `AlarmMeta.urgent` `[7,224]` → `[10]`；`serious` `[10,13]` → `[4]`
- `RecordSearch.damageTypes` `[7,10,224]` → `[10]`
- `RecordVerbs.openVerb / alarmVerb / opVerb` → 按 `We` 重写
- 用户可见文案：「含防撬/试错」→「含密码失败锁定」

> 注：撬锁 / 指纹告警 / 键盘锁定 **不在锁端日志类型表里**，它们属于消息中心（`Rn` / `mType`）。所以记录页不再宣称能筛出这三类 —— 原来那句话是拿另一套枚举硬套出来的。
