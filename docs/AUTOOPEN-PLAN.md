# AUTOOPEN-PLAN — App 内「靠近自动开锁」开关 方案（含验证计划）

> 状态：**方案定稿，未实现**（本仓库约定：实现另开任务）。
> 依据：APK 协议逆向（REVERSE_REPORT §5/§6）+ 三端功能矩阵 + 对抗式安全审核
> （「睡觉时门绝不能自行解锁」红线，F0-F6 门控 + A3/C1/C2 修正）。

## 0. 一句话规格

App 内新增**默认关闭**的「靠近自动开锁」主开关 + **面容档位**子开关（标准/严格）。
开启后：App 在前台时自动完成*无风险预备*（扫描/连接/刷 token/签 ekey），
走近门且**全部门控通过**的瞬间自动下发 cmd04；任一门不过 = 静默拒绝 + 审计落盘。
本特性只做 iOS 端（小程序无生物门控/后台 BLE 条件，不做）。

## 1. 存储键（Store，`kf.*` 前缀自动进备份）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `kf_autoopen` | Bool | **false** | 主开关（全局，非按锁） |
| `kf_autoopen_face` | Int | 0 | 面容档位：0=标准（静默复用≤60s）/ 1=严格（进前台必刷面容） |
| `kf_autoopen_audit_` | 日志块 | — | 拒开审计（只记「哪道门拒了」，**永不记 ekey/skey 值**），尾段 500 条 |

Store.swift 加 2 个 accessor（仿 `syncTime(mac)` 模式），审计键走现有 trace 机制。

## 2. 门控链（fail-closed，缺事件源=门不过）

| 门 | 条件 | 事件源 | 状态 |
|---|---|---|---|
| F0 前台 | App 激活 + 屏幕解锁 | `UIApplication` 生命周期 | 现成 |
| F1 面容 | **标准**：LAContext `evaluatePolicy` 最近一次成功 ≤60s（进前台时主动调，设备生物窗口内静默成功）；**严格**：进前台每次必弹窗 | `LocalAuthentication`（免费账号可用，CONSTRAINTS L15） | 现成 API |
| F2' 停留 | RSSI 升穿阈值后手机降速/停留 ≥3s（堵「骑车路过」） | CMMotionManager + RSSI 滤波器 | 需写 |
| F3 距离 | RSSI P95 按「锁×手机」标定 + 滞后回差（掉回 0.5×阈值才重新武装） | 扫描/连接态读 RSSI + 标定工具页 | 需写 |
| F4 布防互锁 | `kf_defend_` control==2 且当前时刻在 start/end 内（**跨午夜 start>end**）→ 一票否决，优先于 F1 | `DB.defend(mac)` | 现成数据，判定时段需写 |
| F5 一次性 | 每个接近事件一次 04；成功后 60s 冷却 + 回差重武装 | 状态机内部 | 需写 |
| F6 锁态 | rc=26 防拆 / rc=25 busy → 拒 + rc=26 自动关自动开锁 24h | 03 轮询回显 | 现成数据 |

红线复查（睡觉场景四层，任一层失效仍守住）：
后台灭屏=F0 否；亮屏床头刷视频睡着=F1 过期+F2' 静置+**F4 时段**；
手机被拿走=F1（严格档 0 窗口 / 标准档 60s，UI 明示）；户型 4m=F4 时段否决。

## 3. 安全约束（写入实现的硬性规则）

1. **预备无限制，执行全 AND**：扫描/连接/token/签 ekey 任意状态可跑（不改门状态）；
   只有 cmd04 下发要 F0∧F1∧F2'∧F3∧F4∧F5∧F6 全绿。
2. **0E 双确认**：rc=3 自愈自动校时仅在 `30s < |偏差| < 24h` 且（有网时 NTP 对表一致）执行；
   ≥24h 只提示不写——防「把错手机时间写进锁 → 全凭证时间窗集体错乱」自伤 DoS。
3. **ekey 滚动（G3）前置实验**：`times` 字段语义未确证（可能非剩余次数）。
   真机矩阵：times=0/1/8 ×（连开 / 断电 / 锁侧重置）记录 rc 与 03 回显 → 判定规则入库后
   G3 才上线；实验未过前 rc=5 只提示「请联系主人换钥」，不自动重签。
4. **F1 标准档披露文案（强制展示，不遮掩）**：
   「标准档：最近 60 秒内无需重新刷脸。注意——这 60 秒内别人拿走手机也能开门。
   介意请切严格档。」
5. **Siri/Widget 入口定位**：只做「带到就绪态」，最后一步永远是用户的手/脸
   （Intent 10s 窗口 vs BLE 3-5s+命令 2-3s，不承诺「Siri 远程开门」）。

## 4. UI（SettingsView，「开锁」Section 之后新增）

```
Section("靠近自动开锁") {
  Toggle("走近自动开门", kf_autoopen)           // 默认关
  if 开 {
    Picker("面容确认", kf_autoopen_face)        // 标准(静默≤60s) / 严格(每次必刷)
  }
  footer: "仅 App 在前台且门不在布防时段生效；布防时段与防拆事件自动关闭自动开锁。
          睡觉场景请确认布防时段覆盖夜间。"
}
```
- 诊断页新增「上次拒开原因」行（读 kf_autoopen_audit_）。
- 锁卡显示态：「已备好，进门即开」/「门已开」/「被拒：{门名}」。

## 5. 验证计划（实现任务的验收清单）

**单元（XCTest，跑 CI 模拟器）**
- `defendActive`：control 0/1/2/3 ×（不跨夜 22-06 / 跨夜 23-06 / 临界 start/end 秒）表驱动
- `canAttempt` 门控矩阵：开关 × 布防 × F1 档位 全组合（含默认全关回归）
- F1 60s 窗口边界：59s 过 / 61s 拒 / 严格档必弹窗（LAContext mock）
- F2'/F3 滤波器：模拟 RSSI 轨迹（静止强 / 路过弱 / 停留）→ 武装/拒判定
- 0E 双确认：偏差 30s/23h/25h/25h+NTP 不一致 四格
- 回归闸门：`node tools/swiftcheck.js && node tools/golden.js`（本协议层 0 改动，金标应全绿）

**真机（模拟器做不了 FaceID/BLE，必须 iPhone 实物）**
1. 睡觉红线四场景清单（§2 红线表）逐个实测记录
2. 标准档 60s 接管演练：锁屏放桌 59s 被人拿走近 1m → 必须开（证明风险真实）；
   严格档同场景 → 必须拒
3. 车/推车路过门口 2 次不触发；走停 3s 触发
4. rc=3 自愈 + 0E 双确认的 24h 拒写行为
5. 审计日志：连续 20 次触发场景，逐条核对拒因与 F 门一致

**不做**：Widget/Siri 入口（§3.5 定位），后台模式（平台+电池不可控，明确放弃）。

## 6. 落地顺序（供实现任务排程）

1. Store accessor + 设置 UI + 审计键（可单独合入，纯配置无害）
2. F4/F6 时段判定 + 诊断行（纯本地逻辑，先上）
3. F1 LAContext 双档（60s 窗口 + 严格弹窗）
4. F3 RSSI 标定工具页 → 阈值入库
5. F2'/F5 状态机 + 04 自动下发（全门绿才执行）
6. G3 times 语义实验 → 通过后开 ekey 滚动
7. Siri/Widget 入口（最后做，定位=就绪态）
