# 截图问题的代码定位 + 对抗式核对

生成时间：2026-10-27
依据：5 张真机截图 + 全仓代码核对

## 一、截图问题的根因（已定位到具体代码）

### 1. 设置页布局崩坏 —— `SettingsView.swift:511-525`

```swift
private var familySection: some View {
    VStack(spacing: 0) {          // ← 根因
        Section { memberFamilyRows } header: { Text("家人与钥匙") } footer: {...}
        credCareSection
    }
}
```

**`Section` 只在 `List`/`Form` 的直接子级才有分组语义。**
被 `VStack` 包住后，整个 `VStack` 变成 List 的**一行**，里面的两个 `Section` 退化成普通容器 —— 于是：

- header / footer 不再吸附在组头组尾，而是**居中**夹在行之间
- 行与 footer 正文**垂直重叠**（Section 的自动行距消失）
- 两节内容混成一坨

**全仓只有这一处**（另外 3 处 `Section` 被包是误报：一处在 `Menu` 里、两处在 `List` 里的 `Group` 里，都合法）。

---

### 2. 悬浮「开锁」按钮压住 Tab 文字 —— `LockKeeperApp.swift:782`

```swift
mainTabView                          // ← TabView
    .safeAreaInset(edge: .bottom, spacing: 0) {
        VStack { if app.tabSelection != 0 { Button("开锁")... } }
    }
```

**在 iOS 18+ 的 `TabView` 上挂 `.safeAreaInset(edge: .bottom)`，插入内容会盖在 Tab 栏上**，而不是把 Tab 栏顶上去。

截图 3/4/5 里「凭证」「记录」被蓝色胶囊压住，就是这个。

**这是全局性的**（四个 Tab 页都有）。

---

### 3. 列表底部被 Tab 栏压住 —— `DeviceHomeView.swift:39-99`

`ScrollView` 本身没有底部安全区处理。叠加问题 2 的 `safeAreaInset`，最后一行内容会被推到 Tab 栏后面。

截图 1 底部「添加密码」「校准时间」的文字从半透明 Tab 栏后透出来，就是这个。

---

### 4. 锁卡片信息截断 —— `DeviceHomeView.swift:333-351`

```swift
HStack(alignment: .top, spacing: DS.Space.m) {
    HStack { Image(lock); VStack { Text(name).lineLimit(1) ... } }   // ← 被挤
    Spacer(minLength: 0)
    HStack { LinkPill(...); RSSIBars(...) }                          // ← 很宽
}
```

左侧 `Text` 有 `.lineLimit(1)` 但**没有 `.layoutPriority(1)`**，右侧 `LinkPill` 胶囊占掉近半宽度 → 名称被压成「智能...」。

锁钟「2026-10-2...」同理。

---

### 5. 「随时可开」与「密钥未绑定」矛盾 —— `DeviceHomeView.swift:472` + `:1073`

```swift
// 472：独立判断
if (app.status?.sKeyStatus ?? 0) != 0 {
    out.append(("密钥尚未绑定，该门锁可能还没完成配网", ...))
}

// 1073：只看蓝牙
private func linkState(for kc: Keychain) -> LinkState {
    guard kc.mac == app.currentMac else { return .down }
    return sense.linkState          // 只看 BLE 连接
}
```

**两个判断互不知情**：蓝牙连着 → 显示「门锁在线，随时可开」；同时 `sKeyStatus != 0` → 显示「密钥尚未绑定」。

密钥没绑定就**不可能开锁**，「随时可开」是错的，会误导用户点下去。

---

### 6. 临时密码空胶囊 —— `CredentialsView.swift:1169`

```swift
Text(otpPwd)          // 空串时渲染成空胶囊（外层有背景样式）
```

`otpPwd` 初始值是 `""`，生成前就渲染了空 `Text`。应该显示占位（如 `······`）或整行隐藏。

---

### 7. 临时密码失效时间陈旧 —— `CredentialsView.swift:1220-1224` + `:25`

```swift
@State private var otpWin = ""     // 25：初始空
...
if !otpWin.isEmpty { Text("于 \(otpWin) 失效...") }   // 1220：只判空，不判过期
```

`otpWin` 只在生成时赋值（`:1256`），**从不随窗口过期清空**。
昨天生成过一次 → 今天打开页面仍显示昨天的失效时间（截图里的「19:00」而当前 6:49）。

---

### 8. `nextWindow` 边界错误 —— `ZOTP.swift:57-65`

```swift
let m = comps.minute ?? 0
let minutePart = m > 30 ? 0 : 30
var hour = cal.component(.hour, from: now)
if m > 30 { hour += 1 }
```

**`m == 30` 时返回当前窗口自己**（06:30 → 06:30），而正确语义应是下一窗口 07:00。
应为 `m >= 30`。

实测（node 复刻）：

| 输入 | 输出 | 应为 |
|---|---|---|
| 6:49 | 07:00 | ✓ |
| **6:30** | **06:30** | ✗ 应 07:00 |
| 23:45 | 00:00 | ✓ |

## 二、对抗式核对：其余发现

### 9. 只写不清的展示态（陈旧值）

| 变量 | 赋值 | 清空 | 读取 | 判断 |
|---|---|---|---|---|
| `otpPwd` | 3 | **0** | 3 | 只写不清 —— 关掉临时密码后仍显示旧码 |
| `pullGap` | 3 | **0** | 2 | 只写不清 —— 上次的缺口警告会一直挂着 |
| `otpWin` | 1 | 1 | 2 | 清了，但不判过期（见问题 7） |

### 10. `Text(displayName)` 无 layoutPriority

| 位置 | 说明 |
|---|---|
| `DeviceHomeView.swift:341` | 锁卡片名称（截图里的「智能...」） |
| `Sheets.swift:840` | 另一处同样的写法 |

### 11. 记录页空态缺失 —— `RecordsView.swift`

截图 4「全部记录」展开了但没有任何空态提示。用户分不清「没有记录」与「加载失败」。

### 12. 「成员筛选 共 0 条」与凭证页 9 条矛盾

凭证页显示「共 9 条」，记录页「成员筛选 共 0 条」。
需核实：是没建成员（合理）还是成员数据没读到（bug）。

### 13. 临时码 chip 无数量

「全部 9」「密码 1」「指纹 8」都有数字，「临时码」没有。`CredentialsView` 的三态计数里 OTP 那一路可能没接上。

## 四、优先级

| 序 | 问题 | 影响 | 修复成本 |
|---|---|---|---|
| 1 | 设置页 `VStack` 包 Section | 整页不可用 | 小（拆掉 VStack） |
| 2 | `safeAreaInset` 压 Tab 栏 | 全局导航受损 | 中（改挂载层级） |
| 3 | 「随时可开」误导 | 用户点了开不了 | 小（`linkState` 加 sKey 判据） |
| 4 | 列表底部被压 | 最后一行点不到 | 中（与 2 同源） |
| 5 | `otpPwd` 空胶囊 | 看起来像加载失败 | 小（加占位或条件渲染） |
| 6 | `otpWin` 不判过期 | 显示错误的失效时间 | 小（加过期判断） |
| 7 | `nextWindow` 边界 | 6:30 这一分钟算错窗口 | 极小（`>` 改 `>=`） |
| 8 | 锁卡片截断 | 名字/时间看不全 | 小（加 `layoutPriority(1)`） |
| 9 | 记录页空态 | 分不清没数据还是失败 | 小 |
| 10 | 临时码 chip 无数字 | 信息缺失 | 小 |
